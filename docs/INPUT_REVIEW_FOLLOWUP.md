# v162 입력 취소·다중 포인터 개선

기존 모바일 잠입 액션의 입력 취소와 다중 터치 경계를 코드와 Chromium 회귀 검사로 점검했다.

## 발견과 수정

- 캔버스의 `touchcancel`이 정상 탭과 같은 경로로 경비 주시를 바꿨다. 취소 시에는 이동과 터치 기록만 정리하고, 정상 `touchend`에만 주시 선택을 적용한다.
- 공격·행동·붙잡기·기술 버튼이 오른쪽 마우스 버튼과 중복 포인터도 새 누르기로 받았다. 이제 왼쪽 클릭/터치로 시작한 포인터 하나가 버튼을 소유하며 다른 포인터의 누르기·해제·이탈은 기존 동작에 간섭하지 않는다. 조이스틱과 공격을 서로 다른 손가락으로 함께 사용하는 것은 유지한다.
- 일시정지·대화·키패드 중에도 캔버스가 새 조이스틱을 만들었다. 플레이가 가능한 상태에서만 이동 터치를 시작한다.
- 앱 전환이나 메뉴 진입으로 입력을 비울 때 버튼의 포인터 소유권도 지운다. 다시 플레이할 때 새 터치를 받을 수 있다.

## 검증 범위

`tests/rev/t_input_boundaries.py`는 오른쪽 클릭 무시, 중복 누르기 무시, 다른 포인터의 해제/이탈 무시, 취소 시 공격 미실행, 입력 초기화 후 새 터치, 정상 탭의 경비 주시, 취소된 탭의 주시 유지, 일시정지 중 이동 차단을 확인한다. 빠른 회귀 묶음에도 추가했다.

실제 Chromium에서 게임을 실행하는 자동 검사이며 실제 휴대폰 기기 검증이나 전체 임무 수동 플레이 리뷰는 아니다. 최신 v161의 갈아입기 버튼과 기본 제압 거리 개선을 보존해 통합했다. 갈아입기 버튼도 같은 포인터 소유권과 초기화 규칙을 사용한다.

검증 결과: 빌드 검사 7개, 스프라이트 소유권 검사, 맵 도달 검사와 핵심 회귀 스크립트 50개가 통과했다. 모바일 액션 검사에는 기존 24항목이 포함된다. 일부 기존 테스트의 `/root/game` 경로는 현재 작업 경로로 변환하고 로컬 HTTP 서버에서 실행했다. 이 환경의 시스템 Chromium은 `file://` 접근을 허용하지 않아 테스트 실행 보조 코드에서만 URL을 변환했다. 실제 게임 코드나 기존 테스트의 판정 조건은 바꾸지 않았다. 전체 회귀 묶음과 fuzz는 실행하지 않았다.
