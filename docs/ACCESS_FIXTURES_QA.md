# v112 검증 기록

출입·손동작·간판 구현은 [변경 내역](STORAGE_MOTION.md), 화면은 [실제 동작 영상](access-v112/index.html)을 참조한다.

## 이번 변경 검사

다음 검사는 PC와 Chromium 모바일 입력 환경에서 통과했다.

- `t_access_fixtures.py`: 환풍구 15곳 왕복, 맨홀 21곳 지하 왕복, 낙하 장치 21곳 충돌, 손 접촉 128개. 다른 층·원격 출입·막힌 출구·반복 해제·충돌 시점의 대상 이동 검사 포함.
- `t_access_inputs.py`: 실제 키보드·모바일 입력으로 짧은 입력 취소, 1초 유지, 해제 동작, 지연 충돌, 환풍구 출입.
- `t_hide_flow.py`: 네 방향 접근 209개와 입구·수용 인원·동시 입력·실제 출입 버튼.
- `t_storage_motion.py`: 은신 206곳 왕복, 보관과 함께 들어가기 여섯 종류, 낙하 1,039곳, 서서 뛰어내리기 398곳, 매달림 처치 23곳.
- `t_container_presentation.py`: 문 전체 열림, 몸의 연결된 이동과 입구 가림, 낙하 속도.
- `t_motion_windows.py`: 인물 17,512프레임의 여백, 창문 500개 경로, 위층 창문 72개 경로, 손 접촉 128개.
- `t_fixture_lighting.py`: 기본·잉크 화면의 PC 및 모바일 DPR 2에서 조명과 시설 색 일치, 예열 후 추가 캔버스 할당 0.
- `t_interaction_flow.py`, `t_combat_policy.py`, `t_environment_targets.py`, `t_scene_layers.py`: 반복 입력, 길게 누르기, 사물 선택과 층별 가림.
- 게시할 HTML 두 개에서 실제 환풍구 왕복과 간판 낙하를 재검사했다. 영상 여섯 개의 재생과 모바일 가로 넘침도 확인했다.

## 확장 검사에서 남은 문제

`python3 tools/run_tests.py --fast --quick --no-build`는 도달 검사를 통과했고, 35개 중 29개가 통과했다. 여섯 실패를 작업 시작 때 보관한 v111 HTML로 각각 다시 실행해 같은 실패를 확인했다. 기준 소스는 아래 v111 커밋이다.

[v111 기준 커밋](https://github.com/kkhkkh20-bit/yahaeng/commit/bc7e1f2c2ab849c82bb1b8759dac64394af1b9d7)

| 검사 | 현재 및 v111에서 재현된 실패 |
| --- | --- |
| `t_building_search.py` | 위층 은신처가 실제로 확인되지 않음. 수색 배정·경로의 후속 조사 필요. |
| `t_cqc.py` | 첫 처치 무전과 결과 화면 칭호 기대 조건 불일치. |
| `t_hanging_controls.py` | `끌고 가기`와 `더 가까이`라는 이전 안내 문구를 기다리다 시간 초과. 실제 매달림 입력은 별도 최신 검사에서 통과. |
| `t_height_cues.py` | 높이 표시가 의뢰 4의 한 건물에만 있어야 한다는 이전 시안 조건 불일치. |
| `t_ko.py` | 테스트가 배치한 눈썰미 조직원이 변장을 알아채지 못함. 인지 조건의 후속 확인 필요. |
| `tests/mis/tm1.py` | 직원 복장 획득 뒤 기절자 보관 단계의 완료 기대 조건 실패. |

전체 회귀 묶음이 모두 통과한 상태는 아니다. 이번 변경과 관련된 최신 검사 결과와 기존 실패를 구분해 남긴다. 확장 검사에서는 여섯 의뢰를 각 세 시작 조건과 PC·모바일로 완료하는 36개 미션 경로도 통과했다.
