# v211: 모바일 플레이 화면

사용자가 v210의 UI 완성도를 거절한 뒤, 실제 모바일 플레이 화면을 기준으로 HUD 전체를 조정했다. 기존 메인 메뉴의 먹색·아이보리·차분한 강철색을 이어가고, 게임 규칙·에피소드·저장 형식은 유지한다.

- 목표, 짧은 무전, 통행/들킴 상태와 미니맵의 위치를 정리했다. 실제 발각 중에는 회수 작업보다 시야를 끊고 숨기를 우선 표시한다.
- 오른쪽 조작 버튼은 같은 원형 마감과 자체 선 아이콘을 사용한다. 왼쪽 이동 영역은 비운다. 기본 제압과 명시적인 살해/길게 누르기를 구분한다.
- 옷 입기가 이미 주 행동이면 동일한 옷 버튼을 중복 표시하지 않는다. 다른 행동이 선택되면 직접 옷 입기 조작을 유지한다.
- 목표창과 장비창은 시간 정지와 닫는 방법을 고정하고 내용만 스크롤한다. 장비창은 이동 속도 조작도 고정한다.
- 터치의 대상 선택 안내는 버튼 한 곳에서 표시한다. PC의 대상 변경 표시는 기존 전투 안내와 같은 충돌 회피 큐를 사용한다.

## 검증

`tools/capture_field_hud.py`는 390×844,390×640,320×568,844×390,568×320,1280×800의 걷기/제압 접근/옷 입기/발각/목표 읽기/장비 선택을 캡처한다. 배우와 카메라를 배치한 표현 검증이며 실제 플레이 증거와 구분한다. 24개의 일반 상태에서 버튼 겹침과 페이지 오류가 없었다. 결과는 presentation-geometry.json이다. 실제 캡처는 build/field-hud-v211/after에 생성된다.

기존 다중 터치 웅크림, 전체 장비 선택/스크롤/포커스, 목표 읽기와 재개, PC/모바일 버튼 분리, 기절/살해 입력 정책, 임무 식별 정보, 복장/감시 판정 검사를 실행했다. 추가한 t_field_hud.py는 통행 허용의 가시성, 발각 시 안내 우선순위, 전체 목표 접근을 확인한다.

별도 실제 입력 여정은 first_steps_live.py의 도입부→운반책 처치→획득한 기술 사용과 first_night_live.py의 운반책→변장→CCTV 녹화 실수/재시도→감시 차단→서류 회수/탈출이다. 일반 RAF와 활성 AI에서 PC키보드/모바일 CDP 터치를 사용했다. Chromium 에뮬레이션이며 실물 iOS 기기나 사전 지식 없는 사람의 재미 평가를 대신하지 않는다.

## 마감 검수

기능 통과와 미적 완성도를 구분해 독립적인 화면 검수를 진행했다. 좁은 가로 화면의 행동 문구 잘림, 대상 선택 표시 충돌, 스크롤 중 시간 정지/닫기 안내 누락, 읽기 화면의 중복 지시를 수정했다. 재검수는 네 항목 모두 해결, disposition: ship이다. 이 판정은 네 수정 항목 범위이며 게임 전체의 상품성을 보증하지 않는다.

기계 검사는 한 번 실행했다. 기존 template.html 경고7개와 메인 메뉴 전용 DESIGN.md에 없는 HUD 글자/상태색에 대한 권고를 기록했다. 메인 메뉴 DESIGN.md/.impeccable/design.json을 덮어쓰지 않는다. HUD 구성은 .impeccable/surfaces/mobile-hud.md와 src/field-hud.css, 자체 SVG에 기록되어 있다.
