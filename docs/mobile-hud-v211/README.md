# v211: 모바일 플레이 화면

사용자가 v210의 UI 완성도를 거절한 뒤, 실제 모바일 플레이 화면을 기준으로 HUD 전체를 조정했다. 기존 메인 메뉴의 먹색·아이보리·차분한 강철색을 이어가고, 게임 규칙·에피소드·저장 형식은 유지한다.

- 목표, 짧은 무전, 통행/들킴 상태와 미니맵의 위치를 정리했다. 실제 발각 중에는 회수 작업보다 시야를 끊고 숨기를 우선 표시한다.
- 오른쪽 조작은 사용자가 제시한 모바일 액션 레퍼런스처럼 큰 주 행동 버튼과 주변의 작은 원형 버튼으로 구성한다. 기존 라이선스 실루엣과 자체 제압 아이콘을 크게 사용한다. 왼쪽 중앙 이동 영역은 비운다. 하단에는 실제 보유한 빈 캔·담배·연막탄·무전기를 수량과 함께 놓고 즉시 사용한다. 기본 제압과 명시적인 살해/길게 누르기를 구분한다.
- 옷 입기가 이미 주 행동이면 동일한 옷 버튼을 중복 표시하지 않는다. 다른 행동이 선택되면 직접 옷 입기 조작을 유지한다.
- 목표창과 장비창은 시간 정지와 닫는 방법을 고정하고 내용만 스크롤한다. 장비창은 이동 속도 조작도 고정한다.
- 터치의 대상 선택 안내는 버튼 한 곳에서 표시한다. PC의 대상 변경 표시는 기존 전투 안내와 같은 충돌 회피 큐를 사용한다.

## 검증

`tools/capture_field_hud.py`는 390×844,390×640,320×568,844×390,568×320,1280×800의 걷기/제압 접근/옷 입기/발각/보조 아이템/목표 읽기/장비 선택을 캡처한다. 배우와 카메라를 배치한 표현 검증이며 실제 플레이 증거와 구분한다. 최종 레퍼런스 반영 캡처는 보조 아이템을 갖춘 상태를 추가한 30개 일반 상태·총 42장이다. 버튼 겹침과 페이지 오류가 없었다. 결과는 presentation-geometry.json이다. 실제 캡처는 build/field-hud-v211/reference에 생성된다.

기존 다중 터치 웅크림, 전체 장비 선택/스크롤/포커스, 목표 읽기와 재개, PC/모바일 버튼 분리, 기절/살해 입력 정책, 임무 식별 정보, 복장/감시 판정 검사를 실행했다. 추가한 t_field_hud.py는 통행 허용의 가시성, 발각 시 안내 우선순위, 전체 목표 접근을 확인한다.

별도 실제 입력 여정은 first_steps_live.py의 도입부→운반책 처치→획득한 기술 사용과 first_night_live.py의 운반책→변장→CCTV 녹화 실수/재시도→감시 차단→서류 회수/탈출이다. 일반 RAF와 활성 AI에서 PC키보드/모바일 CDP 터치를 사용했다. Chromium 에뮬레이션이며 실물 iOS 기기나 사전 지식 없는 사람의 재미 평가를 대신하지 않는다.

보조 아이템 입력은 기존 투척·연막·무전기의 실제 효과를 사용한다. 누른 채 끌면 방향과 거리를 조준하고 원위치로 돌아오면 취소한다. 놓을 때 한 번만 사용하며, 원래 선택한 도구·휘파람을 복구한다. 보유하지 않은 무전기는 표시하지 않고, 빈 슬롯과 사용 불가 상태는 재고를 소모하지 않는다. t_quick_items.py는 실제 CDP 터치로 단일 소비, 원위치/OS/Escape/blur 취소, 다른 손가락 간섭, 연막 효과, 도구 복구와 다섯 화면 크기의 네 슬롯 배치를 확인한다.

## 마감 검수

기능 통과와 미적 완성도를 구분해 독립적인 화면 검수를 진행했다. 좁은 가로 화면의 행동 문구 잘림, 대상 선택 표시 충돌, 스크롤 중 시간 정지/닫기 안내 누락, 읽기 화면의 중복 지시를 수정했다. 당시 재검수는 네 항목 모두 해결, disposition: ship이었다. 사용자의 새 버튼·하단 아이템 레퍼런스를 반영한 화면은 새로운 전체 HUD 검수를 받았으며 대상 변경 버튼이 적을 가림, 저장 알림이 NPC 대사를 가림의 두 항목이 추가로 발견되었다. 오른쪽 버튼 재배치와 상황 버튼에 대응하는 카메라 공간 갱신, 말풍선 표시 중 일시적인 저장 알림 숨김으로 수정했다. 같은 검수자의 최종 판정은 두 수정 모두 해결, disposition: ship이다. 이 판정은 두 항목의 재검수 범위이며 게임 전체의 상품성을 보증하지 않는다.

기계 검사는 한 번 실행했다. 기존 template.html 경고7개와 메인 메뉴 전용 DESIGN.md에 없는 HUD 글자/상태색에 대한 권고를 기록했다. 메인 메뉴 DESIGN.md/.impeccable/design.json을 덮어쓰지 않는다. HUD 구성은 .impeccable/surfaces/mobile-hud.md와 src/field-hud.css, 자체 SVG에 기록되어 있다.

## 최종 실행 결과

- 로컬 빠른 회귀 107개 전체 통과. 처음 실행에서 상황 버튼이 캐릭터 주변을 가린 한 건을 발견했고, 카메라 공간 캐시를 수정한 뒤 해당 실제 입력 검사 24개와 전체 묶음의 재검사가 통과했다.
- 다섯 터치 화면에서 NPC 대사가 실제 표시되고 고정 UI와 겹치지 않는지, 대상 변경 버튼이 선택된 기절자를 가리지 않는지 확인했다.
- 정상 AI/RAF 초반 세 임무는 PC와 모바일에서 완료했다. 카메라 공간 수정 후 최종 모바일 여정도 다시 완료했다. 순찰의 안전 창을 막 놓친 경우 다음 실제 순찰 주기까지 기다리도록 자동 플레이의 대기 상한만 45초로 늘렸으며 게임 시간을 건너뛰거나 AI를 바꾸지 않았다.
- 마지막 패키지 source_sha256: `c35bd89578863e880d98d92e7f30b8c083c481bd81a14867a20606ab859e9b44`. 실물 iOS 기기와 사전 지식 없는 사람의 재미 평가는 실시하지 않았다.

- 후속 CI의 실제 초보자 여정에서 단축된 버튼 문구가 같으면 접근 거리의 접근성 설명이 남는 문제를 발견했다. aria-label을 표시 HTML 캐시와 독립적으로 갱신하도록 수정했고, 다섯 터치 크기의 접근 안내 회귀 검사를 통과했다. 렌더되는 버튼 모양과 게임 판정은 바뀌지 않는다.
