# 상용 모바일·PC 마감 검토 — 2026-11-08

## 범위와 판단

공개 v211을 기반으로 하는 현재 작업본 v212의 공통 플레이 코드, 일반 RAF/AI를 유지한 PC·터치 조작 기록, 실제 화면 캡처를 검토했다. 미션 추가의 재미나 처음 접하는 사람의 이해도를 자동 완주로 입증했다고 보지 않는다. 브라우저 터치 검증은 실제 iPhone/Android의 음량·프레임·햅틱 검증을 대신하지 않는다. 이 문서의 제안은 적용 완료 목록이 아니다.

상용 마감 기준으로는 보류다. 걷기·제압·운반·변장·작업·시야·녹화·결과의 로직과 여러 애니메이션은 이미 있다. 가장 큰 결함은 **서로 다른 사건이 같은 신호를 쓰고, 중요한 확정 순간이 다음 UI에 묻히는 것**이다. 새 파티클·스킬·보스 콘텐츠보다 원인과 결과의 구분을 먼저 개선해야 한다.

## 직접 확인한 근거

1. `interaction/takedown.js:killGuard`와 `ai/combat.js:hurtPlayer`가 모두 `S.flash`를 설정한다. `render/frame.js`는 이를 같은 전체 화면 적색 막으로 그린다. 처치 성공과 내 피격이 같은 화면 언어를 공유한다.
2. `58_combat_intent.js:finishKo`는 기절한 몸을 사망 상태로 바꾸고 소리·토스트를 내지만, 이 함수 자체에는 전용 마무리 접촉 동작이 없다. 기절→살해라는 중요한 선택의 표현이 상태 변경에 치우친다.
3. `80_hud.js:showEnd` 마지막에서 `openEpisodeTraining()`을 즉시 호출한다. 실제 모바일 첫 의뢰 완료 캡처도 승리/결과 대신 곧바로 기술 화면이다. 결과 정보는 만들어지지만 감정적 마침표로 보일 시간이 없다.
4. `ai/guards.js`에서 의심, 유인 조사, 조명 복구 등이 `?`를 공유한다. 불을 켜러 가는 행동과 플레이어의 신원을 의심하는 행동을 구분하기 어렵다.
5. `interaction/loot.js:updatePick`는 이동·피격 취소 이유를 알리지만, `59_interaction_flow.js:updateObjectAction`의 일부 중단 경로는 `interact=null`로 끝난다. 같은 장기 작업의 취소 설명이 두 체계에서 다르다.
6. `interaction/loot.js:takeItem`는 서류 회수에도 `switch` 소리를 쓴다. 스위치·획득의 재질과 의미가 겹친다.
7. PC CCTV 실제 입력에서는 불법 작업 녹화 1건 → 전선 분리 후에도 기록 유지 → 실내 단말에서 기록 제거 → 탈출을 확인했다. 규칙은 작동하지만 작업을 끝낸 순간 렌즈/서류/현재 목표 사이에 녹화 원인을 읽을 짧은 연결 표현이 더 필요하다.
8. 검증 중 발견한 점프 행동 대상의 매 프레임 교체, 간판의 잘못된 은신 기술 제한, 카메라 서비스 위치와 자동 계단의 충돌은 v212 작업본에서 수정했다. 단순한 이펙트 추가로 해결할 수 없는 상호작용 마감 문제다.

9. `ai/combat.js:hurtPlayer`의 체력 0 경로는 바로 `endGame`으로 간다. 이 경로에는 플레이어 전용 쓰러짐 동작이 연결돼 있지 않다. 실패 지연만으로 사망 과정을 대신하지 않도록 해야 한다.

## 적용 순서와 완료 기준

### 1. 즉시 수정하면 효과가 큰 것

- 처치 성공과 피격의 적색 막 분리.
- 기절·살해·은폐의 확정 시점과 표시 통일. 특히 기절한 대상 마무리의 전용 접촉 표현.
- `?`의 의미를 신원 의심/소리 조사/조명 복구로 구분. 복장 허용과 녹화 위험을 기존 HUD에 한 번만 설명.
- 작업 중단 사유 통일, 행동 선택 대상 고정, 계단 도착 층/작업점 충돌 해소.
- 실제 탈출 완료를 인지한 다음 보상과 기술 화면. 현재 자동 학습 정책은 유지.

완료 기준: 소리를 끈 상태에서도 기절·사망·운반·수납·변장·녹화·차단·기록 제거를 서로 구별하고, 임무 완료와 기술 포인트의 출처를 한 번에 이해할 수 있어야 한다.

### 2. 적은 비용으로 개선 가능한 것

- 서류/스위치/단말의 소리 분리, 접촉 프레임 동기.
- 체력 한 칸의 짧은 감소 잔상, 불가 버튼의 이유와 대비 정리.
- 접촉 FX·성공 토스트 중복 제거, 일반 효과 강도 낮추기.
- 표적 처음 발견 시 이름·직책 확인, 재플레이의 반복 안내 축약.

완료 기준: 평범한 경비 제압보다 필수 표적·핵심 서류·탈출의 의미가 더 강하게 읽히되, 주변 시야와 경보를 가리지 않아야 한다.

### 3. 나중에 다듬을 디테일

- 실제 저사양 Android/iPhone에서 접지·음성/효과음 지연·프레임·축소 모션을 검사.
- 지원 환경의 선택형 짧은 햅틱.
- CSS 중복·디버그 API 중복·최종 스테이지 정의 구조 정리.
- 꼭 필요한 도착·완료 카메라 정착만 조정.

일반 보행 잔상, 모든 암살의 슬로모션·강제 줌, 소모품 축포, 1P 장시간 카운트업, 매 보스 등장 컷신은 추가하지 않는다.

## 아트 방향 — 이스트워드 참고

이스트워드의 생활감 있는 2D 픽셀 실내, 두께가 읽히는 창틀, 가구의 일관된 비례와 재질, 따뜻한 광원과 주변 어둠의 층은 이 프로젝트에 맞는 참고점이다. 현재 캐릭터의 픽셀 밀도·상하 시점·광원 방향을 기준으로 후보 에셋을 비교한다. 한국 골목의 간판과 소품으로 장소성을 유지한다.

첫 비교 단위는 방 하나의 가구·문·창문·벽 스위치·조명 세트다. 스위치가 담당하는 공간과 불 꺼짐/경비 복구의 인과가 장면만으로 읽히는지 확인한다. 밤 분위기를 위해 상호작용 실루엣이나 적의 자세가 사라지면 대비부터 조정한다. 전체 배경 교체보다 이 작은 공간에서 캐릭터와 기능의 조화를 먼저 검수한다.
