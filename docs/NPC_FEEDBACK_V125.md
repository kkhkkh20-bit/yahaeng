## 원인과 수정

| 문제 | 확인한 원인 | 수정 |
| --- | --- | --- |
| 심문해도 말이 안 나옴 | `interrogate()`는 답변을 만들지만, 행동 중 잡담을 줄이는 필터가 붙잡힌 적까지 제외했다. 추격 중에도 별도의 필터가 있었다 | 붙잡힌 적과 진행 중인 심문 답변을 두 필터의 예외로 두고 최우선 표시. 남아 있던 잡담 연결도 심문 시작 시 종료 |
| 말풍선이 알림판 같음 | 사각 배경과 짧은 선으로 바뀐 상태였다 | 둥근 몸체와 화자를 향한 삼각 꼬리로 수정. 기존 누아르 색과 버튼·인물 회피 배치는 유지 |
| 수납함에서 뒤로 나옴 | 출구로 이동하면서도 캐릭터는 수납함 안쪽을 보고 있었다. 옆·뒤의 빈 칸도 출입 후보였다 | 옷장·사물함은 실제 앞문 쪽으로 출입. 안에서 몸을 돌려 앞으로 나온 뒤, 돌아서 닫고 이동. 현재 여섯 의뢰의 53개 수납함 모두 앞문 공간 확인 |
| 이벤트 동작이 굼뜸 | 여닫기 0.6초와 몸 이동 1.1초가 연속되어, 짧은 출입도 1.7초 이상 걸렸다 | 여닫기 0.38초, 사물함 이동 0.72초, 쓰레기통 이동 0.78초, 환풍구 이동 0.65초. 일반 문 0.65→0.48초. 열기·몸 이동·닫기 단계는 생략하지 않음 |
| 끊김 | CPU 프로파일에서 AI 갱신보다 조명 합성 비용이 컸다. 대사가 없어도 배치용 DOM 위치를 조회했고, 행동 안내와 말풍선에서 같은 조회를 반복했다 | 조명용 캔버스를 DPR과 무관하게 CSS 화면의 절반 크기로 사용하고 작은 마스크에서 합성. 대사가 없으면 조기 종료. 같은 프레임의 UI 영역 측정은 공유 |

공격·붙잡기·도구·미니맵 위치, 실제 시야·조명 탐지 판정과 길게 눌러 처치하는 규칙은 변경하지 않았다.

## 동작 검증

[검사 결과](feedback-v125/validation.json)

- 신규 `t_npc_feedback.py`: 여섯 의뢰 × 수동/자동 심문 × PC·세로/가로 모바일 4개 화면, 총 48회. 실제 붙잡기 후 답변, 행동·추격 필터, 잡담보다 높은 표시 우선순위, 둥근 외곽·꼬리, 조작·인물과의 겹침, 정보 지급과 중복 심문 방지를 검사했다.
- 신규 `t_cabinet_exit.py`: PC·모바일 각각 53개 옷장·사물함. 뒤·옆 방향 입력에서도 앞문으로 나오는지, 이동 중 시선이 이동 방향과 맞는지, 닫기 후 안전하게 종료하는지 확인했다. 각 환경에서 앞으로 걷는 표본 3,816개를 확인했다.
- 수납 206개 출입, 시체·붙잡은 적 동반 수납·회수, 환풍구·맨홀·창문·층 이동, 제압 입력과 후속 동작 검사 통과.
- 말풍선의 건물 위 렌더링·맵 경계 108개, 행동 안내와 조작 UI 회피, 첫 진입·튜토리얼·저장 복원 검사 통과.
- 전체 NPC·CCTV·피해를 켠 VIP 경로를 PC 190초·모바일 191초에 완료. 모두 체력 3·발각 0회. 자동화 컨트롤러는 맵을 알고 있으며 사람의 첫 플레이 평가와 구분한다.
- 첫 진입 검사의 로딩 대기를 `window.__game`으로 바꿔, 디버그 API가 아직 생성되기 전에 ReferenceError로 중단되는 간헐적 검사 실패를 수정했다.

## 성능 측정과 한계

로컬 Chromium, DPR 2, 동일 VIP 앞 도로에서 전체 AI를 켠 실제 requestAnimationFrame 루프를 사용했다. 초기 1.6초 뒤 4초를 기록했다. PC는 두 버전 모두 자동 해상도 조정 결과 DPR 1.5, 모바일은 모두 DPR 2였다. PC 화면은 1280×844, 모바일은 390×844이며 터치·화면 크기를 모사한 환경이다.

| 평균 CPU 시간 | v124 | v125 |
| --- | ---: | ---: |
| 모바일 화면 그리기 | 4.42ms | 3.26ms |
| 모바일 게임 갱신 | 1.30ms | 1.38ms |
| PC 화면 그리기 | 7.93ms | 5.16ms |
| PC 게임 갱신 | 1.94ms | 1.94ms |

[프레임·갱신·그리기의 표본 수, 평균·중앙값·95백분위와 DPR 기록](feedback-v125/runtime-perf.json)

빠르게 그리기만 반복하는 오프라인 CPU 프로파일도 조사에 사용했지만, 합성 대기와 배치 처리로 큰 지연 표본이 생겨 FPS 개선 수치로 쓰지 않았다. 위 표는 실제 실행 루프의 측정이다. 실제 iPhone GPU·발열·메모리·장시간 플레이를 검증한 결과는 아니다. 렉이 모두 사라졌다고 단정하지 않는다.
