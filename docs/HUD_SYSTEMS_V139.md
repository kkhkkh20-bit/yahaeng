# v139 — HUD부터 입력·시간·진행까지 리뷰 후 개선

기존 2D 화면과 플레이 흐름을 기준으로, 정보를 읽는 부담과 실제 시스템의 불일치를 우선 수정했다. 새 시각 스타일로 교체하지 않고 기존 색·글꼴·게임 화면을 유지했다.

## 발견한 문제와 반영

| 번호 | 기존 동작과 문제 | 적용 | 플레이에 주는 효과 |
| --- | --- | --- | --- |
| 1 | 평온 상태에서도 체력과 똑같이 생긴 빈 경계 칸 세 개가 공간을 차지했다. 가로 모바일에서는 의뢰 칸이 매우 좁아 문장이 잘렸다. | 평온의 경계 칸과 중복 경계 막대를 숨기고 실제 경계 이름·시간을 쓴다. 가로에서는 목표에 독립 폭을 주고, 짧은 세로에서도 상태 칸이 넘치지 않게 했다. | 체력과 주변 경계를 구분하고 의뢰 내용을 읽을 수 있다. |
| 2 | 끝낸 항목을 HUD에서 아예 제거해 진행을 확인하기 어려웠다. 탈출 안내는 펼쳤을 때 두 번 나왔다. | 제목에 목표 진행을 표시하고 완료한 항목은 펼친 목록에서 줄을 그어 남긴다. 탈출 중복 문장을 제거했다. 기절한 표적을 처치 완료로 세지 않으며, 탈출 가능은 실제 게임 판정을 사용한다. | 남은 일과 끝낸 일을 함께 확인한다. CCTV 기록 때문에 미완료이면 기록 삭제 필요를 표시한다. |
| 3 | 적에게 계속 보이는데도 “숨어 20초”를 표시했고, 직접 들어가는 모습을 들킨 수거함에서도 단순 “숨음”으로 보였다. | 실제 목격 중에는 시야 끊기를 안내하고, 놓친 뒤부터 추적 해제 시간을 표시한다. 들킨 은신처는 “은신처 노출”, 수색 중 은신은 “은신처도 확인한다”라고 알린다. 풀숲에 서 있는 상태를 숨음으로 단정하지 않는다. | 숨는 것과 추격 해제, 안전한 은신과 수색 위험을 구분한다. |
| 4 | 행동 목록이나 전체 목표를 읽는 동안 경비와 타이머가 계속 진행됐다. | 두 목록을 확인하는 동안 게임 시간을 멈춘다. 이동 입력/목록 닫기로 즉시 재개한다. 대상 선택은 선택만 하고 실행은 별도 입력으로 한다. 목록 안의 방향키·Tab·Shift+Tab·Home·End·Escape도 처리한다. | 모바일에서 대상 이름을 읽는 시간이 전투 부담으로 이어지지 않는다. 실제 이동·락픽·상호작용 시간은 계속 게임 규칙을 따른다. |
| 5 | 다트가 0개여도 목표가 있으면 버튼이 활성화됐다. 수납함 안의 사용할 수 없는 투척 도구도 활성처럼 보일 수 있었다. | 실제 잔량·자세·현재 행동에 맞춰 도구 표시를 맞추고, 빈 도구는 조준에 들어가지 않는다. “도구 바꾸기”와 불가능한 행동의 이유를 안내한다. 숨은 상태의 휘파람 유인은 가능하게 유지한다. | 눌러도 반응하지 않는 것처럼 보이는 상황이 줄어든다. |
| 6 | 2D에서 한 프레임이 0.05초를 넘으면 나머지를 버렸다. 15fps에서는 게임 시간까지 느려졌다. | 경과 시간을 작은 충돌 단계로 나눠 이동과 타이머를 처리한다. 명목 60fps의 16.7ms 프레임에서 처리를 두 번 하지 않도록 분할 수를 조정했고, 긴 중단은 0.12초까지만 따라잡는다. | 낮은 렌더 프레임에서 게임 자체가 느려지는 현상을 줄이며, 긴 멈춤 뒤 순간이동을 막는다. |
| 7 | 작은 도구/대상 전환 버튼, 흐린 붙잡기 조건, PC 도구 안내의 중복과 잘못된 설명이 있었다. | 모바일에서 보이는 조작 버튼은 최소 44px, 대상 숫자는 11px로 맞췄다. 붙잡기 조건의 대비를 올리고, PC에서도 실제 선택된 휘파람·심문·도구에 맞는 설명을 쓴다. 다트 전용 설명이 다른 도구에 붙는 중복 문구를 없앴다. | 버튼을 누르기 쉽고, 무엇이 가능한지 읽을 수 있다. |

## 확인을 위한 일시정지 범위

목표/행동 목록을 읽는 동안만 추가로 시간을 멈춘다. 입력을 정리해서 목록을 연 키나 터치가 공격·이동으로 넘어가지 않게 했다. 이동하면 목록을 닫고, 선택만 한 대상을 자동 실행하지 않는다. 전술 지도와 게임 메뉴는 기존 정지 흐름을 사용한다. 플레이 중 작업에 걸리는 시간을 없애거나 적의 탐지 규칙을 완화한 것은 아니다.

## 검수와 결과

- `tests/tutorial/hud_review.py`: 1280×800 PC, 390×844 세로 터치, 375×620 짧은 세로, 844×390 가로 터치. 평상시·수색 중 은신·노출된 은신처·빈 도구·완료 목록을 검수했다. 모바일의 표시된 조작 버튼이 최소 44×44인지, 미니맵과 조작 버튼/수색 표시가 겹치지 않는지도 확인했다.
- `tests/rev/t_hud_systems.py`: 통제 배치에서 경비 위치·체력·게임 시간이 목록 확인 중 변하지 않는지 검사했다. 실제 키보드/터치 조이스틱으로 목표 확인을 끝내고 이동하며, 실제 대상 버튼·목록·방향키로 선택했다. 선택만으로 조명이 꺼지지 않는지도 확인했다. 컨테이너 안 투척 불가와 휘파람 가능을 따로 검증했다.
- 같은 검사에서 1초의 입력을 60/30/15/10fps 경과 시간으로 나눴을 때 게임 시간은 모두 약 1.000초, 이동은 모두 약 99.03 게임 px였다. 이는 프레임 조건을 제어한 재현 검사이며 실제 기기의 렌더 fps 측정이 아니다. 긴 4초 중단의 따라잡기는 최대 0.12초인지, 16.7ms 프레임의 시뮬레이션 호출은 한 번인지도 확인했다.
- `tests/tutorial/first_session.py`: 실제 키보드/CDP 터치 입력으로 두 연습을 완료하고 첫 의뢰에 진입했다. AI와 도구·진행을 지급하거나 플레이어를 옮기지 않고 일정한 게임 시간으로 재현한다.
- `tests/rev/t_mission_flow.py`: 6개 의뢰 × 3개 진입 × 두 입력 방식으로 총 36개 시작→목표→탈출 경로가 통과했다. 플레이어 순간이동과 목표/열쇠 지급은 없으며, 진행 구조를 분리하기 위해 NPC 시뮬레이션은 고정한다. 실제 난이도나 라이브 AI 완주 검사와는 구분한다.
- `t_mission_progress`, `t_combat_policy`, `t_play_clarity`, `t_environment_targets`, `t_interaction_flow`, `t_target_body`, `t_hide_flow`, `t_feedback_v138`, `t_security_response` 회귀 검사를 통과했다. 기절/처치 입력, 층·문·도구·운반, 기존 저장과 은신처 수색 규칙을 함께 확인했다.

## 사용한 검수 도구와 코드 리뷰

승인해 설치한 Impeccable을 기존 화면 개선 범위로 사용했다. PC, 세로, 가로, 행동 선택, 빈 도구 다섯 DOM 상태를 실제 CDP 브라우저로 검사했다. 처음 발견한 붙잡기 조건의 낮은 대비와 대상 숫자의 10px 크기를 수정했고, 최종 다섯 상태는 모두 빈 결과다. Canvas 전체의 가독성과 게임 규칙을 보증하는 자동 결과는 아니므로 별도 화면·입력 검사를 함께 했다. [최초 결과](hud-v139/impeccable-before.json) · [최종 결과](hud-v139/impeccable.json).

Ponytail REVIEW 지침으로 `updateHUD`→상태/도구/목표 표시, 입력→목록 열기/닫기→프레임 진행, 기절→표적 판정→탈출까지 호출과 상태를 추적했다. 명목 프레임에서 불필요하게 시뮬레이션을 두 번 하는 분할을 피했고, 메뉴를 닫은 뒤 지난 시간을 한꺼번에 적용하지 않는지도 확인했다. 단일 브라우저와 현재 맵 규모를 전제로 했다. 새 외부 설치나 자동 훅은 추가하지 않았다.

검수 판정: 위 범위의 배포 가능. 실물 iPhone의 성능과 신규 사용자 학습 성공률은 측정하지 않았다. 시간 처리 개선은 렌더링 fps 자체가 상승했다는 뜻이 아니다.
