# 야행 구조

## 빌드가 하는 일
`build.py` 가 `src/js/*.js` 를 파일 이름 순서로 이어 붙여 즉시 실행 함수 하나(`(function () { … })();`)로 감싸고, `src/stages/*.js` 를 이어 붙인 의뢰 데이터, `src/template.html`, 미리 만든 그림 자료(`build/assets_city.json`, `build/pr/`, `build/kit_mk/kit.json`)와 함께 HTML 파일 하나로 만든다.

- 모듈은 같은 함수 범위를 나눠 쓴다. 다른 모듈의 함수·변수를 import 없이 그대로 부른다.
- `function` 선언은 순서와 상관없이 쓸 수 있다. 다만 **맨 위에서 바로 실행되는 코드**(예: `const X = …` 의 초기화식)는 앞 번호 모듈에 있는 것만 쓸 수 있다.
- 새 모듈은 비어 있는 번호에 끼운다. 번호는 5 간격이다.

## 의뢰 데이터 (`src/stages/`)
의뢰 하나는 객체 하나다. 주요 항목:
- `W, H, start, exit, build(m)`: 지도 크기·출발·출구, 지도 그리기 (`m.villa(x0, y0, x1, y1, 층수, { kind, use, signs, name })` 로 건물을 놓으면 실내 평면은 자동)
- `guards`: `{ kind: 'g1'|'g2'|'civ'|'dog', at: [x, y], post: 바라보는 각도 }` 또는 `{ route: [[x, y, 멈춤초], …] }`. `fl`(층), `wander`(서성이는 사각형), `target`(표적), `radio`(무전기) 등
- `zones`: 구역. `[[x0, y0, x1, y1, 'pub'|'res'|'hos', 'roof'|null, 이름표], …]` 뒤에 적은 것이 우선한다.
  - 적지 않은 곳: 거리 = 공개, 건물 안·지붕 = 출입 금지
  - `zones` 자체가 없는 의뢰는 옛 규칙(어디서나 적진)을 따른다
- `items`(훔칠 것), `wires`(전깃줄), `lamps`, `challenges`(도전 과제 키, 정의는 `25_records.js` 앞의 `CH`), `hints`, `brief`

## 실내 평면과 가구 (`10_interior.js`)
- 세대 나누기(`unit`):
  - 앞쪽(정면 창 쪽) = 거실·주방 (주방은 계단·현관 쪽)
  - 뒤쪽 = 욕실(현관 쪽)·안방(먼 쪽)·작은방
  - 한 세대가 8칸은 되어야 두 세대로 나눈다
  - 얕고 넓은 집은 방을 옆으로 두고, 아주 작은 집은 원룸이다
- 가구 놓기 `furn(x, y, w, h, 종류, 막힘, 방향, 비울칸)`:
  - 방향 r: 0 남 · 1 동 · 2 북 · 3 서 (가구가 바라보는 쪽)
  - 비울칸: 침대 옆, 의자 자리, 싱크대 앞처럼 써야 하는 칸. 놓은 뒤에는 다른 가구가 그 칸을 못 쓴다.
  - 계단에서 모든 바닥 칸으로 가는 길을 막으면 놓지 않는다.
- 방 규칙:
  - 안방: 침대 머리는 안쪽 벽. 넓으면 2인 침대와 협탁 둘. 옷장은 침대와 떨어진 안쪽 벽.
  - 작은방: 1인 침대와, 의자와 마주 보는 책상.
  - 욕실: 욕조, 변기, 세면대, 세탁기.
  - 주방: 안쪽 벽을 따라 냉장고·싱크대·가스레인지·수납장(앞은 비움). 그 앞에 식탁과 의자.
  - 거실: TV와 마주 보는 소파, 그 사이 깔개, 스탠드, 화분, 책장.
  - 가게·사무실·PC방·학원·식당: 의자가 딸린 책상·식탁 줄, 줄 사이 통로.
- 구운 가구 그림 열쇠는 `종류_가로x세로(_r방향)` 이다 (`furnKey`). 새 종류·방향을 쓰면 아래 “가구만 굽기”를 돌린다.

## 굽기 (지도·건물 모양이 바뀌었을 때)
```
python3 build.py
python3 tools/prerender/kenney_ruk/spec.py 6
python3 tools/prerender/kenney_ruk/restore_mk.py m6  # 원본이 없는 경우: 필요한 CC0 모델만 복구
python3 tools/prerender/kenney_ruk/bake_mk.py m6    # 바뀐 의뢰만 (생략하면 전부)
python3 build.py
```
- `spec.py` 는 게임이 정한 건물·옥상 배치를 `spec.json` 으로 뽑는다.
- `bake_mk.py` 는 기반 키트(`build/kit/kit.json`)에 MegaKit 건물 외관을 더해 `build/kit_mk/` 에 저장한다.
- `restore_mk.py`는 고정 리비전의 표준 CC0 팩에서 해당 의뢰에 필요한 모델·텍스처만
  `dl/megakit`에 복구한다. 원본 전체팩이 이미 있으면 다운로드할 필요가 없다.
  `tools/prerender/mk`는 저장소 기준 상대 링크다. 의뢰 하나를 구울 때 다른 의뢰와
  공유 키트는 보존한다. 굽기 도구에는 three.js, Pillow, Playwright/Chromium이 필요하다.
- 기반 키트(바닥·나무·가구)를 바꿀 때만 `bake_base.py` 를 돌린다.
- 새 가구 종류·방향만 생겼으면 `python3 spec.py 6 && python3 bake_base.py furn`: 빠진 가구만 구워 두 키트에 넣는다(건물은 그대로).
- 캐릭터 동작을 더할 때는 `tools/prerender/render.html` 에 포즈를 만들고 `run.py` 의 `ANIMS` 끝에 붙인 뒤 `python3 run.py` 로 `build/pr/` 를 다시 만든다.

## 테스트
`python3 tools/run_tests.py` 로 돌린다. 하는 일:
1. 빌드
2. 도달 검사: 출구·물건·경비 자리에 닿을 수 있는지 (`window.__game.validate()`)
3. 회귀 테스트 `tests/rev/t_*.py` 등. 병렬로 돌리고, 실패한 것은 혼자 한 번 더 돌린다.
4. 무작위 조작 6판

로그는 `build/test_logs/` 에 남는다. 새 기능을 넣으면 `tests/rev/t_기능.py` 를 하나 더한다.
- 문제가 있으면 0 이 아닌 코드로 끝나게 쓴다.
- 페이지 오류는 `print('errs', errs[:3])` 로 내보낸다.

## 계단 구조와 판정 (v82)
- `stairFloor()`가 층별 계단 방향, 올라가는 줄, 내려가는 구멍과 열린 층계참을 결정한다. 그림·라벨·버튼·자동 이동·NPC 층 이동이 같은 구조를 참조한다.
- 내려가는 구멍의 `K` 두 칸은 난간으로 막힌 영역이다. 버튼은 열린 끝 앞의 걸을 수 있는 층계참에서만 활성화한다. `stairWells()`는 이 층계참을 고립된 창고로 바꾸는 후보를 거부한다.
- 오르기: 아래층 입구 → 계단 → 내부 꺾임 → 위층 계단 → 열린 층계참. 내려가기는 역순이다. `crossStairLevel()`이 정해진 지점에서 층을 바꾸며, 완료 콜백은 마지막 지점과 같다. 운반 중인 시체도 같은 프레임에 층을 바꾼다.
- 좁은 계단실 4곳은 한 칸 폭을 유지하고 올라가는 안쪽과 내려가는 입구를 구분한다. 층 이동 중 같은 방향 입력을 계속 누르면 다시 계단에 진입하지 않으며, 손을 떼거나 방향을 바꾸면 해제한다.
- `t_stair_geometry.py`: 의뢰 6개와 도시의 실내 계단 61개·옥상 계단 72개 왕복, 난간 옆/뒤 판정, 키보드·저속 모바일 입력, 운반·NPC 이동·구버전 저장 이관을 검사한다. `t_stairs_all.py`는 실제 행동 선택과 방향키 이동을 검사한다.
