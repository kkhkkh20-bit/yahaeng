# v153 게임 UI·글꼴 통일

[PC·모바일 원본 전후 비교](hud-v153/index.html) · [검증 기록](hud-v153/details.html)

사용자 요청은 화면마다 달라지는 글꼴 굵기를 통일하고, 스킬 트리를 직선으로 바꾸고, HUD와 메뉴를 인게임 화면처럼 정리하는 것이다. 기존 게임·포스터·로고·어두운 HUD/스킬 색상과 조작을 기준으로 기존 화면을 확장했다.

## 글꼴이 섞이던 원인과 변경

이전 UI는 `IBM Plex Sans KR`를 선언하면서 실제 파일은 제공하지 않았고, 메뉴 제목에는 한글 일부만 들어 있는 `Ink Display`를 사용했다. 그 파일은 Black Han Sans이며 글자 254개만 매핑되어 있어 같은 제목 안에서도 다른 글꼴로 대체될 수 있었다. 캔버스 안내는 600–900 굵기의 시스템 글꼴과 Galmuri를 별도로 사용했다.

현재 HUD·메뉴·대사·키패드·캔버스 안내는 **IBM Plex Sans KR Regular / 400**을 공유한다. 한글 11,172음절 전체를 포함한 WOFF2를 자체 제공하며 폰트 합성 굵기를 끈다. 제목·본문·보조 정보는 크기·간격·색으로 구분한다. 기존 ‘야행’ 로고는 별도 로고 서체를 유지한다.

- CSS 별칭은 `Yahaeng UI`, 캔버스는 `uiFont(size)`다. 기존 캔버스 글꼴 지정 48곳을 공통 함수로 바꿨다.
- 실제 브라우저가 로드한 서체는 CDP의 `CSS.getPlatformFontsForNode`로 확인했다. CSS 선언만 확인한 결과가 아니다.
- 폰트가 준비된 후 게임의 첫 텍스트 측정을 시작한다. 다운로드가 실패하면 공통 대체 서체로 계속 부팅한다.
- 새 WOFF2는 561,500바이트다. Google Fonts의 원본 TTF를 글자 윤곽 변경 없이 WOFF2로 변환했다. 변환에는 이미 설치된 FontTools와 Node Brotli를 사용했으며 실행 환경 의존성을 추가하지 않았다.
- 글꼴을 해시 기반 정적 자산으로 분리해 재방문 시 캐시한다. 이전의 사용하지 않는 Galmuri 로딩과 중복 제목용 서체 적용을 제거했다. 원본·해시·OFL 라이선스는 `src/fonts/ui-font.json`과 `OFL-IBMPlexSansKR.txt`에 있다.

## 스킬 연결

곡선 명령을 없애고 수직·수평 직선과 화살표로 실제 선행 관계를 그린다. 기존 27개 기술·24개 선행 연결·비용·보상·저장·습득 경로는 유지한다. 전체 트리와 오른쪽 설명 창, 작은 화면의 스크롤도 유지한다.

## 인게임 메뉴와 HUD

- 의뢰 선택: 큰 카드 격자 대신 미션 번호·목표·보상·실제 지도 썸네일을 갖는 목록으로 바꿨다.
- 일시정지: 실제 플레이 장면을 뒤에 남기고 HUD를 숨긴다. 큰 세로 메뉴와 추적 목표를 분리한다.
- 브리핑·설정·대화·결과: 어두운 공통 색상, 일정한 글자 굵기, 얇은 구분선, 같은 버튼 상태를 사용한다. 밝은 종이색 화면에서 제목 일부만 지나치게 굵어지는 테마 덮어쓰기를 제거했다.
- HUD: 목표·상태·미니맵 위치와 기존 조작을 유지하면서 서체·키 표시·체력·메뉴 표현을 맞췄다. 모바일 주요 공격/행동 버튼은 원형이며 기존 동작 SVG와 동사를 함께 표시한다. 버튼의 실제 동작과 길게 누르기 규칙은 바꾸지 않는다.
- 결과 화면 비교는 `showEnd(true)`로 만든 **표시 확인용 예시**다. 실제 미션을 완료한 기록으로 주장하지 않는다. 실제 경로 완료 검증은 회귀 검사에 별도로 포함된다.

## 소유권과 검증

`interface.css`는 공통 타이포그래피와 메뉴 표현, `hud.css`는 플레이 HUD와 기술 화면의 배치를 담당한다. `00_ui_typography.js`는 캔버스의 글꼴을 소유한다. 이전 밝은 메뉴 테마와 미션 카드의 충돌하는 배치 덮어쓰기를 정리했다.

기존 회귀 47개, 별도의 UI 검사 1개, 빌드/정적 자산 검사 7개를 통과했다. UI 검사는 1440×900, 390×844, 844×390, 320×568에서 실제 서체·400 굵기·직선 연결·세 미션 목록·44px 이상 조작·메뉴 복귀를 확인하며, 폰트를 차단한 상태의 부팅도 확인한다. HUD 상태 검사는 네 화면 크기의 수색·발각·빈 도구·목표 확인·대상 선택을 실제 입력으로 확인한다. 첫 두 연습도 활성 AI와 실제 PC/터치 이동으로 완료했다.

Impeccable의 기존 화면 확장 예외를 적용했다. PRODUCT.md·DESIGN.md는 기존부터 없으며, 새 시각 정체성을 만들거나 제품 사실을 바꾸지 않았다. 독립 검수는 24개 화면과 소스를 검토해 `ship`을 반환했다. 실제 기기 조작 검증은 별도 자동화 결과이며 독립 검수자가 직접 플레이했다고 쓰지 않는다.

기계 검출은 컴파일된 UI에서 한 번 실행했다. 실제 브리핑 버튼의 낮은 hover 대비는 수정했고, 이전 그림자와 작은 범례도 정리했다. 나머지 항목은 11px 정보 표시와 기존 shorthand/cascade의 정적 경고로, 실제 계산값과 렌더링을 함께 검토했다. [검출 및 처리 범위](hud-v153/design-detect-resolution.json).
