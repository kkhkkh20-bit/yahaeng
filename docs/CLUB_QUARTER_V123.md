# v123 — 클럽 기준 구역의 공간·그래픽·이동 정리

## 목표와 범위

첫인상에서 주인공·층·출입구·현재 행동을 이해할 수 있는 화면을 만든다. 새 공략 시스템보다 공간 표현을 우선한다. 대표 의뢰 「VIP」의 클럽 입구·홀·직원 통로를 기준 구역으로 잡았다. 다른 의뢰 전체를 같은 그래픽으로 교체한 버전은 아니다.

[동일 장면의 PC·모바일 전후 비교](quarter-v123/index.html)

## 에셋 조사와 선택

기존 팩과 고정 리비전의 공개 모델 목록을 조사했다. 무료라는 설명만 있는 자료 대신 실제 CC0 라이선스를 확인할 수 있는 두 팩을 선택했다. 새 AI 이미지는 사용하지 않았다.

| 자료 | 선택 이유 | 이번 사용 |
| --- | --- | --- |
| [Kenney Furniture Kit](https://kenney.nl/assets/furniture-kit), CC0 | 모델을 같은 투영·조명으로 다시 출력할 수 있고 형태·면적을 맞추기 쉬움 | 소파·바·스피커·화분·테이블·책상·의자·수납장용 샘플. 해당 가구가 있는 클럽 층에서 사용 |
| [Quaternius Downtown City MegaKit](https://quaternius.com/packs/downtowncitymegakit.html), CC0 | 기존 도시 모델과 계열이 같고 개별 설비·문틀 모델이 있음 | 배수구·문틀. 플랜터는 기존 옥상 화분 위치용 샘플. 맨홀 뚜껑·볼라드도 검토용으로 구웠으나 기존 출입·충돌 동작을 가진 물체에는 덮어씌우지 않음 |
| 기존 Quaternius 여성 인물 | 사용자가 선택한 주인공 외모와 복장별 동작을 유지할 수 있음 | 캐릭터 모델을 교체하지 않고 외곽선과 실제 이동에 따른 걸음 진행을 조정 |

외벽·지붕·잘린 벽·바닥은 현재 게임 좌표에 맞춘 자체 2D 표현이다. 가구·문틀·배수구의 모델 렌더와 구분한다. 캐릭터·물체 전체를 새로운 시점으로 재제작했다고 표현하지 않는다.

원본 데이터만 고정 미러에서 내려받았고 외부 저장소의 코드는 실행하지 않았다. 두 라이선스, 원본 SHA-256, 고정 리비전은 [src/art/quarter/sources.json](../src/art/quarter/sources.json), `LICENSE-Kenney.txt`, `LICENSE-Quaternius.txt`에 기록했다. 렌더 결과는 14개이며 재생성 도구는 `tools/prerender/bake_quarter.py`다. 해당 도구는 기존 `tools/prerender/node_modules`와 `furnglb`의 원본 자료를 사용한다.

## 적용 설계

| 문제 | 적용 |
| --- | --- |
| 밖에서 건물 전체 평면이 반투명하게 겹쳐 지붕과 실내를 혼동 | 클럽의 전체 평면 오버레이를 제거. 가까운 실제 창문·문을 바라볼 때 시야가 통하는 부분만 표시. 멀리 떨어져 있거나 다른 쪽을 보면 지붕 유지 |
| 비슷한 창문 줄 사이에서 입구를 구별하기 어려움 | 실제 출입문 좌표에 맞춰 깊이 있는 문틀·상부 차양·문턱을 배치. 임의의 가짜 출입구는 추가하지 않음 |
| 실내·외벽·가구의 표현이 섞임 | 잘린 벽의 윗면·앞면과 창틀을 구분. VIP룸은 목재, 홀·통로는 큰 바닥 면으로 표현. 바·소파 등은 동일 투영으로 구운 모델 사용 |
| 지붕 위 구조물의 그림과 충돌이 따로 노는 위험 | 계단실은 기존 `cells`·`door` 좌표, 물탱크 등은 기존 옥상 배치 데이터를 따라 그림. 길·계단 도착점·문·창문 판정을 이동시키지 않음 |
| 골목이 반복 타일로 보임 | 클럽 앞 보도의 포장 간격·배수 홈을 정리. 작은 배수구는 배경 설비로 사용하며 새 은신처로 표시하지 않음 |
| 흰 외곽선과 여러 시야가 인물보다 먼저 보임 | 모바일의 중복 외곽선을 줄이고 발밑 위치 표시 유지. 기준 구역의 평상시 경비 시야는 옅게, 평온한 주민의 시야는 숨김. 실제 의심·발각과 탐지 판정은 유지 |
| 입력만 눌러도 제자리걸음, 정지·출발 시 걸음이 튐 | 걷기·끌기 등의 진행을 실제 이동 거리와 연결. 벽에 막혀 이동량이 없으면 걸음과 지상 발소리가 진행되지 않음. 수로·덕트 이동에도 같은 측정 적용 |
| 모바일에서 동작이 작음 | 기준 구역에서 카메라를 8% 가까이 조정. 기존 보간과 주인공의 화면 하단 배치를 사용하며 미니맵·공격·붙잡기·행동 버튼의 위치는 유지 |

새 에셋을 모두 디코딩한 뒤 바닥 캐시를 만들어, 처음 진입한 판에서 이전 임시 그림이 계속 남는 일을 막았다. 3D는 제작 단계에서만 사용하며 플레이 중에는 기존 2D 렌더러를 사용한다.

## 검증

- 신규 `t_quarter_presentation.py`: 14개 샘플의 완전한 실루엣·투명 여백, 시작 시 이미지 준비, 불투명 지붕, 가까운 창문 접근·시선 방향, 기존 충돌·문·계단 좌표 유지, 저장 복원, 실제 이동에 따른 걸음·정지·벽에 막힘을 PC·모바일에서 검사.
- 기존 `t_motion_windows.py`: 인물 17,512프레임의 여백, PC·모바일 창문 496개·층 72개·접점 128개 검사 통과. 인물 모델은 이번에 다시 굽지 않았으며 기존 동작 회귀 검사로 사용했다.
- 계단·환풍구·수납·상호작용·제압 입력·후속 동작, 첫 진입·모바일 조작 안내 검사 통과.
- 경비 대응 규칙과 전체 AI의 6개 대응 장면, 구토제·간판·뒷문 12개 장면 통과.
- 전체 NPC·CCTV·피해를 켠 VIP 매복 경로를 PC·모바일에서 완료. PC 3분 10초·체력 3·발각 0회, 모바일 3분 11초·체력 1·발각 3회. 자동화 컨트롤러는 맵을 알고 있으며 사람의 첫 플레이나 재미 평가와는 구분한다.
- 기존 6개 의뢰 × 3개 배치 × PC·모바일의 36개 경로 통과. 이 검사는 NPC를 정지하고 이동·문·회수·처치·탈출 연결을 확인한다.

## 남은 범위

전체 맵의 건물 배치 변경, 다른 의뢰의 에셋 통일, 모든 인물·행동의 새 애니메이션 제작은 이번 범위에 포함하지 않았다. 기준 구역의 전후 화면을 먼저 비교하고, 이후 같은 기준을 다른 장소에 확장한다. 이 버전만으로 상용 게임 수준의 그래픽이나 실제 휴대폰 성능을 달성했다고 주장하지 않는다.
