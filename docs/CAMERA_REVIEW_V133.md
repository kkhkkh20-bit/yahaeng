# v133 — 모바일에서 골목과 층이 읽히는 시점

사용자 화면에서는 지상에 있는 인물의 발 표식이 지붕 위에 보였다. 낮은 카메라, 세로 화면의 좁은 가로 범위, 작은 원형 가림 제거가 겹친 문제다. v132의 진행 가능 여부 검사만으로 이 화면 문제를 발견하지 못했다.

## 조사와 적용 기준

공식 Steam 화면을 내려받아 직접 확인했다. 아래 게임의 카메라 수치를 추정해서 그대로 복사한 것이 아니라, 화면에서 확인한 공간 구성 원칙을 현재 맵에 적용했다.

| 자료 | 화면에서 확인한 점 | 야행에 적용 |
| --- | --- | --- |
| [Shadow Tactics 공식 화면](https://store.steampowered.com/app/418240/) · 첫 번째 스크린샷 | 거리·문·적의 시야가 한 지면에서 이어져 보인다. 지붕이 인물 주변 이동 공간을 삼키지 않는다. | 골목 바닥을 따라 앞 건물의 가리는 부분을 걷어낸다. |
| [Commandos 2 공식 화면](https://store.steampowered.com/app/6830/) · 세 번째 스크린샷 | 넓은 이동 공간과 건물 경계가 먼저 읽힌다. | 휴대폰은 세로 범위 고정 대신 가로 지면 폭을 확보한다. |
| [Desperados III 공식 화면](https://store.steampowered.com/app/610370/) · 세 번째 스크린샷 | 계단·발판·난간이 지상과 높은 길을 구별한다. | 실제 층고와 계단을 보존하고, 발 표식도 인물이 있는 바닥의 깊이 판정을 받게 한다. |
| 기존 야행 | 위에서 보는 지면과 벽 경계가 명확하고, 이동 방향이 화면 방향과 맞는다. | 기존 2D 표시로 같은 좌표를 비교하고, 현재 Cloudflare 2D 게임도 별도로 확인했다. |

자료 URL과 원본 스크린샷 주소는 `camera-v133/references.json`에 기록했다. 참고작의 미술 자산을 게임에 가져오지 않았다. 실제 Cloudflare의 기존 2D 화면과, 새 구역을 기존 2D 렌더러로 표시한 화면은 서로 구분해 실었다.

## 변경

- 카메라를 지면 기준 약 35.3도에서 54도로 높였다. 54도는 현재 맵에서 비교해 정한 수치다. 기존 카메라 거리를 유지해 안개나 밝기가 각도 변경 때문에 달라지지 않게 했다.
- 세로 휴대폰은 기본 확대에서 가로 지면 폭을 최소 8m 확보한다. 390×844에서 수직 범위는 약 17.3m다. 주인공 발은 화면 가로 45%, 세로 60%에 둔다. 중앙 상태 표시·오른쪽 미니맵·모바일 버튼은 기존 위치를 쓴다.
- 원형 점무늬 구멍을 지면 구획을 따르는 건물 절개로 교체했다. 같은 골목 바닥에 겹쳐 그려지는 벽·지붕만 걷어낸다. 바닥을 숨기던 지붕 위에 발 표식만 남는 현상을 막는다.
- 건축물 재질과 가구 재질을 분리했다. 책상·계단·수납함·조작 중인 문짝을 가림 제거가 지우지 않는다.
- 창문을 통해 실내가 보이는 계산, 조준·적 선택·미니맵 범위, 화면 방향 이동을 새 카메라 투영에 맞췄다. 기존 창문·벽·층별 인물 표시 규칙을 사용한다.
- 마우스 휠·기존 확대 버튼이 사선 화면에도 적용된다. 휴대폰은 두 손가락으로 확대할 수 있다. 핀치는 이동·처치 입력을 해제하고, 손을 떼도 이동이 이어지지 않는다. 기존 2D 확대 저장값은 사선 화면의 시작 배율로 쓰지 않는다.
- 매번 장면 전체를 광선으로 검사하던 가림 감지를 제거했다. 건물 절개는 작은 지면 구획 텍스처를 사용한다.

## 검수

출발점·서쪽 골목·수거함·뒷문 쪽·1층 홀·2층 정산실을 PC/세로 모바일의 같은 좌표에서 비교했다. 두 화면 크기에서 렌더 결과의 실제 픽셀을 읽어 인물이 그려지는지, 발 주변의 걸을 수 있는 지면 표본이 지붕에 덮이지 않는지 검사한다. 장면 그래프의 `visible` 값만 확인하는 검사가 아니다. 물체가 있는 칸은 바닥 검사에서 제외한다.

확대, 기존 확대값 분리, 실제 터치 핀치와 이동 입력 해제, 카메라 역투영도 확인한다. 기존 2D와 사선 화면에서 8방향 이동을 측정해 방향별 화면 속도가 일정한지 검사했다. 390×844 기본 걷기는 양쪽 모두 약 108px/게임초였다. 이는 시뮬레이션 속도이며 기기 FPS가 아니다.

활성 AI 상태로 에피소드의 PC 번호판·계단 경로와 모바일 맨홀·창문 경로를 다시 완주한다. 창문과 열린 문을 통한 시야, 벽과 다른 층의 인물 차단, 상층 페이드, 수납함 발견·용량·출입, 지하·덕트 우회, 짧게 기절·길게 처치도 회귀 검사한다. 공개 뒤에는 실제 HTTPS에서 PC·터치 출발·이동·메뉴 복귀와 게시 파일 해시를 확인한다.

```
python3 build.py --episode --club --itch
python3 tests/camera/capture.py episode-one after
python3 tests/camera/check_view.py
python3 tests/episode/play_episode.py staff
python3 tests/episode/play_episode.py window
python3 tests/rev/t_club_systems.py
python3 tests/rev/t_club_projection.py
python3 tests/rev/t_club_pace.py
python3 tests/rev/t_club_passages.py mobile
python3 tests/rev/t_access_inputs.py
python3 tests/episode/verify_deployment.py
```

클라우드 브라우저의 터치 검수는 실제 iPhone의 GPU 성능 측정이 아니다. 이번 변경은 시점과 공간 가독성에 집중했으며, 맵의 크기·생활 소품·전체 캠페인 미술을 새로 제작한 작업은 아니다.
