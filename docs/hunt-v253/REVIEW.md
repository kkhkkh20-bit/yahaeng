# v253 맵 동선과 도주 후 수색

검토 결과, 도주가 쉬운 주된 원인은 적이 시야를 잃은 지 1.2초 만에 느린 수색으로 전환하는 점과, 거리 120px 안팎만 확인하는 외부 수색이었다. 새로 목격해도 완료된 수색 계획을 재사용하거나, 실제 수색 중인데 경보 시간이 끝나 복귀하는 문제도 있었다. 탈출 안내는 벽과 건물을 무시한 직선 거리로 출구를 선택했다.

## 적용

| 맵 | 동선과 탈출 |
| --- | --- |
| 닫힌 배차실 tB | 학습 동선과 단일 탈출 유지 |
| 운송 단지 p0 | 서쪽 담에 두 칸 작업 통로, 남쪽 철문 / 서쪽 작업 골목 |
| 거래소 e2 | 서쪽 정비 골목 / 동쪽 하역 골목 |
| m2 | 기존 동쪽 큰길 / 서쪽 골목을 실제 도보 경로로 비교 |
| m4 | 기존 서쪽 큰길 / 공터 하수구를 실제 도보 경로로 비교 |
| m6 | 기존 동쪽 정문 / 남쪽 담 개구멍을 실제 도보 경로로 비교 |
| m7 | 기존 서쪽 시장 골목 / 동쪽 큰길을 실제 도보 경로로 비교 |
| 본부 m5 | 남쪽 교차로 벽 중앙 한 칸 개방, 양끝 엄폐 유지. 동쪽 본부 출구 / 서쪽 뒷골목 |
| 사저 n1 | 남서쪽 골목 / 북동쪽 관리 골목 |

출구 네 곳을 추가했고, 기존 목표·보상·적 인원은 유지했다. 가까운 출구도 돌아가는 길이 길면 실제로 짧은 경로의 출구를 안내한다. 플레이어 전용 개구멍도 경로에 포함한다. 이전 체크포인트는 몸 상태와 진행도를 보존하며 통로와 출구를 갱신한다.

목격자는 마지막 목격 지점 가까이까지 추격한다. 실제로 본 이동 방향을 기억하고, 그 방향의 지점과 외부의 더 넓은 범위, 가까운 출입구·사다리·은신처를 수색한다. 기존 현장 예약과 물리적 이동, 층별 접근 검사를 유지한다. 새 목격 정보가 있으면 완료된 계획 대신 새 계획을 만든다. 수색 중인 경비가 있는데 경보 시간만 끝나 전원 복귀하는 현상을 막았다. 실제 수색이 끝나거나 유효 시간이 지나면 정상 복귀한다.

초반 운송 단지는 수색 배정 최대 2명·45초, 후반 본부와 사저는 최대 6명·75~80초로 설정했다. 모든 적이 플레이어 위치를 공유하는 방식은 사용하지 않는다. 신고·전달 조건은 기존 그대로이며, 목격 이후 숨은 플레이어의 좌표를 수색 계획에 사용하지 않는다. 캐릭터가 가만히 있으면 오래된 이동 방향도 사라진다.

## 검증과 범위

- 공개 캠페인 9개 맵의 모든 탈출 원에 대한 구조적 경로 검사 통과. 잠긴 문을 열 수 있다는 전제의 구조 검사이며, 9개 전체를 직접 완주했다는 뜻은 아니다.
- 초반 p0는 원래 AI·카메라·체력·스킬·시간을 유지한 채 일반 브라우저 프레임과 키보드 / 터치 입력으로 각각 완주. 기절 2명, 목표 처치 1명, 은닉 3명, 변장, 체력 3, 발각 0. PC는 새 서쪽 통로, 터치는 남쪽 출구로 탈출했고 다음 임무 연결을 확인했다. 브라우저 터치는 실제 iOS 기기 검증이 아니다.
- 통제된 수색 시험에서 실제 목격 방향, 외부 수색 지점, 새 목격 시 재계획, 숨은 위치 미참조, 수색 중 경보 유지와 종료를 확인했다.
- 기존 층간 추격, 변장 신고 9개 상황(PC / 모바일), 청각 우선순위, 휘파람과 모서리 끌어오기, 이동 통로, 지도 경계, 임무 진행 회귀 검사 통과.
- 빌드 검사 8개와 물리적 상호작용 검사 20개 묶음 통과.

증거: `flow-hunt.json`, `native-p0.json`, `pc-complete.webp`, `mobile-complete.webp`. 후반 임무의 실제 완주 및 장시간 반복 플레이 밸런스는 이번 검증에 포함되지 않는다. m7의 옛 조작 스크립트는 제거된 바닥 복장을 전제로 해 실행 중단되었으며, 성공 증거로 계산하지 않았다.
