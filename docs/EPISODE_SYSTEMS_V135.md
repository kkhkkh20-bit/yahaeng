# v135 — 기존 야행 규칙으로 연결한 에피소드

기존 야행의 규칙 코드와 사선 화면의 연결을 대조했다. 별도 판정을 새로 만드는 대신 이동·충돌·행동·AI·보안·목표 상태를 기존 코드에서 받고, 물체의 위치와 동작·표시를 그 상태에 연결한다. 배경 미술과 CC0 인물 자산은 유지한다.

## 발견한 문제와 변경

| 항목 | 기존 규칙 / 누락 | 이번 에피소드 |
| --- | --- | --- |
| 화단 | `45_player.js`의 B칸 웅크림 은신은 있었지만 `nearHide()`는 수납함만 찾았다. 이전 검사는 숨기 함수를 직접 실행했다. | 실제 행동 목록에 화단 진입을 연결했다. 웅크림 은신도 유지한다. 방향 이동 탈출·끌어들이기·기습은 같은 기존 처리다. 낮은 테두리와 사람을 가리는 잎을 쓰고, 숨은 주인공은 잎을 옅게 해 위치를 확인할 수 있다. |
| 행동의 연속 | 완료 후 사라진 행동 대상을 계속 고정해 다음 행동이 막혔다. | 자기 행동이 정상 완료되면 선택을 해제한다. 줍기→사용, 옷 갈아입기→운반, 넣기→혼자 숨기, 환풍구/맨홀 출입이 이어진다. 다른 이유로 선택 대상이 사라진 경우의 실행 방지는 유지한다. 가까운 소지품·사용 대상을 먼 문보다 먼저 제안한다. |
| 화면·벽 | 대각선 화면과 미니맵 방향이 달랐고, 벽이 낮은 바닥 띠처럼 보였다. 열린 문 위의 두꺼운 벽이 뒤의 사람을 가렸다. 잘린 벽의 원래 높이 그림자도 남았다. | 북쪽을 위로 고정한 65도 시점. 모바일 가로 지면 8m, 발 기준 가로 45%·세로 60% 유지. 실내 벽 1.15m / 전면 벽 0.9m로 단면을 보이고 어두운 마감 면을 둔다. 창턱 1.07m와 얇은 문·창틀은 남긴다. 문 위 벽을 걷어내되 열린 통로 위에 마감 판을 만들지 않는다. 그림자에도 절개를 적용한다. |
| 시야·조명 | `canSee`, `guardCone`, `castRay`, 조명/자세 계산은 원본에 있다. 그림과 다른 층 계산을 구분해야 한다. | 기존 판정을 사용한다. 적의 실제 의심 진행을 작은 표시로 연결하고 손전등의 실제 각도·거리와 벽 차단을 그린다. 계산 후 층을 복원한다. |
| 문·창문·층 | `windowPassage`, `stairTravel`, `58_access_flow.js`의 실제 경로가 있다. | 같은 경로로 문, 1층 창문, 2층 창문, 계단, 맨홀·하수도, 환풍구·덕트를 사용한다. 시설은 해당 층에서 유지한다. 실내 인물 발견은 창문·열린 문·벽의 실제 LOS를 따른다. |
| 수납·운반 | `57_hide_flow.js`의 접근·문 열기·수납·꺼내기·탈출과 정원 판정. | 수거함·화단·맨홀·사물함·옷장에 연결. 사물함/옷장에서도 사람과 몸의 정원을 함께 검사한다. 화장실 안 청소용 사물함을 추가해 식당 경로의 쓰러진 경비를 숨길 수 있다. |
| 대인 행동 | `58_combat_intent.js`, `43_cqc_radio.js`, `60_interact.js`의 붙잡기·심문·기절·처치·운반·변장·훔치기. | 같은 입력 처리기를 쓴다. 짧게 기절 / 길게 처치 유지. 직원이 소지한 파란 카드와 직원 출입문을 연결하고 양면 카드 리더기를 그린다. |
| 식사·화장실 | `42_social.js`, `43_surfaces.js`, `44_dining.js`의 소지품·사용·실제 일과 이동. | 골목식당을 출입 가능한 방으로 만들고 진열대 위 앞치마·약, 식사, 변기·세면대·사물함을 배치했다. 식당 경비를 가까운 식사와 화장실 동선에 연결했다. 약이 준비되면 다음 긴 식사 주기를 기다리지 않는다. 목격과 허가 복장은 기존 규칙을 따른다. |
| NPC의 문 통과 | 길이 없는 것을 도착으로 처리해 식사 일과가 진행되지 않았다. | 통과 권한이 있는 닫힌 문을 경로에 포함하고, 가까이 가서 손을 대고 0.36초 동안 연다. 실제 문 상태를 바꾼 뒤 통과한다. 도착하지 않은 빈 경로는 도착 처리하지 않는다. 막힌 식사 방문도 다시 이어 간다. |
| CCTV·녹화 | `40_guard_ai.js`, `37_security_camera.js`의 시야·목격·관리자·녹화와 삭제. 새 구역에는 시설이 없었다. | 실제 카메라, 보안 담당자, 책상 모니터를 추가했다. `cameraSees()`를 AI와 표시에서 같이 사용한다. 관리실 행동은 전원 차단과 신원 녹화 삭제로 이어진다. |
| 건물 전원 | 원본의 건물 두꺼비집은 자동 평면 건물에만 생성됐다. | 지정한 외벽에 두꺼비집을 배치하는 데이터를 추가했다. 클럽 실내등과 CCTV가 함께 꺼지고, 원본의 경비 복구 행동으로 이어진다. 외부 가로등은 별도 전원이다. |
| 간판 사고 | `58_sign_flow.js`의 고정 해제·낙하·충돌 시점 처리가 있다. | 2층 창가의 고정부·연결줄·간판을 같은 함정 객체에 연결했다. 길게 누른 뒤 손동작으로 풀고, 실제 낙하가 끝나야 아래 범위에 결과를 적용한다. |
| 도구·흔적 | 휘파람·빈 캔·유인물·다트·핏자국·닦기 등 원본의 상태와 수량. | 기존 처리와 표현을 유지한다. 약은 손에 들고, 쓰거나 내려놓으면 상태에 맞춰 표시가 바뀐다. |
| 주시·계획·진행 | 원본의 적 주시, 순찰로, 전술 지도, 발견한 목표/연결 입구·체크포인트·재시작. | 선택한 적의 실제 순찰 경로를 같은 바닥에 그린다. 원본 전술 지도에서는 3D 화면을 숨겨 투영이 섞이지 않게 하고 미니맵도 해당 투영을 사용한다. 목표는 짧은 방향·거리 표시로 연결한다. 소개·메뉴·재시도는 같은 에피소드로 돌아온다. |

## 완주와 검수

- `episode-pc.json`: 심문·변장·은닉 → 책상 메모·번호판 → 계단 → 표적·장부 → 탈출.
- `episode-touch.json`: 심문·은닉 → 맨홀·하수도 → 2층 창문 → 기절한 표적 처치·장부 → 창문 탈출.
- `episode-diner.json`: 앞치마·약 → 식사·화장실 → 경비 심문·변장·사물함 은닉 → 직원 출입문·계단 → 표적·장부 → 탈출.
- 위 경로는 AI를 유지한 고정 시간 간격 검사다. 진행 조건·열쇠를 지급하거나 NPC를 없애서 완주하지 않는다. 선택 위치를 직접 놓는 부품 검사는 `*-controlled`로 구분한다.
- `systems-pc.json`, `systems-touch.json`: 실제 후보 목록·입력 처리기로 화단 진입, 방향 탈출, 기존 웅크림 은신, 진열대 소지품, 약 사용·화장실 도착, 카드 훔치기/문, CCTV 녹화/삭제, NPC 문 통과, 순찰로, 건물 전원, 간판을 검사한다.
- `prop-pixels.json`: 약·앞치마가 진열대 위에 실제로 그려지는지 확인한다. 열린 문 너머 인물도 검사한다. 포즈 변경 뒤 스키닝을 두 프레임 반영하고 화면과 같은 sRGB로 읽는다. 단순히 visible 값만 확인하지 않는다.
- `pixels.json`: PC/세로 화면 여섯 위치의 주인공과 주변 바닥, 역투영·확대·실제 핀치.
- `projection.json`: 실제 마우스/터치 인물 주시와 전술 지도 전환·복귀.
- `startup.json`: 지연된 자산 로딩과 재시작 두 번에서 등록 인물 수와 장면 인물 수가 일치한다. v134에서도 중복 인물은 재현되지 않았으며 이를 이번 버전의 성능 개선 근거로 주장하지 않는다.
- `native-portrait.json`: 실제 브라우저 프레임과 활성 AI로 화단 출입·기본 버튼의 앞치마→약 선택·식사 사용·화장실 접근을 녹화해 검토했다. 별도 프로토타입도 브라우저 프레임에서 붙잡기부터 장부·탈출까지 완주했다(`native-prototype.json`).
- 원본 2D의 식사/진열대, 수납함·기절/처치 입력, 간판·덕트, 건물 수색·변장/층 판정을 회귀 검사했다. 전체 군중 식사 검사도 통과했다.

브라우저 프레임 녹화는 클라우드 소프트웨어 GPU, 세로 DPR .75/그림자 512 및 PC DPR .65/그림자 384 환경이다. 실제 iPhone 성능 측정은 아니다. 고정 좌표 전후 사진과 실제 이동 검수를 구분해 보관한다.

## 범위

에피소드는 클럽 한 블록의 잠입·대인 행동·은신·도구·보안·환경 암살·목표/재시도 연결에 집중한다. 기존 캠페인의 도시 운전·차량 교통·파벌전, 대규모 군중, 옥상/전선 이동망은 이 지도에 배치하지 않았다. 기존 2D 캠페인은 그대로 남아 있으며 Cloudflare의 동결된 테스트 배포를 덮어쓰지 않는다.
