# 금성회 간부 추적

작전 목표는 금성회 지휘망을 해체하고 최종 명령자를 찾는 것이다. 기존 선형 에피소드의 난이도와 기술 준비 흐름을 유지한다. 조직도는 의뢰 선택 화면이 아니다.

- 하부 간부를 처치하면 다음 보고선의 역할·가명이 드러난다. 문서와 암호표를 대조하면 실명, 거점, 동선이 확인된다. 9명과 19개 단서가 연결된다.
- 까마귀는 연락 총책이다. 그의 처치와 원본 장부를 함께 확보해야 의장의 실명과 마지막 장소가 밝혀진다. 새 마지막 에피소드 `n1`은 보존된 `m3` 사저의 지형·층·잠입 기회를 활용하며 별도 의장 캐스트와 결말을 갖는다. 기존 `m3`은 그대로 남긴다.
- 기절은 처치 단서를 주지 않는다. 회수한 기록만으로도 처치 목표가 생략되지 않는다. 단서는 기술 포인트를 추가 지급하지 않는다.
- 조직도는 시작 화면, 브리핑, 일시정지, 에피소드 완료 후 기술 준비에서 열 수 있다. 플레이 중에는 시간을 멈추며, 닫을 때 원래 화면과 일시정지 상태를 복원한다. 터치 HUD에 버튼을 추가하지 않는다.

## 저장과 기존 진행

`yahaeng.case.v1`은 알려진 단서 ID만 저장한다. 기본 조회는 저장하지 않으며 저장소를 쓸 수 없을 때는 세션 메모리를 사용한다. 기존 실제 완료 기록에서는 해당 단서를 추론한다. 건너뛴 입문 에피소드에 가짜 완료·사망·포인트를 생성하지 않는다.

재도전해도 플레이어가 얻은 지식은 남는다. 적의 생사와 탈출 조건은 현재 세계 및 실제 완료 기록에서 계산하므로 체크포인트 이전으로 돌아가면 되살아난 적을 처치 완료로 표시하지 않는다. 과거 버전에서 본편에 진입하여 생략된 하부 간부는 ‘보고선 차단’으로 구분한다. 처음부터 시작하면 단서도 초기화한다. v205 최종 완료자는 추가된 마지막 에피소드부터 이어간다.

현재 구현 범위는 단서를 따라 간부 계층을 밝히는 추적 시스템이다. 적의 무작위 승진·부활·복수나 플레이어 전술을 학습하는 AI는 구현하지 않았다.

## 검증

- `tests/rev/t_caseboard.py`: 미공개 신원 숨김, 기절/처치, 암호 대조, 총책+장부 조합, 체크포인트, 기존 저장, 마지막 목표, 모달 입력·포커스와 4개 화면 크기. 세계/기록을 설정하는 통제된 회귀 검사다.
- `tests/tutorial/officer_hunt_live.py`: 새 저장과 입문 의뢰 선택 후 실제 AI·시간·체력·키보드/터치 입력으로 후방 접근 → 암살 → 단서 → 조직도 → 탈출 → 기술 준비 → 다음 의뢰를 검증한다. 물리 iOS 실기기 검증은 아니다.
- `tests/rev/t_mission_flow.py`: NPC 시뮬레이션을 정지한 기능 검사로 새 마지막 에피소드까지 세 배치·두 입력 방식의 실제 이동, 문, 계단, 카드, 회수, 길게 누르기 처치, 탈출을 확인한다. 마지막 에피소드 전체를 실제 AI 상태로 완주했다는 의미는 아니다.
