# v134 — 사라지는 시설과 건물 절개 수정

사용자 영상/사진에서 확인한 문제는 소품의 존재를 시야 검사에 묶은 표시 조건과, 지면 칸별로 건물 픽셀을 버리는 가림 처리다. 고정 좌표에서 진행·픽셀 검사를 통과해도 이동할 때 생기는 톱니 모양 경계와 소품 전환을 잡지 못했다.

## 변경

- 화단·수거함·사물함·맨홀·환기구 모델은 같은 층에서 유지한다. 시야와 거리는 상호작용 안내·실내 인물 발견에 사용한다. 물체의 존재를 짧은 중심점 시선 검사로 켰다 끄지 않는다.
- 지붕/벽의 지면 칸별 셰이더 절개와 상층 투명 페이드를 제거한다. 건물에 접근하면 지붕과 사용하지 않는 상층을 통째로 걷고, 해당 층의 벽은 방향별 구획으로 낮춘다. 진입/복원 거리를 달리해 경계 근처에서 앞뒤로 걸어도 건물이 반복 전환되지 않는다.
- 낮춘 벽은 같은 높이의 마감 면으로 끝낸다. 구획별 공유 재질과 정적 묶음으로 벽마다 별도 그리기를 하지 않는다. 문과 창문 경첩 애니메이션은 유지한다.
- 적이 보이는데 시야 표시만 별도의 플레이어 시야 조건으로 사라지던 중복 조건을 제거한다. 앞쪽 시야는 실제 벽 광선·조명·자세별 감지 계산으로 검사하고, AI의 전방위 근접 인지 범위도 함께 표시한다. 달리는 중 가까운 뒤쪽으로 접근할 때의 감지도 포함한다.
- 시야 표시 후 이전 층 계산 상태를 복원한다. 문·조명·자세 변화와 방향 전환 시 시야를 갱신한다. 카메라 각도·모바일 버튼 배치는 유지한다.

## 검수 자료

`stability-v134/index.html`: v133/v134 같은 좌표의 모바일 화면 비교. 정지 사진은 이동 영상으로 설명하지 않는다.

- `moving.json`: PC/세로 모바일 각각 161개 이동 위치, 접근 전환 1회, 경계 왕복에서 전환 없음, 같은 층 소품 유지·다른 층 차단, 가까운 뒤쪽 걷기/달리기 감지 표시, 시야 계산 후 층 유지.
- `pixels.json`: 두 화면 크기 × 여섯 위치의 실제 주인공 픽셀 및 주변 이동 바닥 검사, 확대·모바일 핀치/이동 해제.
- `sight.json`: 벽/닫힌 문 차단, 문을 열었을 때 시야 확장, 웅크린 자세의 실제 감지와 표시 표본 비교, 다른 층 차단.
- `episode-pc.json`, `episode-touch.json`: 활성 AI를 유지하고 실제 입력 처리기를 사용해 PC 번호판·계단 경로 / 터치 맨홀·창문 경로의 표적 처치·장부·탈출 및 메뉴 복귀 검사. 고정 시뮬레이션 스텝이며 기기 FPS 검사가 아니다.

- `systems.json`, `passages.json`: PC/터치 창문·벽 시야, 은닉 용량/출입·시체/혈흔, 모바일 맨홀·덕트 이동/손 조작/기습·복귀 회귀 검사.
- `native.json` 및 `native-*.webp`: 별도 프로토타입을 실제 브라우저 프레임과 활성 AI로 붙잡기·기절·변장·시체 운반/은닉·수거함 출입·사물함·계단·장부·탈출까지 완주했다. 시뮬레이션 시간을 직접 증가시키지 않았다. 클라우드 소프트웨어 GPU에서 DPR .65 / 그림자 384로 녹화했으므로 실제 휴대폰 속도·화질의 검증 자료로 사용하지 않는다. 입력 드라이버의 대기 시간은 프레임 개수가 아닌 실제 게임 경과 시간으로 계산하며, 이동 도착 허용 범위는 13px다.

실제 iPhone Safari의 성능을 측정한 작업은 아니다. 기존 2D Cloudflare 배포는 유지한다.
