# 화면 글 점검 — 의뢰 「VIP」(m2)

외부 피드백 "설명을 글보다 다른 형태로 전달하라(섀도우 택틱스 참고)"와 "'이걸 어떻게 깨?'를 환경으로 풀 때 쾌감"을 확인하려고, 실제 게임(v267)에서 화면에 뜨는 글을 장면별로 모았다.

## 수집 방법

- 빌드한 `build/preview_city.html`에서 m2를 진행하며 21개 장면에서 글을 모았다.
  - 장면: 브리핑, 시작 무전, 이동, 클럽 앞, 경비 등 뒤, 동시 암살, 시체 운반·숨기기, 변장, 가로등, 옥상 간판, 간판 낙하, 의심, 발각, 일시정지, 결과
- 두 종류를 따로 기록했다.
  - **HUD 글**: 화면에 보이는 HTML 글
  - **게임 화면 글**: 캔버스의 `fillText`·`strokeText`를 가로채 기록했다
- 진행을 위해 녹화 때처럼 일부를 조정했다(시작 위치, 경비 방향, CCTV 제거). 처음 한 번만 뜨는 도움말(`hint`)은 이 수집에 거의 걸리지 않았다.
- 코드 전체의 규모: `toast(` 호출 184곳, `hint('` 호출 66곳, 짧은 대사(barks) 21줄, 대화 32줄, 시작 무전 10줄.

## 분류

- **없앰**: 다른 표시와 겹치거나, 플레이어가 스스로 알아낼 답을 미리 알려 주는 글
- **그림으로**: 정보는 필요하지만 아이콘·색·바닥 표시·소리로 바꿀 수 있는 글
- **남김**: 조작에 꼭 필요하거나, 세계 안에서 들리는 정보(엿듣는 대사)

## 같은 해법을 네 번 알려 주는 경우: 간판 낙하

간판으로 표적을 처치하는 해법이 아래 네 층으로 겹쳐 안내된다.

1. 경비 대사 "간판 아래는 비워 둬. 고정대 수리 아직 안 됐어." — 단서(26번, 남김)
2. 무전 "실장이 간판 아래에 오면 고정 풀기" — 해법(8번)
3. 옥상의 "표적이 낙하 범위 안에 있음" — 타이밍(23번)
4. 행동 안내 "X 간판 고정 풀기" — 입력(18번)

1번만으로도 플레이어가 "간판을 쓰면 되겠다"를 떠올릴 수 있다. 2번과 3번이 있으면 그 생각을 하기 전에 답이 나온다. 피드백의 "이걸 어떻게 깨?" 쾌감을 살리려면 1번과 4번만 남기고, 2번은 선택 안내로, 3번은 바닥 표시로 바꾸는 것을 권한다.

## 권하는 순서

1. 겹치는 글부터 없앤다(4, 7, 10, 24번). 정보 손실이 없다.
2. 해법을 알려 주는 무전(8번)을 선택 안내로 바꾸고, 간판 낙하에서 효과를 확인한다.
3. 상태·구역·층(2, 3, 5, 16번)을 색과 배지로 바꾼다.
4. 건물 이름·목표 안내(15, 17번)를 지도로 옮긴다.
5. 의뢰 이름을 하나로 맞춘다(1번: "의뢰 01" / "에피소드 04").
