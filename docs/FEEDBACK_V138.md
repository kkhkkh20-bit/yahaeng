# v138 — 소품·기절·조명 목격·은신처 수색

## 이번 피드백 반영

### 소품 그림과 통로

클럽 왼쪽의 작은 소품(`m2`의 21,16)은 기존 `O` 장애물이었다. 예전 픽셀 소품과 밝은 바닥이 함께 보여 수거함처럼 보였고, 바로 아래 대형 수거함과 함께 좁은 길을 막았다. 이 소품은 제거해 통로를 열었다. 다른 `O` 소품은 잎·테두리·몸통이 있는 화분으로 그린다. 장애물 바닥을 주변 바닥 재질에서 고르도록 바꿔, 아스팔트·맨땅 위 소품 아래에 밝은 보도 한 칸이 생기는 문제도 고쳤다. 화분의 밑동과 수거함 본체는 실제 장애물로 보이고, 빈 통로는 지나갈 수 있다.

### 기절 소리와 발견 신고 구분

목 조르기·붙잡은 적 기절의 기본 소리 반경은 12px로 줄였다. 바닥·음악의 기존 보정은 적용된다. 완전한 무음은 아니며, 반격이나 충돌의 큰 소리와 실제 범행·쓰러진 사람 목격은 계속 반응한다.

동료를 발견하는 순간의 수색 배정은 별도 문제였다. 발견자는 900px 안의 다른 층 경비까지 즉시 수색에 배정할 수 있었다. 이제 발견자 본인과 같은 높이·층에서 외침이 전달되는 거리(260px, 벽 감쇠 적용)에 있는 경비가 즉시 합류한다. 발견자는 “여기 쓰러진 사람이 있어!” / “시체다!”라고 말해 이유를 알린다. 기존 무전·실종 점검은 별도로 작동한다. 소리를 들었다는 이유만으로 플레이어의 얼굴이나 현재 위치를 지급하지 않는다.

### 불 끄는 장면을 목격하면 항의하고 복구

불이 꺼지기 직전의 밝기와 실제 시야로 목격 여부를 판단한다. 목격한 경비는 “불 끄지 마세요. 다시 켭니다.”라고 말하고 스위치로 간다. 스위치 앞에서 짧게 작업한 뒤 켜므로 멀리서 켜는 마법 동작은 없다. 보지 못한 경비에게 같은 항의를 지급하지 않는다. 실제 시체 조사·추격은 우선한다.

### 수색 중 은신처 확인

발견 현장 주변의 수거함·사물함·옷장·맨홀·풀숲을 수색 지점에 포함하고, 일반 방보다 먼저 확인하게 했다. 고체인 사물함 칸 자체로 길을 찾다가 포기하던 문제를 고쳐, 실제로 접근 가능한 앞/주변 칸까지 이동한다. 수납함은 열어 확인하고, 확인 시간이 끝난 뒤에야 숨겨진 사람·플레이어를 발견한다. 풀숲의 숨긴 몸도 같은 층·높이에서 확인한다. 새 몸을 넣으면 이전 발견 표시를 초기화한다.

수색 위치 선정에는 숨은 플레이어의 현재 위치를 쓰지 않는다. 실제 현장 주변에 있는 장소들을 예약해 확인하며, 빈 곳도 조사한다.

### 붙잡기 → 기절 → 운반 → 숨기기

붙잡힌 적과 함께 들어가서 기절시키던 일반 행동을 제거했다. 가까이에 수납함이 있어도 먼저 바깥에서 기절시킨다. 이후 별도 운반 행동으로 들어 올리고, 수거함의 넣기 동작을 실행한다. 짧게 기절·같은 버튼을 길게 눌러 처치하는 기존 입력 구분을 유지하며, 다른 버튼이나 앱 전환으로 처치가 이어지지 않는지 확인했다.

풀숲에는 추가 문제가 있었다. 운반한 몸을 캐릭터 앞 26px에 내려놓으면, 캐릭터가 풀숲 한가운데 있어도 몸은 경계 밖에 놓일 수 있었다. 이제 실제 풀숲을 대상으로 “화단에 숨기기”를 선택하고, 몸을 안쪽으로 내려놓은 뒤 은닉 상태가 된다. 기절 상태를 유지하며 플레이어가 자동으로 함께 숨지는 않는다.

## 화면 검수에서 추가로 고친 것

- 조명 항의·은신처 확인 대사가 행동 집중 표시 때문에 숨겨졌다. 중요한 행동 설명 대사는 그때도 표시하되 층·거리·시야 조건은 유지한다. 실제 화면의 말풍선 목록에서 텍스트가 그려지는지 검사했다.
- 사물함 수색 화면을 그릴 때 지역 함수 `onGround`를 잘못 참조한 오류를 캡처 검사에서 발견해 같은 층·높이 조건으로 교체했다. 최종 PC·터치 캡처는 오류 없이 통과했다.
- 이미 설치한 Impeccable의 실제 브라우저 검사를 붙잡기 화면에도 적용했다. 두 버튼의 “길게 처치”가 10px로 작다는 지적을 11px로 수정했고, 같은 상태의 재검사는 빈 결과다. [수정 전](feedback-v138/impeccable-before.json) · [수정 후](feedback-v138/impeccable-after.json).
- Ponytail REVIEW 지침으로 소리→발견→수색, 입력→기절→운반→수납의 호출과 상태 흐름을 검토했다. 새 외부 도구나 상시 훅은 설치하지 않았다. [기존 도구 설치 범위](EXTERNAL_TOOLS_V137.md).

## 검증

- `tests/rev/t_feedback_v138.py`: 실제 맵을 이용한 통제 배치. 통로, 소품 바닥, 조용한 기절, 현장 신고의 거리·층, 조명 목격/비목격과 실제 복구 위치, 고체 사물함 접근·개방·발견, 풀숲 안쪽 내려놓기를 PC/터치에서 통과했다. 클럽 음악이 있는 검사 지점의 기절 소리 반경은 보정 후 7.2px다. 조명 목격 뒤 이동 포함 약 3.21초에 복구했고, 그때 스위치와 거리는 33.9px였다.

- `t_rendezvous`, `t_dialogue_proportions`: 의뢰 내선 통화와 기존 대화 크기/입력을 통과했다.
