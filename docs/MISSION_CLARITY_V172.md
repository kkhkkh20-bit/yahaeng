# v172 — 첫 의뢰의 목적과 대상을 알아보는 흐름

첫 의뢰의 실제 완료 조건은 **클럽 실장 처치 + 사무동 장부 회수 후 이탈**이다. 이전에는 첫 목표 화살표가 서쪽 경비를 가리키고 제압·변장·은닉을 차례로 요구해, 경비가 의뢰 대상처럼 보였다. v172는 경비 처리를 선택 수단으로 돌리고 실제 사람과 물건의 정체를 먼저 보여 준다.

- 브리핑에서 제거할 사람과 가져올 물건을 두 장의 시각 카드로 구분한다. 실장은 게임에서 사용하는 초상과 실제 복장 시트를 함께 보여 준다. 장부는 게임의 금고 그림과 문서 그림으로 표시한다. 알려진 건물과 지도 표식을 함께 제공한다.
- 플레이 중에는 표적의 얼굴·이름과 회수 물품이 기존 Graphite 목표 패널 안에 남는다. 실제 처치·회수 때 각 항목이 완료된다. 표적을 기절시키면 `기절 · 처치 미완료`로 표시한다. 경비를 쓰러뜨려도 필수 목표 수가 늘거나 완료되지 않는다.
- 첫 자동 목표는 장부의 단서가 있는 공개 야시장이다. 살아 있는 경비, 옷, 방치된 몸은 자동 의뢰 목표를 가로채지 않는다. 직접 운반을 선택했을 때의 은신처 안내, 변장·은닉 보상 없는 체크포인트, 수동 목표와 선택한 단서는 유지한다.
- 현장에서 직접 본 표적에게 이름과 `처치 대상`을 표시하고, 장부의 첫 화살표는 `장부 단서`라고 표시한다. 표적의 미관측 이동 위치를 공개하지 않는다.
- 다른 본편 의뢰도 같은 대상 카드와 완료 표시를 사용한다. 무전기와 현금 가방은 각각 구분되는 그림을 쓴다. 기존 모바일 조작부에는 버튼을 추가하지 않는다.

## 검증

새 저장 파일에서 실제 의뢰 선택 및 PC 키보드 / 모바일 CDP 터치 입력으로 다음을 확인했다. 이동과 AI 시간을 재현 가능하게 전진시킨 자동 브라우저 플레이이며, 사람이 실시간으로 플레이한 검증을 뜻하지 않는다.

1. 서쪽 경비를 포함한 누구도 제압하지 않고 공개 야시장에서 번호 획득: PC·모바일 모두 체력 3, 변장 없음, 몸 0, 발각 0, 경보 0. 기본 복장으로 걸어서 단서에 도달했다.
2. 기존 선택 경로로 첫 의뢰 완주: 순찰 기절 → 변장·은닉 → 번호 → 카메라 전선 두 곳 → 금고·장부 → 내선으로 실장 유인 → 처치 → 서쪽 탈출. PC·모바일 모두 체력 3, 기술 학습·다트 사용 없음. 모바일은 발각 1·경보 1이 있어 무발각 완주로 보고하지 않는다.
3. 1280×800 PC, 390×844·320×740 모바일 세로, 844×390 모바일 가로에서 브리핑 그림, 대상 패널, 펼치기·접기와 문구 넘침을 검사했다. 제어된 기절/처치/물품 회수/체크포인트 사례는 별도 상태 실험으로 구분했다.
4. 기존 `t_review_fixes`와 `t_continuity_review`의 “풀숲 안내가 첫 목표” 기대값을 새로운 목적에 맞게 수정했다. 지도 외곽 픽셀 검사는 등록된 월드 글자 영역을 제외한다. 글자의 의도된 어두운 바탕을 누락된 배경으로 오인했던 경우이며, 외곽 그림의 밝기나 충돌을 바꾸지 않았다.

추가 진단용 `t_play_clarity.py`는 이번 변경 전의 공개 v171에서도 같은 `attack/grab choices not together` 조건에서 실패한다. 이번 수정은 근접 공격·붙잡기 범위를 변경하지 않았다. 이 진단을 통과했다고 보고하지 않는다.

이 변경은 초보자가 목표와 수단을 혼동할 구조를 줄인 것이다. 처음 접하는 사람이 설명 없이 임무를 이해하는지는 별도 사용자 관찰로 확인해야 한다.
