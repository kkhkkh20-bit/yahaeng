# 기절·처치·붙잡기 기준 · v84

| 조작 | 짧게 누름 | 길게 누름 |
| --- | --- | --- |
| 공격 · Z / Space | 표적·조직원·주민 모두 기절 | 기절시킨 뒤 같은 입력을 1초 계속 누르면 처치 |
| 화단·수거함으로 끌고 가기 · X / E | 끌고 가서 기절 | 같은 입력을 계속 누르면 처치 |
| 붙잡기 · C / Q | 살아 있는 적을 붙잡음 | 계속 붙잡으며 처치로 바뀌지 않음 |
| 다트 · V / F | 1초 전에 떼면 기절 다트 | 1초 이상 누른 뒤 떼면 처치 다트 |
| 기절한 사람에게 공격 | 처치하지 않음 | 1초 누른 뒤 처치 |
| 끌어내려 추락시키기·밀기·치명적 함정 | 작동하지 않음 | 1초 누른 뒤 실행 |

모바일도 동일한 버튼 의미를 따른다. 조명·CCTV를 다트로 깨는 행동에는 사람 처치 규칙을 적용하지 않는다. 이동 중 발생한 사고나 NPC의 공격을 제압 입력으로 바꾸지는 않는다.

## 표시

- 적 위에 공격과 붙잡기를 별도로 표시한다. PC는 현재 입력 묶음의 Z/C 또는 Space/Q를 함께 표시한다.
- 화단·수거함 행동은 `끌고 기절`, 아래에 `길게: 처치`로 표시한다. PC 키 안내와 대상 안내도 같은 의미를 쓴다.
- 진행 고리는 실제로 누른 공격 또는 행동 버튼에 표시한다. 버튼 위치는 유지한다.
- 적이 열쇠를 가지고 있어도 열쇠 훔치기가 붙잡기를 가리지 않는다.

## 입력과 상태

처치 의도는 처음 선택한 대상과 실제 키·터치 입력에 연결한다. 손을 떼거나, 버튼 밖으로 나가거나, 입력이 취소되거나, 앱이 가려지면 길게 누르기가 취소된다. 다른 버튼으로 남은 시간을 채울 수 없다. 비동기 돌진·끌어당기기 중에도 같은 대상과 입력을 유지한다.

기절한 표적은 암살 완료로 계산하지 않는다. 기절 뒤 손을 뗐더라도 다시 다가가 길게 눌러 처치할 수 있다. 쓰러진 사람을 옮겼을 때는 몸의 실제 위치에서만 후속 처치를 할 수 있다.

`58_combat_intent.js`는 입력 출처·유지 시간·대상 잠금과 붙잡기 판정을 관리한다. `killGuard()`는 수동 제압 의도를 전달받아 기절로 처리하고, `updateKoHold()` 또는 사전에 완료한 길게 누르기가 실제 처치 시점을 결정한다. 다트는 발사 당시 의도를 투사체에 저장하므로 나중에 다른 키를 눌러도 결과가 바뀌지 않는다.

## 검증

`t_combat_policy.py`: 표적·조직원·주민, 화단·수거함, 중간 해제·다른 입력·앱 전환, 별도의 후속 처치, 두 사람 제압, 다트의 명중 결과, 붙잡기 유지, 치명적 함정의 취소를 검사한다. PC 두 키 묶음과 실제 모바일 터치로 공격·붙잡기·화단 행동도 실행한다. 열쇠를 가진 표적 위에 붙잡기 문구와 단축키가 보이는지, 모바일 버튼 위치와 진행 고리가 올바른지 확인한다.

기존 붙잡기·기절·매달리기·상호작용·계단·변장·세력·임무 회귀 검사도 실행했다. 구형 창문 테스트의 기대기 위치는 가변 지도에 남쪽 창문이 없을 때도 걸을 수 있는 외벽 앞을 선택하도록 보정했다.
