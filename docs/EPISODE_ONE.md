# 에피소드 01 — 마지막 정산

폐점한 백야 클럽. 회계책 송대건을 처치하고 원본 장부를 회수한 뒤 골목으로 이탈한다.

## 의도

사선 화면의 기존 구역을 실제 의뢰 하나로 묶는다. 새 기능의 숫자보다 같은 공간을 여러 방식으로 읽고 이용하는 데 집중한다. 필수 조건은 표적 처치와 장부 회수 두 가지다. 정보 획득 순서, 변장, 기절 인원, 특정 암살 방법은 강제하지 않는다. 제한 시간도 없다.

## 공간과 접근

| 공간 | 역할 | 선택 |
| --- | --- | --- |
| 서쪽 골목 | 안전한 출발, 문지기, 수거함과 화단 | 문지기 심문·변장, 휘파람 유인, 지나치기 |
| 1층 홀 | 직원의 마감 동선, 순찰, 인수인계 책상 | 메모에서 직원 출입문 비밀번호 확보 |
| 직원실·계단 | 홀과 분리된 출입 관리 구역 | 번호판 문, 같은 번호의 뒷문, 환풍구 우회 |
| 2층 정산실 | 장부 책상, 표적의 짧은 일과, 순찰·계단 경비 | 정면 잠입, 창문 진입, 대기 후 암살 |
| 맨홀·덕트 | 골목 안에서 이동·몸 숨기기·후방 진입 | 기존 이동·은신·기습 규칙을 그대로 이용 |
| 동·서 골목 | 경보 뒤 이탈 경로 선택 | 목표를 마친 뒤 가까운 출구 이용 |

## 행동의 결과

- 짧은 공격은 기절. 처치는 기존 길게 누르기 규칙을 따른다. 기절한 표적만으로 의뢰가 완료되지 않는다.
- 장부부터 가져가거나 표적부터 처리할 수 있다. 둘 중 하나만 마쳤을 때는 출구가 열리지 않는다.
- 메모는 책상 위에, 번호판은 실제 문틀 양쪽에 있다. 지형·문·창문의 시야 판정과 그림을 함께 쓴다.
- 사체 발견과 무전 응답 누락은 기존 건물 수색으로 이어진다. 목격하지 않은 범행 때문에 플레이어 신원을 자동 확정하지 않는다.
- 표적은 정산 책상 → 뒤쪽 창가 → 서류장 옆을 오간다. 긴 이벤트를 기다릴 필요 없이 동선 어디서든 접근할 수 있다.

## 범위

신규 진입점 `build/episode-one/`. 기존 `club-study` 시제품과 2D 캠페인, Cloudflare 2D 테스트 파일은 유지한다. 기존 CC0 캐릭터·재질을 재사용하며 표적은 정장 모델로 구분한다.

검수 항목: PC·모바일 완주, 잘못된 번호 거부, 책상 메모의 실제 도달 가능성, 창문·덕트 우회, 두 목표의 완료 순서, 기절/처치 구분, 재시작과 소개 화면 복귀.

## 빌드와 검수

`python3 build.py --episode --club --itch`로 생성한다. 에피소드 검수는 3D 전용 빌드가 필요하므로 일반 2D 자동 묶음과 분리했다.

```
python3 tests/episode/play_episode.py staff
python3 tests/episode/play_episode.py window
python3 tests/episode/play_episode.py duct
python3 tests/episode/check_rules.py
python3 tests/episode/verify_deployment.py
```

`staff`는 PC의 심문·변장·수납·책상 메모·번호판·계단·처치·장부·탈출을 검증한다. `window`는 터치 버튼으로 맨홀 이동·창문 진입·기절·길게 처치·장부·창문 하강·탈출을 검증한다. `duct`는 번호판 문을 열지 않고 덕트로 직원실에 들어간다. 경비 AI를 없애거나 목표 완료를 주입하지 않는다. 각 경로 후 재시작, 실패, 소개 화면 복귀도 확인한다.

별도 통제 상황에서 독립적인 책상 단서 획득, 기절/처치와 두 목표 조건, 위층 수색이 아래층 문을 잘못 여는 문제를 검사했다. 기존 수납함 4종 × 복장 4종의 출입·손 조작, PC/터치 처치 길게 누르기, 기존 사선 구역 완주도 회귀 검사했다.

완주 검사는 시뮬레이션 시간을 빠르게 진행한다. 기록된 약 1분은 공략을 아는 자동 입력의 게임 시간이며, 신규 플레이어의 예상 분량이나 실물 휴대폰 FPS를 뜻하지 않는다. 공개 주소 검수는 실제 브라우저 프레임에서 키보드·터치 이동, 출발과 메뉴 복귀, 게시 파일 해시를 별도로 확인한다.
