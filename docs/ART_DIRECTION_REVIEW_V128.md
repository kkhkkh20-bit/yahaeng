# 야행 — 클럽 뒷골목 사선 화면 시제품

2026-11-01 · v128. [플레이](https://kkhkkh20-bit.github.io/yahaeng/club-study/) · [화면 비교와 플레이 영상](https://kkhkkh20-bit.github.io/yahaeng/club-v128/)

## 이번에 실제로 바꾼 것

클럽 뒷골목, 1층 홀, 2층 사무실, 연결 계단을 하나의 고정 사선 카메라로 다시 구성했다. 주인공·가구·건물이 같은 좌표와 조명을 공유하며, 문·수납함이 실제 경첩을 중심으로 열린다. 주인공을 가리는 외벽과 지붕은 작은 영역을 걷어내고, 실내 전면 벽은 높이를 낮춰 이동 공간을 보여준다. 위층은 뒤로 물려 지붕이 골목 전체를 덮는 비중을 줄였다.

여성 주인공의 기존 모델·복장 조합을 유지했다. 배경만 다른 각도의 그림으로 바꾸면 손과 발의 접점이 다시 어긋나므로, 이 대표 구역에는 Three.js의 실시간 3D 표시를 사용했다. 플레이어가 보는 시점은 고정된 사선이며, 기존 2D 타일 충돌·AI·전투·상호작용 규칙을 그대로 연결했다. 전체 캠페인의 엔진 전환이나 프리렌더 배경 교체를 완료했다는 뜻은 아니다.

- 같은 1m 타일, 층고 2.8m, 계단 높이 약 16cm를 기준으로 골목·벽·가구를 배치했다.
- 콘크리트·벽돌·목재·금속의 채도와 무늬 대비를 맞추고, 하나의 주광과 실내 조명 아래 그림자를 공유한다.
- 인물은 8방향 64px 그림을 돌려 쓰는 대신 기존 CC0 골격을 연속 재생한다. 평상시 서기, 걷기, 붙잡기, 제압, 운반, 출입 자세를 연결한다.
- 문 손잡이·수납함 뚜껑·책상 물건에 손을 뻗는 보정을 적용했다. 운반은 몸을 어깨에 가로로 얹는 자세로 조정했다.
- 책상과 바 테이블이 은신처로 잘못 분류되어 시각적으로 사라지는 문제를 이 구역에서 막았다. 지원하는 사물함·옷장·수거함만 숨을 곳으로 쓴다.
- 화면 방향의 이동 입력을 월드 방향으로 역변환한다. 적 선택도 실제 사선 화면의 인물 위치를 사용한다. 선택한 적·의심 중인 적에게만 시야를 표시하고, 조준 선은 사선 좌표로 그린다.
- 중앙 은신 표시, 오른쪽 미니맵, 모바일 행동 버튼 위치, 짧게 기절·길게 처치 규칙을 유지했다. 모바일 발 위치는 화면 높이 약 62%로 둔다.

## 레퍼런스와 연결되는 기준

[Shadow Tactics 공식 화면](https://store.steampowered.com/app/418240/)과 [Commandos 2 공식 화면](https://store.steampowered.com/app/6830/)을 비교했던 [v127 진단](ART_DIRECTION_REVIEW_V127.md)을 구현 출발점으로 삼았다.

| 참고한 기준 | 시제품의 적용 | 아직 부족한 점 |
| --- | --- | --- |
| 하나의 시점에서 이어지는 벽·지면·인물 | 같은 카메라로 장면 전체를 표시 | 주변 건물 형태와 창문 반복이 단순하다 |
| 계단·문·난간으로 높이와 이동 경로를 설명 | 실제 층고와 계단 경로, 경첩 문, 실내 벽 절개 | 작은 모바일 화면에서 층 경계의 읽힘을 더 검증해야 한다 |
| 어두운 배경 속 인물과 중요한 통로의 구분 | 공통 그림자, 실내 빛, 발 표식, 가림 제거 | 소프트웨어 브라우저 외 실제 휴대폰의 밝기·성능 검증이 남는다 |
| 물체의 용도와 행동이 맞물리는 장면 | 책상 장부, 수납함 전체 문, 운반과 보관 연결 | 여러 방향의 손 접점과 좁은 공간의 두 사람 동작은 추가 다듬기가 필요하다 |

출시작과 같은 세부 묘사·미술 완성도에 도달한 결과는 아니다. 무료 캐릭터의 각진 형태, 단순한 건물 군집, 적은 생활 소품이 여전히 보인다. 이번 목표는 다른 화풍의 물체를 계속 추가하는 대신, 한 구역에서 시점·축척·재질·접촉의 기준을 세우는 것이다.

추가 검수에서는 처치된 몸의 `guardId`도 원래 인물에 연결해 표시 누락을 막았고, 시체 들기·내려놓기는 기존 `bodyAnim` 시간과 같은 연속 자세를 쓰도록 연결했다. 기절·처치 양쪽 몸, 들기 중간 높이 변화, 내려놓은 뒤 몸이 남는지를 별도로 검사했다.

## 자산과 재현

- 캐릭터: 기존 저장소의 Quaternius **Ultimate Modular Women / Characters**, CC0. 새 이미지 생성이나 AI 이미지 합성은 사용하지 않았다. [원본 출처](../tools/prerender/characters/sources.json), [배포 파일·해시·라이선스](../src/club-study/assets/sources.json).
- 건물·문·창문·가구·재질: 이 시제품용 코드로 제작. 외부 건물 이미지나 참고작의 미술 자산을 가져오지 않았다.
- 렌더러: Three.js 0.168.0, MIT. 라이브러리와 라이선스를 함께 배포한다. CDN 런타임 의존성은 없다.
- `python3 tools/build_club_study.py`로 기존 원본 GLB에서 필요한 애니메이션만 포장하고 공유 자세 코드를 생성한다. `python3 build.py --club --itch`로 기존 게임과 별도 시제품을 만든다.
- 추가 모델 약 7MB와 라이브러리 약 1MB가 별도 구역에서 로드된다. 기존 게임 번들도 포함하므로 이를 최종 다운로드 최적화로 보지 않는다. 일반 게임에서는 이 모델과 Three.js를 요청하지 않는다.

상세 실행 결과는 [검증 기록](CLUB_STUDY_VALIDATION_V128.md)에 남겼다.

## 검증 범위

실제 브라우저에서 활성 AI와 정상 입력 경로를 사용해 뒷골목 접근 → 붙잡기·심문 → 기절 → 변장 → 운반·수거함 보관 → 수거함 출입 → 문 열기·실내 진입 → 사물함 출입 → 계단 → 사무실 경비 제압 → 책상 장부 회수 → 계단 귀환 → 탈출을 검사한다. 자동 경로 검사는 시간을 전진시키므로 실제 기기의 프레임 속도 측정과 구별한다. 별도 프레임 재생 녹화에서는 클라우드 소프트웨어 GPU 때문에 DPR .65, 그림자 맵 384로 낮춰 검사한다. 일반 플레이 구역의 기본 화질을 촬영한 스크린샷과 이 녹화의 화질·속도를 구분해야 한다.

화면 비교의 ‘이전’은 **새 시제품과 동일한 배치를 기존 렌더러로 표시한 장면**이다. v127에 이 맵이 이미 있었다는 뜻이 아니다. 기존 출시 화면과 완전히 같은 장소의 전후 비교로 표현하지 않는다.

일반 캠페인은 기존 표시 방식을 유지한다. 실시간 장면의 장치 호환성과 실제 손맛, 작은 화면에서의 발견 가능성을 확인한 후 다른 구역으로 넓혀야 한다. 이 한 구역의 짧은 회수 목표를 전체 게임의 최종 난이도로 제안하지 않는다.

이번 새 렌더러의 검수 경로는 골목·문·수납함·실내 계단·책상 회수다. 창문을 통한 층간 출입, 옥상 특수 동작과 전체 캠페인으로의 확장은 후속 이식·검수가 필요하다.
