# v104 · 시야·휘파람·선택 표시·성능

2026-10-31 (한국 시간)

VIP 출입구 옆에서 바로 바깥에 있는 적이 휘파람을 무시하는 상황을 재현했다. 직선이 문 옆 벽에 닿으면 소리를 크게 줄여 계산했으며, 클럽 음악도 범위를 줄였다. 이제 휘파람은 가까운 열린 출입구를 돌아 전달된다. 음악 속에서도 가까운 거리는 들리고, 소리가 난 실제 위치로 확인하러 간다. 무작위 위치 오차로 문 옆 벽을 목적지로 삼는 문제도 줄였다. 지붕/층 정보는 휘파람 발생 위치를 사용한다.

일반 경비의 밝은 곳 기본 범위를 250→520px로 늘렸다. 보통 난이도 배율을 적용하면 약 5.6→11.7칸이다. 일반 시야각은 약 57→69도로 넓혔다. 어두운 곳의 기본 범위 95px, 벽 가림, 층·높이와 변장 허가 판정은 유지한다. 밝은 곳에서 멀리 웅크렸다고 항상 안 보이지는 않는다. 시야 원뿔도 새 거리와 밝기에 맞춰 계산한다.

기절자 선택은 원래 적의 좌표 대신 현재 시체 그림의 경계를 사용한다. 방향·쓰러지는 프레임·복장별 경계를 자산에 기록하며, 몸을 옮긴 뒤에도 빨간 선택 테두리가 따라간다. 같은 대상의 중복 테두리는 줄였다. 정예 여부를 나타내던 고정 빨간 표식은 중립색으로 바꾸고, 소리를 들었다는 파동은 노란색으로 표시한다. 실제 발각과 길게 눌러 처치하는 구분은 유지한다.

[모바일·PC 전후 화면](ai-v104/index.html): 휘파람은 실제 VIP 문 옆 상태에서 실행했고, 기절자 이동 후 선택을 확인했다. 밝기 비교는 같은 위치에 고정한 조명을 사용한 거리 테스트다.

## 성능 변경

- 시야 표시의 고정 조명 계산을 재사용하고, 이동하는 손전등 후보를 공간 격자에서 찾는다. 기존 모든 인물을 훑는 방식과 밝기 값이 같은지 검사한다.
- 닫힌 건물의 지붕에 완전히 가려지는 인물·시체, 화면 밖 시체는 그리지 않는다. 끌어내기·날아가는 시체의 진행 중인 동작은 유지한다. 지붕이 열리고 닫히는 전환 중에는 기존 표현을 유지한다. AI 갱신은 계속한다.
- 화면에 닿을 수 없는 시야는 계산하지 않는다. 경비 시야는 더 자세하게, 평상시 주민의 옅은 시야는 적은 표본으로 그린다. 실제 발견 판정의 빈도는 낮추지 않는다.
- 플레이 중 프레임이 밀리거나 idle callback이 시간 초과로 실행된 경우, 선택적인 인물 준비 작업은 뒤로 미룬다. 시간 초과를 여유 시간으로 간주해 강제 색칠하던 멈칫을 줄인다.
- 뛰기·사망 등의 동작은 가까이 다가갈 때 준비한다. 모든 인물의 불필요한 동작을 시작 시 미리 칠하던 캔버스 캐시를 줄인다. 조각 폭을 줄이는 실험은 전체 프레임 시간의 개선이 일정하지 않아 기존 폭을 유지했다.
- 낮은 프레임이 지속되면 2초 구간 중앙값 두 번을 확인해 렌더 해상도를 조절한다. 60fps 설정에서는 48fps 아래의 지속적 저하에 대응한다. 한 번의 느린 프레임은 해상도를 낮추지 않는다.

브라우저 측정 자료는 아래 파일에 기록한다. 캐시 크기는 칠한 인물 캔버스의 픽셀 합이며 전체 프로세스 메모리가 아니다. 서버의 Chromium 측정으로, 실제 휴대전화 FPS나 발열을 검증한 결과는 아니다.

## 검증

- `t_ai_feedback.py`: VIP 벽 옆 휘파람 청취 후 실제 이동, 재사용 대기, 열린 공간의 밝은/어두운 10칸 탐지, 밝은 곳 웅크림, 벽 가림, 조명 끄기 후 원뿔 갱신, 소리의 벽 차단, 손전등 격자와 기존 전수 계산의 값 비교, 옮긴 기절자의 실제 테두리 그리기, 지속 저하에 대한 해상도 대응, 부족한 idle 시간에 작업을 양보하는지, 닫힌 지붕 아래 인물 그리기를 생략하고 전환 중에는 유지하는지 검사. 모바일·PC 통과.
- `t_play_clarity.py`, `t_building_search.py`: 변장·실제 관측·다층 수색 검사 통과.
- `t_combat_policy.py`: 짧게 기절·길게 처치, 실제 키보드·터치 입력 검사 통과.
- `t_characters.py`, `t_controls_readability.py`, `t_interaction_flow.py`: 인물·팔레트·화면 가림·대상 선택·실내 접근 판정 검사 통과.

## 브라우저 측정

같은 시드·카메라·정지 배치로 인물 준비가 끝난 뒤, 전후 페이지를 번갈아 30프레임씩 4회 측정한 중앙값이다. 원본: [perf.json](ai-v104/perf.json).

| 화면 | 전체 그리기 ms 전→후 | 시야 구간 ms 전→후 | 인물 캔버스 MiB 전→후 |
|---|---:|---:|---:|
| 390px 거리 | 11.87→12.37 | 0.35→0.25 | 155.6→109.6 |
| 390px VIP | 15.03→15.39 | 1.82→1.63 | 160.2→116.2 |
| 1280px 거리 | 9.28→9.15 | 0.36→0.32 | 155.6→109.6 |
| 1280px VIP | 10.23→10.48 | 1.02→0.98 | 160.2→116.2 |

인물 캔버스 캐시는 약 27~30% 감소했다. 전체 그리기 시간은 일부 표본에서 소폭 늘기도 한다. 따라서 고정 해상도에서 전체 FPS가 개선됐다고 결론내리지 않는다. 지속적인 저프레임에서는 선택적 준비 작업을 미루고 렌더 해상도를 조절한다.

## 저성능 조건의 실제 루프

Chromium CPU 4배 감속, 390×844·DPR 2에서 VIP 실내의 실제 애니메이션 루프를 각 8초 실행했다. 2초 구간의 프레임 중앙값으로, 마지막 구간은 이전 약 100ms(10fps)→수정 약 66.7ms(15fps), 수정본 DPR은 1.5였다. 시작 2초는 수정본도 느렸으며 60fps를 달성한 결과는 아니다. 선택적 준비 작업 양보와 자동 해상도 대응이 동작함을 확인하는 부하 테스트다. 실제 휴대전화 측정과 구분한다. 원본: [runtime-perf.json](ai-v104/runtime-perf.json).
