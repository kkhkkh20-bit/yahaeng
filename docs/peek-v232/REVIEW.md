# v232 출입구·어둠·근접 시야 검수

## 발견한 원인과 수정

- **옥상에 내려갈 계단실이 없음:** 개정된 에피소드 3은 예전 구운 건물 데이터가 없었다. 이동 로직은 존재하지만, 구매 외관의 옥상 소품·계단실과 실제 옥상문 연결 데이터가 비어 있었다. 구운 모델 유무와 관계없이 실제 계단에서 계단실과 문 앞 도착점을 생성한다. 계단실 충돌·문·층 이동·목표 안내가 같은 좌표를 사용한다. 자동으로 문 안에 걸어 들어가는 기존 계단 조작에 맞춰 안내도 고쳤다. 예전 저장이 새 계단실 내부에 있으면 체력·복장·목표·조명 상태를 유지한 채 해당 계단실 문 앞으로 복구한다.
- **스위치가 떠 있음:** p0/e2의 수동 지정 스위치 5개는 바닥 칸 중심에 있었다. 같은 방의 접근 가능한 벽으로 실제 제어 위치를 옮기고 회로 식별자는 보존했다. 모든 공개 에피소드의 스위치를 벽 접면의 작은 픽셀 플레이트로 표현한다. 실제 제어점과 표시 지점의 차이는 5px이며 벽 두께 안에서 연결된다. 등 중심을 누르는 동작이나 떠 있는 3D 스위치 이미지는 구매 아트 경로에서 사용하지 않는다.
- **창문·문이 판처럼 튀어나옴:** 측면 창문의 기울어진 정면 그림을 제거했다. 측면과 북쪽 외벽은 벽 두께 안의 어두운 창 구멍/문 프로파일로 그린다. 남쪽 정면은 구매 외관의 실제 정면 개구부를 유지한다. 실내 문은 기존 경첩 동작을 유지하면서 사무실·주거 재질의 색을 구분한다. 옥상문의 불필요하게 돌출된 문짝 그림도 없앴다.
- **보는 창과 조작하는 창이 다름:** 양쪽 창문이 동시에 닿는 좁은 골목에서는 미리 보이는 쪽과 행동 대상이 달라질 수 있었다. 문·창문 선택과 근접 시야가 거리·바라보는 방향의 같은 기준을 사용한다. 실제 접근 거리와 통과 판정은 유지한다.

## 가까이에서만 안쪽이 보이는 방식

새 버튼 없이 창문이나 열린 문에 가까이 다가가면 해당 개구부 너머의 같은 층 일부가 짧게 드러난다. 좁은 골목에서는 바라보는 쪽을 우선한다. 출입구에서 벗어나거나 닫힌 문 뒤에서는 보이지 않으며, 옥상이나 다른 층에서 아래층을 투시하지 않는다.

보이는 범위는 창 폭과 실제 내부 벽에 막히는 광선으로 제한한다. 전체 지붕을 반투명하게 만들지 않는다. 지붕 아래 실제로 그려진 바닥·가구·인물·조명을 작은 재사용 버퍼에 담아 제한된 부분만 부드럽게 합성한다. 어두운 방은 그대로 어둡고, 다른 방이나 벽 뒤의 인물은 드러내지 않는다. 회로·적 시야·소음·탐지·아이템·스킬 판정은 이 표시 때문에 바뀌지 않는다.

## 어둠

기존의 넓고 푸른 중간 밝기 대신 미조명 구간을 더 검게 낮췄다. 조명 중심의 밝기는 보존해 밝은 곳과 그림자의 차이를 키웠고, 닫힌 지붕도 낮은 톤으로 정돈했다. 실제 가림 다각형·방별 회로·손전등 판정은 유지한다. 주인공의 어두운 곳 윤곽과 기존 위치 표시를 남겨 이동을 읽을 수 있도록 했다. 어둡다고 무조건 안전하다는 별도 상태는 추가하지 않는다.

## 검증

- 공개 9개 에피소드: 조명 201개의 제어 위치 검사(공유 스위치 중복 포함), 36개 옥상 계단 연결, 계단실 충돌·문 앞 도착점·이전 저장 복구 검사.
- PC/터치: 양쪽 골목의 방향 선택, 실제 조작 대상 일치, 같은 층 한정, 내부 벽 가림, 거리 이탈, 닫힌 문 차단, 작은 화면 버퍼, 새 저장 반복 시 스위치 위치 안정성을 검사한다.
- 기존 옥상 경로 검사: 판자 연결과 건너뛰기, 실제 키보드/터치로 계단실 140개 접근 사례. 문 열림/닫힘과 문턱의 인물 그리기 순서도 검사한다.
- PC 첫 에피소드와 모바일 세 번째 에피소드의 기존 경로를 실제 입력으로 완주했다. 세 번째 에피소드는 실제 새 계단실 안으로 걸어 들어가 내려가는 과정을 포함한다. 별도의 모바일 입력 재플레이에서 획득한 복장으로 접근해 스위치 소등·점등과 창가 근접·이탈을 확인한다.
- PC/모바일에서 골목, 옥상문, 스위치, 창가 시야, 소등된 실내를 비교 캡처한다. 이는 개발자가 경로를 알고 진행하는 회귀 검증이며 신규 사용자 사용성 조사와 구분한다.

새 에셋 구매나 엔진 변경은 없으며 구매 팩 원본은 계속 비공개로 유지한다.
