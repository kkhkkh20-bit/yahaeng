# 은신 출입과 낙하

## v112 · 손으로 여닫는 출입구와 매달린 간판

2026-10-31 · [실제 동작 영상](access-v112/index.html)

맨홀·수거함·사물함·옷장에 손을 뻗어 손잡이와 덮개를 여닫는 단계를 추가했다. 기본 인물과 여성 주인공 네 복장의 8방향 자세를 추가로 구웠다. 프레임마다 저장한 양손 좌표를 실제 손잡이 좌표와 연결한다. 몸이 안으로 들어가는 동안에는 입구 위에 남은 팔과 손이 덮개를 당긴다. 나올 때는 몸을 꺼낸 다음 돌아서서 닫고 조작을 돌려준다. 몸이 입구를 통과하는 기존 속도는 유지하고 손 조작 시간 0.6초를 앞뒤에 따로 둔다.

환풍구를 바닥 창살·낮은 외벽 환기구·돌출된 옥상 환기함으로 구분한다. 현재 여섯 의뢰에 배치된 15곳은 바닥형과 옥상형이다. 바닥에는 통로와 사다리, 옥상에는 측면 통풍살과 돌출된 뚜껑을 그린다. 맨홀에서 지하로 내려가거나 지하에서 올라올 때도 이동 동작을 거친다. 출입은 벽·층·거리와 실제 걸어갈 경로를 확인하고, 나올 공간이 막혔으면 내부 상태를 유지한다. 환풍구를 빠져나올 때는 덮개를 닫으며 원래 옥상 높이를 복원한다.

낙하 장치 21곳에 실제 지지대·사슬·간판 또는 실외기를 그린다. 해당 높이에서 고정 장치에 가까이 다가간 뒤 같은 행동 버튼을 1초간 유지해야 풀 수 있다. 손으로 고정을 푸는 동안 간판은 그대로 매달려 있고, 해제 후 낙하하며 지면 충돌 때만 판정한다. 처음 누를 때 위치가 아니라 충돌 순간 아래에 있는 지상의 적을 처리한다. 다른 층과 아이는 대상에서 제외하며, 결과와 잔해는 한 번만 생성한다. 연결된 기존 외벽 간판은 중복되지 않게 숨긴다.

새 시설도 v111의 야간 마스크·조명·낮은 채도를 사용한다. 작은 그림 버퍼를 공유하며 입력 안내는 기존 버튼 위치를 유지하고 `들어가기`·`나오기`로 짧게 표시한다.

검증은 Chromium의 PC·모바일 입력 환경에서 수행했다. `t_access_fixtures.py`는 환풍구 15곳 왕복, 맨홀 21곳 지하 왕복, 낙하 장치 21곳 충돌, 복장·방향·열기/닫기별 손 접촉 128개를 검사한다. 출입 표시 좌표의 최대 변화는 0.005초당 3.83px이었다. `t_access_inputs.py`는 실제 키보드·모바일 버튼의 짧은 입력 취소, 길게 누르기, 손 조작, 지연 충돌과 환풍구 왕복을 확인한다. 기존 은신 206곳 왕복과 네 방향 209개 접근, 수용 인원·시체 보관·붙잡은 적과 함께 들어가기, 낙하 1,039곳, 서서 뛰어내리기 398곳, 매달림 처치 23곳, 창문 왕복·위층 연결·조명 처리 검사도 통과했다. 인물 17,512프레임에 잘림 없는 여백이 유지된다. 확장 검사에서 이전 배포본에도 남아 있는 여섯 실패는 [검증 기록](ACCESS_FIXTURES_QA.md)에 구분했다.

## v111 · 물체 색감과 조명 일치

2026-10-31 · [전후 화면](tone-v111/index.html)

새 물체의 색과 동작 중 조명 처리가 기존 배경과 달랐다. 사물함은 밝은 청회색, 옷장은 노란 갈색, 수거함은 선명한 녹색과 표식, 맨홀은 밝은 테두리를 사용했다. 재질색을 기존 소품에 가까운 회색·회갈색·회녹색으로 조정했다.

더 큰 문제는 동작 중 시설이 야간 조명 효과 뒤에 그려졌던 점이다. 같은 닫힌 문이어도 행동을 시작하면 조명을 받지 않은 원색으로 밝아졌다. 움직이는 뚜껑·문·앞판에 이미 계산된 같은 층의 야간 마스크와 조명색을 적용한다. 위층의 색조와 높이에 따른 안개도 반영한다. 캐릭터와 조작 표시는 기존 가독성을 유지한다.

예를 들어 모바일 사물함 표면 표본은 이전에 정지 상태 RGB 약 60/68/70에서 동작 상태 129/144/158로 바뀌었다. 수정 후 같은 촬영 조건에서는 55/62/59와 53/56/56으로 가까워졌다. 모든 이미지는 같은 맵·위치·조명·동작 단계에서 비교했다.

`tests/rev/t_fixture_lighting.py`에서 기본 화면·잉크 화면 각각 PC와 모바일 기기 배율 2 조건으로 검사했다. 의뢰 2개의 물체·층 10개 조합을 조명 켜짐/꺼짐 상태에서 비교했고, 정지와 동작 상태의 표면 표본 차이는 RGB 채널당 최대 5.8이었다. 2층·3층의 조명과 색조도 확인했다. 조명을 켜면 시설이 실제로 밝아진다.

동작 중 시설 한 곳에 작은 캔버스 두 장을 공유한다. 화면 전체를 다시 조명 처리하지 않으며, 예열 후 100회 반복 그리기에서 추가 캔버스 할당은 0이었다. 기존 출입·수용 인원·보관·끌어들이기·문 전체 열림·낙하 연결 검사도 통과했다. 화면 검증은 Chromium에서 수행했다.

## v110 · 멈춤 없는 출입과 문 전체 열림

2026-10-31 · [전후 동작 영상](motion-v110/index.html)

v109에는 넘는 동작과 내려가는 동작 사이에서 속도가 다시 0이 되는 구간이 남아 있었다. 수거함과 맨홀의 표시 좌표를 한 곡선으로 연결하고, 입구 아래 최종 표시 위치를 72px에서 40px로 줄였다. 혼자 출입하는 본 동작은 1.45초에서 수거함 1.05초·다른 시설 1.1초로 단축했다. 입구까지 걷는 시간은 별도이며, 몸이 가려진 다음 뚜껑을 닫는 순서를 유지한다.

사물함과 옷장은 기존 긴 몸체의 아래쪽에만 문을 덧그렸던 구조를 없앴다. 닫힌 상태부터 열린 상태까지 같은 전체 몸체를 사용한다. 사물함은 통풍구와 손잡이가 달린 문 한 장, 옷장은 양쪽 문 전체가 경첩을 중심으로 열린다. 출입할 때는 서서 걸으며, 몸 전체가 문 안에 들어간 뒤 닫힌다. 수용 인원과 보관 결과는 기존 기준을 따른다.

매달린 손을 놓는 낙하는 위로 솟는 효과와 느린 출발을 없애고, 한 층은 0.26초·두 층은 0.3초에 착지한다. 적을 난간에서 끌어내릴 때도 잡아당기기의 끝 속도가 낙하의 시작 속도로 이어진다. 처치에는 같은 공격 버튼을 1초간 유지해야 하며, 주인공은 난간에 남는다.

`tests/rev/t_container_presentation.py`에서 몸이 입구를 넘은 뒤 다시 멈추지 않는지, 닫히기 전에 실제 캐릭터 픽셀이 입구 아래로 가려지는지, 사물함·옷장 세 규격의 상단·중단·하단이 모두 열리는지 검사했다. 닫힌 배경 그림과 움직이는 몸체의 픽셀도 일치한다. 적의 당김·낙하 연결 속도와 주인공의 연속된 낙하 좌표를 확인했다. PC·모바일 화면에서 통과했다.

기존 은신 206곳, 매달린 자리의 착지 1,039곳, 서서 뛰어내리기 398곳, 보관·끌고 들어가기, 네 방향의 매달림 처치와 실제 키보드·터치의 길게 누르기 검사도 통과했다. 영상은 Chromium 모바일 화면 기록이며 실물 휴대폰 검증은 포함하지 않는다.

## v109 · 은신 출입과 낙하

2026-10-31 · [동작 영상](motion-v109/index.html)

숨을 때 중간 자세에서 몸의 기준 좌표를 다시 잡고, 앞판에 가리는 시점도 갑자기 바뀌어 머리와 몸이 잘리는 문제가 있었다. 같은 좌표 곡선과 연속된 자세를 출입 양쪽에 사용한다. 수거함은 발이 테두리 위로 올라온 뒤 앞판 안으로 넘어가며, 몸이 입구 아래로 내려간 다음 뚜껑을 닫는다. 나올 때는 역순으로 움직인다.

옷장·사물함은 문을 열고 닫는 동안 실제 입구로 몸이 드나든다. 침대는 옆으로 접근해 몸을 낮추고 침대 밑으로 들어간다. 가구의 가로·세로 크기를 보관하고, 예전 저장 데이터는 현재 가구 배치에서 크기를 복원한다. 벽 너머 접근을 막고, 가구 중심 한 칸이 아닌 전체 외곽에서 유효한 출입 공간을 찾는다. 화단도 같은 출입 흐름을 사용한다. 운반 대상과 붙잡은 적의 보관 결과는 접촉한 다음 한 번만 적용한다.

매달림 공격은 바로 위의 같은 층·같은 옥상에 있고 팔이 닿는 적에게만 가능하다. 공격 버튼에 `끌어내리기`를 표시한다. 같은 입력을 1초간 유지한 뒤, 한 손으로 난간을 잡고 다른 손으로 적을 끌어내린다. 적은 잡힘 → 가장자리 밖으로 이동 → 낙하 → 착지 순서로 움직이며, 착지했을 때 추락사와 임무 결과를 적용한다. 주인공은 난간에 남는다. 다른 층·반대편·막힌 지점의 적을 잡거나 착지할 곳 없이 떨어뜨리지 않는다. 공격 중에 평지 전용 “등 뒤로 접근” 안내를 표시하지 않는다.

주인공의 내려가기 또한 실제로 매달린 자세에서 손을 놓은 위치를 이어받는다. 서서 뛰어내리는 동작은 별도 자세를 사용한다. 출발 층은 착지할 때까지 유지하고, 착지 프레임에 달리는 자세가 끼어들지 않게 한다. 아래층 착지 후보에서 벽면·옥상 장애물을 제외한다. 기존 버튼과 HUD 위치는 유지한다.

새 자세는 기존 모델의 뼈를 보간해 8방향 스프라이트로 구웠다. 런타임 3D 렌더러는 추가하지 않는다. 새 동작만 시트 뒤에 추가하거나 다시 구울 수 있도록 프리렌더 도구를 확장했다. 보간 뒤 회전값을 완전히 초기화해 특정 방향에서 자세가 뒤집히는 문제도 방지한다.

검증은 Chromium PC·모바일 화면과 실제 키보드·터치 이벤트로 수행했다. 실물 휴대폰 검증은 포함하지 않는다. `t_storage_motion.py`는 6개 의뢰의 모든 은신 유형, 연속된 표시 좌표, 보관과 붙잡고 들어가기, 착지와 매달림 처치 결과, 지지하는 손의 접점을 확인한다. `t_ledge_inputs.py`는 방향키·WASD·터치의 짧은 입력 취소, 길게 누르기 진행, 낙하 전 생존, 착지 결과 1회 적용, 주인공의 매달림 유지를 확인한다. 기존 은신·기절/처치·사물 상호작용·표적 보관·창문 및 스프라이트 여백 검사도 실행했다.

최종 결과:

- PC·모바일 각각 은신시설 206곳 출입: 수거함 37, 맨홀 21, 옷장 34, 침대 28, 사물함 19, 화단 67. 유형별 운반 보관·붙잡고 들어가기 6종씩 통과.
- PC·모바일 각각 매달린 자리에서 내려오기 1,039곳, 서서 아래층으로 뛰어내리기 398곳, 네 방향의 매달림 처치 23건 통과.
- 복장 4종과 기본형의 지지하는 손 접점 520개 및 시작·끝 자세 일치 통과. 전체 스프라이트 16,152프레임이 비어 있지 않고 프레임 가장자리에 잘리지 않는지 확인.
- 기존 수거함·맨홀 209회 왕복씩, 창문 500곳·위층 창문 72회·매달림 접점 128개씩 PC·모바일 통과.
- 실제 입력의 두 PC 키 배치·터치, 기절/처치 정책, 사물 조작과 환풍구 왕복, 표적 운반·보관 검사 통과.
