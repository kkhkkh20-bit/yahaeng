# v141 · 2D 런타임 구조와 로딩 정리

사용자 요청: 전체 구조를 리팩토링하고, 무거운 초기 로딩과 불필요한 코드·에셋을 정리한다. 기준은 v140 (`0dfea17`)의 동결된 HTML이다. 외부 라이브러리 설치는 추가하지 않았다.

## 실제 변경

- `src/modules.json`에서 95개 런타임 파일의 순서와 소유 그룹을 명시한다. 누락·중복·경로 이탈은 빌드 오류로 처리한다. 파일명 정렬에 숨어 있던 의존 순서를 드러냈다.
- `15_graphics.js`, `40_guard_ai.js`, `60_interact.js`, `70_render.js`를 `graphics/`, `ai/`, `interaction/`, `render/`로 나눴다. 가장 긴 파일은 1,555줄에서 720줄로 줄었다. 기존 선언의 실행 순서를 보존했고, 부팅 검사 API도 `devtools/`로 분리했다.
- `runtime/sprite_sources.js`는 의뢰와 독립된 이미지 소유권 서비스다. 같은 이미지는 한 번만 요청한다. 현재 의뢰에서 쓰는 체형만 먼저 읽고, 변장·근접 동작은 필요할 때 준비한다. 의뢰 전환 시 원본·색칠 캐시의 보존 목록을 함께 정리한다. 이전 의뢰의 늦은 다운로드는 캐시에 되살아나지 않는다. 실패한 요청은 간격을 두고 재시도한다.
- 쓰지 않는 녹음 배경음 4개 약 1.19MB(base64)를 원본 목록과 생성기, 배포 입력에서 제거했다. 현재 WebAudio 배경음과 효과음은 유지한다. 도달하지 않는 그리기 함수, 사용하지 않는 버튼 도우미, 비활성 경고음 함수·프레임 스캔을 제거했다.
- `tools/buildlib/`에 모듈·에셋 정규화·배포 참조 그래프를 분리했다. 패키징은 현재 HTML과 JS/CSS, press 페이지의 참조를 따라간 뒤 도달하지 않는 assets 파일만 제거한다. 누락되거나 폴더 밖으로 나가는 참조가 있으면 삭제 전에 실패한다. 정리 작업이 다음 빌드의 버전 메타데이터를 바꾸지 않도록 만들었다.
- 메뉴 뒤 월드의 매 프레임 시뮬레이션·그리기를 중단했다. 타이틀/의뢰 목록은 UI만 대기하고, 시작하면 정상 프레임 루프를 재개한다. 메뉴로 돌아와도 게임 시간이 흐르지 않는다.
- 실제 통과 경로가 없는 m2 창문 두 곳은 봉쇄 창문으로 구분한다. 사용할 수 없는 창문 통과 동작을 만들지 않는다. 열 수 있는 문은 영구 장애물로 간주하지 않는다.

현재 런타임은 오프라인 단일 HTML을 위해 하나의 IIFE 범위를 공유한다. import/export로 모든 상태를 격리한 ES 모듈 전체 전환은 아니다. 이번 변경은 책임별 소스 분리, 명시적 구성, 이미지 수명 관리와 빌드 안전성에 초점을 두었다. [구조 안내](ARCHITECTURE.md).

## 전후 측정

| 항목 | v140 | v141 | 감소 |
| --- | ---: | ---: | ---: |
| 배포 assets 폴더 | 20.04 MB | 7.67 MB | 61.7% |
| 현재 버전의 참조 에셋 | 8.86 MB | 7.67 MB | 13.5% |
| 초기 메뉴 디코딩 픽셀 추정 | 334.95 MB | 104.14 MB | 68.9% |
| 의뢰 m2 디코딩 픽셀 추정 | 356.08 MB | 233.40 MB | 34.5% |
| 의뢰 전환 후 디코딩 픽셀 추정 | 353.34 MB | 122.53 MB | 65.3% |

배포 폴더 감소에는 과거에 쌓인 스크립트 제거가 포함된다. 그 파일들이 모두 매번 다운로드됐다는 뜻은 아니다. 현재 버전 전체 참조 에셋의 감소는 약 13.5%다. 이 값은 초기 화면에서 실제 요청하는 부분집합과 구별한다. 현재 게임에 필요한 캐릭터 모양·동작을 삭제한 결과도 아니다.

별도의 `tests/integration/profile_loading.py`로 실제 프레임 루프를 켜고 캐시 없는 로컬 HTTP 메뉴 로딩도 검사했다. 문서 본문을 제외한 리소스 응답 본문은 7.54→3.85MB, 요청은 121→102개였다. 기존 메뉴는 250ms 동안 월드를 16번 그렸고, 새 메뉴는 0번 그렸다. 시작 후 키보드 이동과 메뉴 복귀 뒤 정지도 검사했다. CDN 압축·캐시·실제 통신망 속도 측정은 아니다. [원본 로딩 결과](refactor-v141/loading.json).

`tests/integration/profile_refactor.py`는 같은 난수·뷰포트·m2 위치·정상적인 자경대 복장을 사용한다. 메뉴, m2, tB→m6→tB 전환을 비교하고, 소유권 측정 시 명시적 GC를 요청한다. 디코딩 픽셀 바이트는 살아 있는 이미지의 너비×높이×4 합계이며, GPU 복사·캔버스·오디오를 모두 포함한 실제 RAM 측정이 아니다.

따로 돌린 60회 그리기 표본의 중앙값은 PC 10.9→10.7ms, 터치 크기 7.0→6.4ms였다. 한 환경의 통제 표본이며 실물 휴대폰 FPS 향상으로 일반화하지 않는다. 주된 확인 결과는 초기·의뢰 전환 뒤 디코딩 이미지의 감소다. [원본 수치](refactor-v141/metrics.json) · [화면과 결과](refactor-v141/index.html).

## 검증

- 빌드 파이프라인 6개: 모든 모듈의 등록, 중복/누락 거부, 중첩·press 참조 보존, 누락/경로 이탈 시 삭제 방지, 재패키징 결과 안정성, 효과음/아틀라스 보존.
- 독립 이미지 서비스: 중복 요청 통합, 늦게 완료된 구 의뢰 다운로드 폐기, 소유권 해제, 오류 후 재시도 간격·복구.
- 실제 PC/터치 브라우저: 초기 필수 캐릭터 시트 두 장만 준비, 의뢰 전환 후 불필요한 모션 해제, 새 변장 모델의 지연 로딩과 표시, 막힌 창문 비활성화.
- 핵심 회귀 37개와 도달 검사 통과, 튜토리얼 실제 입력 완주, 동작 트랙과 인물 표현, 공개 배포 파일·실제 입력 검사. 실행 기록은 [검수 폴더](refactor-v141/index.html)와 배포 기록에 보관한다.

옛 검사 중에는 이전 버전에서도 실패하는 제품 규칙이 남아 있었다. 즉시 문 열기, 옛 공터 컨테이너·사다리, 1개 건물만 적용하던 높이 시안, 살아 있는 적을 넣으며 기절시키기, 첫 처치마다 무전하기 등의 기대를 현재 규칙으로 정리했다. 의심/신원 전파 검사는 실제 목격과 전달 완료를 구분한다. 벽 너머 공격 검사는 실제로 닫힌 문과 첫 접촉 프레임을 사용하며, 시간이 지난 뒤 정상적으로 우회해 접근하는 AI를 오류로 취급하지 않는다.

원본 그림을 다시 렌더링하거나 새로운 에셋 팩을 다운로드하지 않았다. 캐릭터·건물·동작 시트의 원본은 유지하며 현재 빌드가 요구하는 파일만 배포한다. 글꼴 문자 수집은 새 하위 모듈까지 재귀적으로 읽도록 고쳤다.
