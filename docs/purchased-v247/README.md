# v247 — 구매 픽셀 조립과 실제 접근점

새 팩을 구매하거나 외부 캐릭터 팩을 다운로드하지 않았다. 이미 소유한 GuttyKreum Dotonbori City v3·Office Interior v3의 픽셀로 가구 변형과 기능 오브젝트를 조립했다. 원본 전체 ZIP/타일 시트는 공개하지 않는다. 정확한 조각 좌표·원본 해시·조립 방식은 [통합 manifest](manifest.json), [fixtures.json](../../src/art/purchased-details/fixtures.json), [props.json](../../src/art/purchased-props/props.json)에 기록했다.

## 픽셀·재료 규칙

- 기준은 원본 32px → 월드 48px, 1.5배 nearest-neighbour다. 새 소품 atlas는 원본 팔레트를 변경하지 않았다. 어두워짐과 조명색은 기존 게임의 런타임 조명에서 처리한다.
- 가구 소품은 이 밀도로 들어가지 않으면 기존 렌더러를 유지한다. 대상 칸에 맞추려고 그림 전체를 찌그러뜨리지 않는다.
- 큰 상자와 다리는 평평한 면을 이어 필요한 크기를 만든다. 모서리·테이프·손잡이 두께는 보존한다. 완성된 상자 묶음을 다시 겹쳐 타워로 만들지 않는다.
- 여닫는 문과 수납장 문짝에는 기존 경첩 평면과 열림 각도를 적용한다. 이 기하 투영에 따른 폭 변화는 일반 소품의 크기 조절과 구분한다.
- 일본어 간판을 다시 넣지 않는다. 기존 한국어 간판과 게임 상태 표시는 유지한다.

## 실제 연결한 그림

|---|---|---|

| 책장 3색 | 원본 전체 자르기 | 기존 `shelf/shelfS`, 높이 1칸. 물류 선반·보안 모니터·명시적 가구 제외. |

| 옥상 연결 다리 | 구매 덱·프레임·난간 재료 | 가로/세로 연결과 양 끝 지붕 겹침. 물리 경로·같은 높이 인물의 앞 난간 가림 검증은 별도 조립 검사에서 다룬다. |

책상·의자·바닥·외벽 등 v246까지의 구매 에셋 경로도 계속 사용한다. 대응 원본이 확인되지 않은 소파·침대·금고·냉장고·CCTV·수거함 등은 용도가 맞는 기존 그림을 유지한다. 의자를 늘여 소파로 쓰는 식의 대체는 하지 않는다. 원본 팩의 완성된 거리를 그대로 이식한 작업도 아니다.

## 접근 공간 보정

27맵의 침대 이외 가구 은신처 115개를 조사했다. 이전에는 23개가 문 중심에서 수평 24px 치우쳤고, 5개는 기존 접근 경로도 없었다. 중앙 접근 기준으로 막힌 곳은 6개였다.

- `cabinetFrontStand`는 전면 중앙의 안전점, 경로 연결점, 실제 작업점을 반환한다. 안전 접근은 몸 반경 14px, 마지막 18px 접근은 몸 proxy 10px와 실제 발 접지 `P.y+13` 반경 6px로 검사한다. 자신의 수납장에 기대는 몸 proxy만 허용하고, 실제 발과 다른 벽·가구는 통과시키지 않는다.
- m4 숙소 금고를 `(8,19)`에서 `(6,19)`로 옮겨 양문 앞을 비웠다. 계약서 접근점도 같은 금고를 따라간다.
- m5 수납장을 외벽 창 바로 위 `(13,9)`에서 `(13,8)`로 옮겼다.
- 자동 계단구멍 후보는 수납장 전면 칸을 침범하지 않는다. 도시 시제품의 작은 집 4곳은 보조 구멍 대신 기존 기본 계단을 유지한다. 옛 저장에 남던 8칸의 잘못된 난간도 지정된 방 패치로 복구한다.

캐릭터·사체·아이템·체력·인벤토리를 초기화해서 배치 문제를 해결하지 않는다. m4의 수집하지 않은 계약서만 새 금고로 이전하며, 이미 획득한 상태는 유지한다. m5의 이전 수납장 좌표는 별도 매핑으로 이전한다.

## 캐릭터와의 관계

캐릭터는 구매 GuttyKreum 픽셀 작품으로 바뀐 것이 아니다. 기존 Quaternius 기반 3D 관절 모델을 오프라인에서 8방향 2D 스프라이트로 출력하는 경로가 남아 있다. 신규 복장도 이 경로의 실루엣과 팔레트를 조정한 것이다. 환경의 32px 픽셀 문법과 캐릭터의 64px 프레임이 완전히 같은 도트 품질이라고 주장하지 않는다. 일부 캐릭터 모션에는 1.8배 배율이 남아 있으며, 소품의 1.5배보다 단위 픽셀 확대 배율이 20% 크다. 두 경로가 정확히 같다고 표기하지 않는다. 기존 월드 크기·접지·조명을 유지하면서 복장 식별성을 점검한 범위다.

추가 캐릭터 팩을 검토할 때도 “64px 캔버스”라는 숫자만 맞추면 안 된다. 투명 여백을 제외한 실제 그림의 픽셀 높이와 게임에서의 키, 위에서 내려다보는 시점, 8방향의 정지·걷기·작업·전투 구성, 선 두께와 광원 방향을 현재 배경 옆에 나란히 놓고 비교해야 한다. 현재 복장 수가 늘어난 사실과 구매 배경의 도트 품질에 완전히 맞아진 주장은 구분한다.

## 검증 자료

- [소품 실제 렌더 검수표](prop-gallery.png): 15개 atlas 조각을 생산 렌더 함수로 그린 확대 검수이며 실제 플레이 화면은 아니다.
- `tests/rev/t_purchased_props.py`: 원본 자르기 일치, 상자 지지면/높이, 10개 가구 변형, 벽 설치, 1.5배 밀도, 월드 불변, 늦은 이미지 로드의 1회 캐시 갱신.
- `tests/rev/t_cabinet_approach.py --require-clear`: 27맵 115개 중앙 안전/작업 접근 및 몸·실제 발의 벽/가구 미관통 검사. 최종 preview에서 115/115 유효, 수평 치우침 0. [개별 좌표 결과](cabinet-clearance.json), [진단 그리드](cabinet-physical-audit.png)는 실제 게임 그림과 구분한다.
- `tests/rev/t_cabinet_checkpoint.py`: m4 계약서 획득 전/후, m5 숨은 플레이어/보관된 몸, 도시의 이전 난간 그리드 복구를 검사한다. 구체 결과는 [checkpoint.json](checkpoint.json)을 확인한다.

이 검사는 Chromium의 개발자 검수다. 실물 모바일 기기, 초보자 블라인드 플레이, 모든 에피소드 완주를 의미하지 않는다. 새 atlas 준비 전에는 기존 그림으로 동작하며 로드 후 층/미니맵 캐시를 갱신한다.


## 최종 조립과 동작 검수

수납장 외곽 높이를 흰색 60px·목재 62px로 줄였다. 기존 가구 footprint와 은신 용량은 유지하며 닫힌 문이 숨은 인물의 머리를 가린다. 두 문짝은 각각 반대편 경첩으로 열리고, 실제 팔 관절로 만든 17프레임의 여닫기 동작을 기본/넓은 문 및 주인공의 4복장에 연결했다. 작업 중에는 발과 몸통을 고정한다. 보관·꺼내기 이후에는 문을 닫고 안전한 전면 칸으로 걸어나온다.

- [PC 수납장 실제 입력](cabinet-pc.png), [터치 닫힘 정착](cabinet-touch.png): 제작 맵의 수납장 앞에 검수용으로 배치하고 경비·카메라를 격리한 뒤, 자연 RAF와 실제 키/터치로 출입했다. 전체 미션 완주 자료와 구분한다.
- [다리 검수](bridge.png): 가로 난간 높이 15px, 세로 다리의 덱만 회전. 앞 난간은 같은 높이 인물을 가리고 높은 인물은 난간 위에 보인다. 기본 캠페인의 6개 다리에서 PC/터치 양방향 총 24회 이동 경로 검사 통과.
- [복장 4종 검수표](wardrobes-npc-wardrobes.png): 후드·앞치마 작업복·여성 코트·여성 블레이저. 기존 역할·소속 색·명시된 간부/어린이 외형은 유지했다. 27맵에서 실제 배정과 출력 확인.
- `t_cabinet_actor_runtime.py`: 4복장 × 흰색/목재 × 기본/넓은 문 × 열기/닫기 × 17프레임, 544포즈와 미로드 fallback 확인. 연속 진행률의 완전 접촉 구간도 검사해 프레임 반올림이 손을 일찍 빼지 않도록 했다.
- `t_cabinet_body_recovery.py`: PC/터치 각각 92회 보관·꺼내기에서 문 닫힘, 안전 보행, 사체 보관 수, 정상 내려놓기를 확인했다.
- `t_cabinet_exit.py`: PC/터치 각각 수납장 54개에서 앞문 출입과 닫힘/보행 정착 확인.
- `t_hide_flow.py`, `t_access_fixtures.py`, `t_purchased_fixtures.py`, `t_roof_routes.py`, `t_stair_geometry.py`, `t_sprite_ownership.py`의 관련 회귀 검사 통과. 8개 빌드 검사, 20개 물리 상호작용 검사, 맵 도달 검사도 통과했다.
- `first_steps_live.py`: 실제 PC 키보드와 Chromium 터치로 첫 에피소드의 기절·변장·몸 숨기기·2층 서류 획득·탈출을 각각 완료했다. 두 경우 모두 체력 3, 발각 0. 이후 수납장 비율/손 동작 보정은 위 독립 출입 검사로 확인했다.

스크린샷 검수와 자동 검증에서 통과한 범위이며 실물 모바일 성능 평가나 모든 에피소드 완주를 뜻하지 않는다. 소품은 구매 팩의 픽셀 밀도를 유지했지만, 캐릭터의 모든 모션을 같은 원본 픽셀 그리드로 재제작한 것은 아니다.
