# 기존 시스템과 사선 구역 연결 검수 · v130

새 화면의 문제는 기존 규칙이 없어졌다기보다, `70_render.js`가 사선 화면으로 전환하며 기존 그리기 단계를 건너뛰는데 새 렌더러에 대응 표현이 빠졌다는 것이다. 화단은 충돌 지도와 숨기 규칙에 존재했지만 모델이 없었고, `S.peek`·창문 관찰도 새 화면의 지붕 처리와 연결되지 않았다.

| 기존 규칙·근거 | 사선 구역 적용 |
|---|---|
| `57_hide_flow.js`: 숨기·넣기·꺼내기·출입·용량 | 수거함 2개, 화단 2개, 사물함 2개, 옷장 1개. 같은 기존 판정을 사용. 가까운 시설만 작은 표시. 운반 중 수용량/가득 참 표시. 건물에 가려진 가까운 시설 주변을 열어 보여 줌. |
| `60_interact.js`: 붙잡기·끌어들여 기절·은신 기습 | 두 인물을 같은 포즈에 연결하고 수납 완료 뒤 숨김. 기존의 탭 기절/길게 처치 유지. 기습 중 뚜껑도 움직임. |
| `45_player.js`·`70_render.js`: 창문 관찰·문 상태·층 | `castRay/los`와 같은 충돌 지도를 0.25칸 간격으로 샘플링. 보이는 실내 위의 지붕·윗층만 카메라 투영 방향으로 잘라냄. NPC·시체·물품·시설도 같은 가시성 사용. 다른 층은 비공개. 건물 전체를 열어 주는 x-ray를 사용하지 않음. |
| `60_interact.js`: 1층 창문 넘기·2층 진입/하강 | 창틀 넘기 포즈 연결. 북쪽 외벽에 실제 지상 접근이 가능한 2층 창문 배치. 2D 스프라이트의 가짜 Y 높이 이동을 사선 구역에서는 실제 높이로 분리하여 AI 위치·카메라·착지 일치. 셋백 창문은 지상 출입으로 잘못 연결하지 않음. |
| `35_light_noise.js`·`60_interact.js`: 소리·던진 도구·핏자국 | 빈 캔·담배·다트 비행, 소음 파문, 핏자국 메시 연결. 기존 상태가 끝나거나 닦이면 표현도 제거. 청소는 낮은 손동작 사용. |
| `40_guard_ai.js`: 새 조직원 투입 | 동적으로 추가되는 조직원도 모델 생성. 시야 표시는 실제로 보이는 조직원만. |
| 붙잡기·심문·기절·처치·변장·운반·문·조명·계단·장부·탈출 | 기존 입력/AI/미션 상태 그대로 사용하며 대표 경로 재검증. |

현재 사선 지도는 대표 클럽 구역이다. 원본 캠페인의 맨홀·지하 통로, 환풍구 연결망, 전선, 간판 함정, 식사·화장실 기회는 이 구역에 배치되어 있지 않다. 이들의 전체 미션 지도·3D 연출까지 변환했다고 주장하지 않는다. 원본 2D 캠페인에는 그대로 남아 있다.

검증:

- `t_club_study.py`: AI 활성 PC/터치 입력으로 붙잡기 → 기절 → 변장 → 운반 → 넣기 → 다시 꺼내기/재은닉 → 혼자 출입 → 문 → 사물함 → 계단 → 2층 제압 → 장부 → 탈출. 체력 3, 처치 0으로 완료.
- `t_club_systems.py`: PC/모바일 창문 안 NPC 표시, 벽·닫힌 문·다른 층 차단, 문 열기, 은닉처 전부 렌더링, 화단 출입, 창문 통과 중 포즈, 빈 캔/휘파람, 핏자국 닦기, 가득 찬 수거함 진입 제한.
- `t_club_parity_moves.py`: 실제 붙잡기/행동 버튼으로 화단 끌어들이기와 은신 기습. 2층 창문 75개 시뮬레이션 샘플에서 높이 0→2.8m, 하강 후 같은 지상 지점 착지.
- 기존 창문 동작 회귀 `t_motion_windows.py`: PC/터치, 창문 496·층별 접촉 128. 기존 경비 시야 `t_club_sight.py`: 문 개폐, 웅크림, 층 구분 통과.

`docs/parity-v130/`에 실제 브라우저 화면과 결과를 보관한다. 가속 시뮬레이션은 규칙·경로 확인용이며 실제 휴대폰 FPS 측정이 아니다.
