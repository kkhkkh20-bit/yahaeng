# v107 · 동작과 창문

2026-10-31

이동·상호작용 도중 몸이 잘리거나 동작이 생략되어 보이는 부분과 창문 상태를 점검했다. [전후 화면과 동작 영상](motion-v107/index.html).

확인한 원인과 변경:

- 매달림·넘기·운반·붙잡힌 사람·들기·처치·쓰러짐 및 일부 주민 걷기·대화 프레임에서 몸이 촬영 칸 끝에 닿았다. 여백을 넓혀 다시 촬영하고, 동작별 배율과 바닥 기준점을 저장해 게임 안 크기와 위치를 보정한다. 13,552프레임 전부에서 불투명한 인물 부분이 가장자리에 닿거나 빈 프레임인 경우가 없다.
- 매달림이 공통 손 위치와 한 방향 그림에 기대고 있었다. 복장·8방향·4프레임의 실제 두 손을 측정해 전선·가장자리·벽 오르기 중의 접촉점에 맞춘다. 시체 선택 고리도 새 촬영 배율을 적용한 실제 몸 범위를 따른다.
- 1층 창문 통과는 바로 점프를 시작했다. 창틀 방향에 맞춰 접근·넘기·착지를 이어가고, 옆으로 빗나간 통과와 잠긴 창문 넘기를 막는다. 걷는 단계는 이전 웅크림 상태 대신 이동 자세를 사용하며, 오르기 완료 후 바라보던 방향도 유지한다.
- 창문과 환풍구 동작 일부가 옥상 오르기로 분류됐다. 창문 출입 중 어느 실내를 보여 줄지 명시하고, 층 전환을 이동 진행도에 연결했다. 창문 동작은 사라지는 지붕보다 위에 한 번 그려 가려지지 않게 하며, 창문 출입 때의 검은 화면 효과를 없앴다.
- 사물 조작에 쓰던 두 사람용 들기 프레임은 보이지 않는 상대 때문에 팔이 가려질 수 있었다. 사물 조작은 단독 자세를 쓰고, 준비·마무리는 평소 서기 자세로 돌아간다. 물건 취득·문 열림 등 효과는 기존 접촉 시점에 한 번 적용한다.
- 창문이 가는 장식처럼 보이고 잠김을 그림으로 읽기 어려웠다. 열린 틈·겹친 창짝, 잠금 걸쇠, 창살, 창턱을 구분한다. 실내 평면·외벽·옆벽에서 같은 상태를 그리며 별도 창살을 중복해서 덧그리지 않는다. 창문 방향도 현재 화면 층 대신 해당 창문의 층을 기준으로 계산한다.

버튼 위치와 조작 체계는 유지한다. 배관의 기존 손 접점과 착지 좌표도 유지한다. 메인 화면·임무 구성은 이번 변경에 포함하지 않는다.

검증:

- `t_motion_windows.py`: 전체 시트의 빈 프레임·촬영 잘림 검사. PC·모바일 각각 실제 맵 창문 통과 500건, 위층 창문 출입 72건, 복장·방향·프레임별 매달림 손 접점 128건. 연속 입력, 창틀 위치, 착지·층 전환, 지붕 뒤 가림·중복 그리기, 창문 출입의 검은 화면도 검사.
- `t_trav.py m1 m2 m3 m4 m5 m6`: 이동 후보 269건 중 유효 동작 264건 완료. 벽·계단·배관·위층 창문·가장자리의 막힌 착지, 순간이동, 카메라 튐 실패 0건. 5개 후보는 지형상 실행 불가로 제외.
- `t_interaction_flow.py`: 실제 키보드·터치 입력, 반복 입력 잠금, 준비·접촉·마무리, 대상 변경·소실, 문 상태 경쟁, 환풍구 15곳 왕복 통과.
- `t_pipe_contacts.py`: PC·터치 각각 배관 32곳 왕복, 복장별 접점 19,400건과 실제 그리기 위치 1,660건 통과.
- `t_world_alignment.py`, `t_scene_layers.py`: 시체 중복·층별 렌더, 기존 저장 호환, 옥탑문 43곳, 실내외 전선·간판 분리 통과.
- `t_characters.py`: 복장별 주인공 외모·전체 동작·기존 캐릭터 키·팔레트 호환 통과.
- `t_target_body.py`: 옥상 기절자 높이·한 번 그리기·처치·보관 상태 유지. 이전 버전에서도 실패하던 전지적 목표 위치 가정은 목격 정보 기반 목표 검증으로 바꿨다.

화면은 데스크톱 Chromium의 PC·모바일 화면 크기로 확인했다. 영상은 고정 간격으로 시뮬레이션을 진행한 동작 기록이다.

에셋 재생성은 `tools/prerender/bake_modular.py`를 사용한다. 공통 모델과 주인공은 변경한 동작을 부분 갱신하고, 주민은 해당 동작만 갱신했다. `--patch`는 캐릭터별로 존재하는 동작에 적용하고, 시트마다 배율·기준점 메타데이터도 함께 저장한다.
