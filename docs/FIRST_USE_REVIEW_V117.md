# v117 첫 플레이 관점 리뷰

## 어떻게 확인했나

저장 기록이 없는 모바일 화면에서 `시작하기`를 누르고, 화면에 보이는 목표와 버튼을 따라 연습 1을 끝낸 뒤 의뢰 01 브리핑과 첫 이동까지 직접 조작했다. 모바일은 Chromium의 실제 터치 이벤트와 가상 시계를 사용했다. 생각하고 화면을 확인하는 동안 게임 시간이 임의로 흘러가지 않도록 시간을 멈춰 구간별로 진행했다.

이는 개발자가 처음 접하는 사람의 관점으로 진행한 점검이다. 실제 신규 유저 모집, 관찰 조사, 기기별 Safari 검증을 수행한 것은 아니다. 이탈률·학습 시간·재미 개선 수치로 일반화할 수 없다.

## 발견한 문제와 수정

| 문제 | 처음 접하면 느낄 수 있는 혼동 | 반영 |
| --- | --- | --- |
| 경고 중에도 목표와 화살표가 마당 안쪽을 가리킨다 | 나가야 하는데 더 들어가게 된다 | 경고 즉시 목표를 `아래쪽 길로 나오기`로 바꾸고 실제 공개 도로를 가리킨다 |
| 연습 시작부터 탈출구가 열려 있다 | 현재 단계의 대상과 탈출 화살표가 다른 방향을 가리킨다. 직진만 해도 학습하지 않고 완료할 수 있다 | 현재 단계 안내 하나를 사용한다. 마지막 탈출 단계에서만 출구를 열고, 이전 체크포인트의 열린 출구도 보정한다 |
| 기절 안내가 붙잡은 뒤에도 그대로다 | 붙잡기와 공격의 관계, 길게 눌렀을 때 결과를 구분하기 어렵다 | 접근 중 `붙잡기 또는 공격`, 붙잡은 뒤 `공격 짧게 눌러 기절시키기`로 바뀐다. PC는 실제 키, 모바일은 버튼 이름을 표시한다 |
| 운반 전후 같은 긴 문장 | 지금 메라는 것인지 넣으라는 것인지 다시 읽어야 한다 | 옷 갈아입기·운반·수거함에 넣기를 현재 상태에 따라 나눠 표시한다 |
| 버튼 영역에 밀려난 가까운 목표 화살표 | 붙잡은 사람과 주인공을 덮는다 | 가까운 연습 대상의 화살표는 생략하고 행동 표시를 사용한다 |
| 첫 연습 결과에서 선택형 고급 기술까지 설명한다 | 끝난 뒤에도 읽어야 할 규칙이 많다 | 결과 설명을 줄이고 다음 버튼에 `의뢰 01 시작`을 명시한다 |

기존 모바일 버튼 위치, 미니맵 위치, 중앙 신분 표시는 유지한다. 경비의 시야나 공격력을 낮추는 변경은 없다.

## 재검증

`tests/rev/t_first_session.py`는 새 저장으로 시작해 실제 키보드와 CDP 터치 입력으로 이동한다. 플레이어 위치·아이템·AI 상태·연습 단계에 값을 대입해 통과시키지 않는다. 시간을 프레임 단위로 진행하며 NPC와 대화·발각·상호작용은 모두 작동시킨다.

- PC / 모바일: 시작 → 거리 통과 → 마당 경고 → 퇴거 → 대화 듣기 → 붙잡기 → 짧은 공격으로 기절 → 옷 갈아입기 → 운반 → 수거함 → 허용 구역 → 탈출 → 결과 → 의뢰 01 브리핑 → 첫 대화 종료. 두 경로 모두 발각 0회, 사망자 0명.
- PC / 모바일: 연습을 하지 않고 길을 따라 출구까지 가도 완료되지 않는지 별도로 검사한다. 이전 버전처럼 출구가 열린 체크포인트를 불러와도 현재 단계에 맞춰 닫히는지 검사한다.
- 가까운 붙잡기 대상 위에 목표 화살표가 다시 그려지지 않는지 검사한다.
- `t_controls_readability.py`: PC·세로 모바일 2종·가로 모바일, 기본/잉크 화면의 행동·대화·표시 회귀 검사.
- `t_copy_scenarios.py`: 조작 이름·기절/처치 문구·기존 단서 회귀 검사.
- `t_mission_flow.py`: 기존 의뢰 6개 × 배치 3종 × PC/모바일 = 36개 완료 경로.

이전 직접 조작에서는 경고 이후 공격을 한 번 받았다. 수정본 재검증은 경고가 표시되면 바로 퇴거하는 경로이므로, 두 결과를 신규 유저 성공률 비교로 해석하지 않는다. 전체 과거 테스트가 모두 통과한다는 주장도 아니다.

## 남은 확인

첫 의뢰에서 플레이어가 비밀번호·복장·환경 사고 중 어느 공략을 스스로 발견하는지는 실제 신규 유저 관찰이 더 필요하다. 연습의 순서를 벗어나 먼저 운반하거나 다른 조직원을 공격하는 선택도 이후 관찰 대상이다. 이번에는 직접 확인한 안내 충돌과 완료 판정을 우선 수정했다.
