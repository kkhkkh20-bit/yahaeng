# 야행 전체 흐름 재검토 · v157

[원본 전후 비교](review-v157/index.html)

검토 기준은 **모바일에서 그늘과 풀숲을 이용해 접근 → 가까이 제압 → 몸 정리 → 다음 구간**을 이어 가는 액션이다. v156에서 첫 접촉을 정리한 뒤 이번에는 저장·재시도·목표 추적·화면 갱신까지 연결해서 점검했다.

지금 추가할 가치가 큰 것은 새로운 조작이나 복잡한 관리 체계보다 **첫 성공을 보존하고, 다음 행동을 일관되게 알려 주는 장치**였다. 실제로 저장한 은신 자세가 사라지고, 끝난 목표의 선택 상태가 남는 문제가 있었다. 아래 항목을 수정해 v157에 적용했다.

## 발견한 문제와 적용

| 우선순위 | 재현·영향 | 적용 |
| --- | --- | --- |
| P1 | 본편에서 웅크려 저장한 뒤 일어서고 체크포인트를 불러오면, 전역 입력 상태가 서 있던 상태를 유지했다. 첫 갱신에 걷기로 바뀌어 풀숲 은신이 풀릴 수 있었다. | 세 본편 의뢰에도 저장 당시의 웅크림을 복원한다. 눌린 키·공격 예약은 기존대로 해제한다. 실제 체력·몸·임무 진행은 되돌려 놓지 않는다. |
| P1 | 수동으로 선택한 장부를 회수하거나 추적 중인 단서를 완료해도 선택 플래그가 남았다. 화면은 다른 목표를 가리키면서도 자동 몸 정리 안내를 막았다. | 유효한 목표와 단서는 계속 존중하고, 완료·무효가 된 추적만 해제한다. 자동으로 고른 표적의 ID도 실제 선택 상태에 맞게 기록한다. |
| P2 | 수동 목표를 고른 뒤 자동 안내로 돌아갈 조작이 없었다. | 기존 일시정지 화면의 목표 목록에 ‘자동 안내’를 추가했다. 선택 상태와 키보드 포커스를 유지하며, 새 HUD나 별도 메뉴를 만들지 않는다. |
| P1 | 첫 순찰을 제압하고 몸을 숨기는 데 성공해도 필수 목표·열쇠·단서를 얻기 전까지 체크포인트가 없었다. 다음 접촉의 실패가 첫 성공까지 되돌렸다. | 실제 첫 몸 정리 완료 시 체크포인트를 요청한다. 수색·추격·무전·동작 중에는 저장하지 않고 기존 안전 조건을 통과한 뒤 저장한다. 어려움의 체크포인트 제한과 무료 포인트 없음은 유지한다. |
| P1 | 가로 844×390의 목표 표식이 하단 여백을 270px로 고정해, 상단 HUD보다 낮은 표시 영역의 끝이 오히려 위에 놓였다. | 실제 조작부 위치로 표식 영역을 계산한다. 작은 세로·가로 화면과 배율 변화에서도 사각형이 뒤집히지 않고 목표 화살표가 조작부 위에 남는다. |
| P2 | 렉을 따라잡는 120ms 프레임에서 물리 계산 7회마다 HUD도 7회 갱신했다. 따라잡기 중에 같은 DOM 작업을 반복했다. | 물리·이동·AI의 세부 계산은 유지하고 실제 화면 프레임 끝에서 HUD를 한 번 갱신한다. 직접 시뮬레이션을 호출하는 검사·도구의 기본 동작도 유지한다. |

## 시스템별 점검

| 영역 | 확인한 내용과 판단 |
| --- | --- |
| 모바일 조작·HUD | 네 화면 크기의 실제 패키지와 목표 선택·자동 복귀·저장 복원을 비교했다. 기존 버튼 위치·서체·시각 체계를 유지했다. 320×568에서도 목록의 아래 목표까지 실제 스크롤과 터치로 선택하고 자동 안내로 돌아오는 검사를 통과했다. |
| 은신·시야·소리 | 기본 연습의 시야 피하기·웅크림·발소리·조명·유인 흐름을 PC·터치로 완료했다. 풀숲은 버튼으로 들어가는 기능을 되살리지 않았다. |
| AI·변장·층·수색 | 기존 회귀 묶음에서 실제 목격, 신원 기억, 경보, 소리 조사, 조명 복구, 층간 추적과 은닉처 수색을 검사한다. 이번 개선을 이유로 AI 기억을 지우거나 어둠을 무적으로 만들지 않았다. |
| 제압·운반·성장 | 첫 의뢰의 실제 순찰에 접근해 짧게 기절시키고 몸을 숨겼다. 근접 거리·길게 처치·기술 학습 조건과 보상 예산을 유지했다. 기술 수를 추가하지 않았다. |
| 임무 진행·선택 경로 | 명시적인 목표와 단서를 유지하면서 완료된 추적은 정리한다. 기존 임무 진행 검사는 NPC를 동결해 문·물품·처치·탈출 연결을 분리 검증하므로, 이를 활성 AI의 전체 의뢰 완주라고 부르지 않는다. |
| 배경 세계 | 같은 시드 42로 여섯 기존 의뢰를 각각 입력 없이 120초 관찰했다. 현재 주요 의뢰 m2/m4/m6는 30초 시점의 NPC 쓰러짐이 모두 0이었다. m4는 120초 누적 1회로 배경 사건이 완전히 사라진 것은 아니다. 보관된 m3는 30초에 7회였으며 현재 주요 세 의뢰와 구분한다. 이 관찰을 평균 난이도·생존시간 통계로 사용하지 않는다. |
| 성능·재시도 | 렉 보정의 HUD 반복을 줄이고 저장 자세와 첫 재시도를 고쳤다. 첫 성공을 실제로 저장한 뒤 메뉴에서 ‘이어 하기’로 복구하는 연결까지 검증했다. |

## 검증 자료

- [신규 회귀](review-v157/mechanics.json): 저장 자세·풀숲 은신, 수동 추적의 수명, 자동 복귀, 안전한 체크포인트, 120ms 물리 시간 보존과 HUD 한 번 갱신, 네 크기·세 배율·세 주요 의뢰의 실제 화살표 렌더링 36경우를 검사한다.
- [실제 PC·터치 진행과 저장 복구](review-v157/continuation-journey.json): 메뉴에서 시작해 이동·제압·운반·숨기기를 직접 입력하고, 의뢰 선택 화면으로 나갔다가 실제 ‘이어 하기’로 복구했다. 활성 경비·카메라, 고정 시뮬레이션 시계에서 체력 3·발각 0·기절 1·숨긴 몸 1·스킬 예산 4·웅크린 은신 상태를 유지했다. 배우·체력·인벤토리 강제 변경은 없다.
- [기초 연습 PC](review-v157/tutorial-pc.json) · [터치](review-v157/tutorial-touch.json): 첫 두 연습을 완료하고 첫 의뢰로 진입했다.
- [HUD 갱신 비교](review-v157/presentation.json): 같은 생산 패키지의 16.7/33.3/120ms 프레임을 검사했다. HUD 갱신은 각각 1/2/7회에서 1/1/1회로 바뀌고 진행한 게임 시간은 동일했다. 함께 기록한 실행 시간은 단일 헤드리스 표본이며 실물 휴대폰 FPS 향상률로 주장하지 않는다.
- [최종 패키지](review-v157/local-package.json): HTML·버전·스크립트·서체 8개 파일 해시, 실제 IBM Plex Sans KR Regular, PC·터치의 실제 프레임 이동·웅크림·목표창 일시정지·메뉴 복귀를 확인했다.
- [재현 원본](review-v157/baseline-audit.json) · [촬영 조건 이전](review-v157/before-captures.json) / [변경 후](review-v157/after-captures.json): 실제 v156/v157 패키지, 같은 시드와 입력, 네 화면 크기, 원본 이미지 24장이다. 자세 복원 장면만 플레이어 위치를 맞춘 통제 장면이며 실제 본편 조작 완료 증거와 구분한다.

핵심 회귀 스크립트 **51개**, 빌드 검사 **7개**, 도달 검사를 통과했다. [전체 결과](review-v157/regression.txt). 별도로 기존 선택 경로 검사도 PC·터치에서 통과했다. [선택 경로 검사](review-v157/optional-goals.txt). 독립 UI 검수는 네 크기의 원본 12장·동작 기록·변경 코드를 확인해 **ship**으로 판정했고 수정 요구는 없었다. [검수 기록](review-v157/finish-review.json). 이 판정은 이번 여섯 변경과 제공된 상태에 한정한다. 배포 상태는 같은 폴더에 별도로 기록한다. UI 검출은 [빈 경고 목록](review-v157/design-detection.json)이었다. 기존 IBM Plex Regular 400·색·메뉴·조작부를 유지하고, 새 아트·외부 패키지·초기 능력을 추가하지 않는다. episode-one/club-study 보관 판본은 변경하지 않았다.

이번 검토는 코드·통제 회귀·실제 첫 진입과 저장 복구에 대한 것이다. 일반 사용자 재미 평가, 모든 본편의 활성 AI 전체 완주, 실물 휴대폰 발열·배터리·FPS 검증은 하지 않았다.
