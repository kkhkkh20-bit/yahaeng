# v113 · 준비가 실행을 바꾸는 첫 의뢰

2026-11-01 · [전후 화면·검증 영상](fun-v113/index.html)

첫 의뢰 VIP를 중심으로 공략의 연결을 보강했다. 화면 정리와 수색 수정은 모든 의뢰에 적용된다. 주요 의뢰 세 개, 주인공, 미니맵·중앙 섞임 표시·모바일 버튼의 위치는 유지한다.

## 바꾼 이유와 플레이 변화

장부는 필수 회수물인데 실장의 행동과는 연결되지 않았다. 사무동을 턴 뒤 다시 클럽으로 이동해 표적을 처리하는 흐름이 반복됐다. 장부를 미끼로 실장을 사무동으로 부를 수 있게 해, 이미 익힌 실내·창문·사물함·조명을 매복에 재사용하게 했다.

| 행동 | 게임의 반응 |
| --- | --- |
| 사무동 금고에서 장부 회수 | 1층 사무실 책상의 내선 전화 사용 가능 |
| 내선으로 실장 호출 | 손 조작의 접촉 시점에 한 번만 발신. 실장이 기존 길을 걸어 이동 |
| 이동하는 동안 준비 | 실내 은신·위치 선정·조명을 활용할 시간. 호위는 사무동 밖에서 대기 |
| 실장 도착 | 약속 장소에 35초간 머문다. 플레이어는 매복하거나 기회를 넘길 수 있음 |
| 기회를 놓침 | 기존 일과로 복귀. 경계가 풀린 뒤 재호출 가능. 임무 실패나 강제 시간 제한 없음 |
| 범행이나 경보로 상황 변경 | 약속 취소. 경비가 기억한 목격·옷차림·추격 상태는 유지 |
| 매복 후 탈출 | 결과 화면의 접근 방식에 `장부로 불러낸 매복` 기록 |

전화는 실제 생성된 책상에 놓이고 같은 층에서 손이 닿아야 한다. 물건을 추가로 운반하거나 열쇠를 더 모을 필요는 없다. 들고 있던 다른 도구를 소모하지 않는다. 기존 저장본에서 이어 해도 장부를 확보했다면 이용할 수 있고, 진행 중 약속과 인물 경로는 체크포인트에 함께 저장된다.

간판 사고·술병 유인·VIP룸 뒷문도 계속 사용할 수 있다. 구토제를 집거나 술병을 준비하면 최소 안내에서도 그 공략의 다음 행동을 보여 준다. 화장실 방문을 놓쳤을 때는 이미 떠난 장소를 계속 가리키지 않는다. 직접 선택한 의뢰 목표나 전체 안내의 추적 경로가 자동 안내보다 우선하며, 단서를 끄면 자동 공략 제안도 끈다.

첫 의뢰의 도전 과제는 미녹화·사고·정보 수집 세 개로 정리했다. 대량 처치와 연속 처치를 유도하는 항목은 첫 의뢰에서 뺐다. 직원 진입 보상의 조건도 별 네 개로 조정해 모든 진입로를 실제로 열 수 있게 했다. 이전 과제로 얻은 별은 전체 누적 보상에 계속 반영하고, 이미 달성한 진입 조건도 유지한다.

## 화면과 수색

평상시 중앙 상태 표시는 작은 아이콘과 단어로 남기고, 위험할 때는 기존 크기와 이유 표시로 돌아온다. 시야 원뿔은 평온한 상태에서 옅게 표시하되 실제 길이와 인지 판정을 줄이지 않는다. 다트를 조준할 때만 대상 마름모를 표시하며 평상시 자동 조준 계산도 생략한다.

말풍선은 한 번에 하나를 표시한다. 단서 대화와 발각 외침을 우선하고, 가까운 행동 중에는 관계없는 잡담을 줄인다. 들리지 않는 `소곤소곤` 표기, 최소 안내의 기회 발견·완료 중복 알림, 빈 행동 버튼의 일반 설명 알림도 줄였다. 기존 단서·비밀번호 수집과 전체 안내 모드는 유지한다.

수색 경비는 같은 층의 가까운 방과 은신처를 확인한 뒤 다른 층으로 이동하도록 배정 비용을 조정했다. 플레이어의 숨은 위치를 배정 기준으로 사용하지 않는다.

v112에서 실패했던 위층 은신처 수색 검사는 발견 후 일반 출입 동작이 끝날 때까지 숨은 상태가 남는 문제도 포함하고 있었다. 강제 발견은 즉시 은신을 해제하되 몸이 나오는 동작은 유지한다. 여러 경비가 같은 탈출 동작을 다시 시작하지 않으며, 발견된 상황에서는 문을 여유롭게 닫는 마무리 동작을 생략한다. 막힌 출구나 다른 층 판정을 바꾸는 방식으로 우회하지 않았다.

## 검증 결과와 범위

- `t_rendezvous.py`: PC·모바일 조건의 실제 목표 이동, 35초 체류, 재호출, 경보 취소, 경로 원본 보존, 체크포인트, 구토제 공략 안내, 수동 선택 우선, 보상 진입로의 달성 가능성, 강제 은신 해제와 연속 피해 방지. 실제 키보드·터치 버튼도 검사했다. 고정된 검사 조건에서 실장 도착은 약 31.7초였고 이동 중 좌표 재배치가 없었다.
- `t_rendezvous_walkthrough.py`: 금고 문 → 카드·장부 회수 → 전화 → 사물함에 은신 → 실장 실제 도착 → 나와서 길게 눌러 처치 → 탈출을 PC·모바일 이동으로 각 세 조건, 총 여섯 번 완료했다. 인위적인 목표 달성·열쇠 지급·플레이어 위치 이동 없이 진행하며, 관련 없는 NPC를 고정하고 호출 대상·호위의 AI를 실행한다.
- `t_mission_flow.py`: 여섯 의뢰·세 조건·PC/모바일의 기존 36개 완료 경로 통과.
- `t_building_search.py`: 기존 실패 해소. 실내 위치 13,388개, 실외 오르기 여섯 조건, 구석 CCTV, 실제 계단을 이용한 위층 수색, 은신처 발견, 수색 종료·저장 복원·신원 판정 통과.
- `t_product_plan.py`, `t_mission_progress.py`, `t_contract_density.py`: 준비 저장, 음용·유인, 단서와 목표, 의뢰 진행·진입 구조 통과.
- `t_controls_readability.py`, `t_camera_presentation.py`, `t_play_clarity.py`: PC와 모바일 세 화면 비율·기본/잉크 화면의 행동 우선, 중요 대화 표시, 화면 경계 108조건, 위험 표시와 조작 유지 통과.
- `t_ai_feedback.py`, `t_disguise_ai.py`, `t_combat_policy.py`, `t_copy_scenarios.py`: 기존 밝기별 시야 길이·휘파람·변장·실제 수색·입력별 기절/처치·문구 통과.
- `t_access_fixtures.py`, `t_access_inputs.py`: v112의 환풍구 15곳·맨홀 21곳·낙하 장치 21곳·손 접촉·실제 버튼 검사 통과.

화면과 입력 검증은 Chromium 브라우저에서 수행했다. 새 공략의 이동·입력 완료 여부와, 전체 NPC를 포함한 난이도·사람이 느끼는 재미 평가는 구분한다. 이번 변경과 관련된 검사를 실행했으며 전체 테스트 묶음이 모두 통과했다고 주장하지 않는다. 이전 배포본에서도 실패했던 나머지 구형 항목은 [v112 검증 기록](ACCESS_FIXTURES_QA.md)에 남아 있다.
