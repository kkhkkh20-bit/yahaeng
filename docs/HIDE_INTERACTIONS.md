# v108 · 수거함과 은신 동작

2026-10-31

수거함이 작은 상자처럼 보이고, 적을 넣거나 주인공이 들어가는 과정과 결과가 맞지 않는 문제를 수정했다. [전후 화면·동작 영상](hide-v108/index.html).

대형 수거함은 넓은 입구·바퀴·경첩·뚜껑·앞판으로 형태를 구분한다. 맨홀은 뚜껑이 옆으로 움직여 실제 구멍이 드러난다. 그림과 몸이 사라지는 경계는 같은 입구 좌표를 사용한다. 기존 고정 시설 그림과 중복해서 그리지 않으며, 보관 인원을 나타내던 붉은 점은 없앴다.

행동은 다음처럼 이어진다.

- 혼자 숨기: 가능한 앞쪽 입구까지 걸어감 → 뚜껑 열기 → 몸을 넘겨 내려감 → 닫기.
- 운반 대상 넣기: 접근·열기 → 어깨에서 내리고 입구 아래로 넣기 → 보관 처리 → 닫기. 주인공은 밖에 남는다.
- 붙잡은 적과 들어가기: 적을 먼저 끌어 넣음 → 주인공이 뒤따라 들어감 → 닫기. 적이 들어간 시점에 기절·처치가 적용된다.
- 나오기: 열기 → 몸 내밀기 → 입력 방향의 빈 칸으로 나옴 → 닫기. 나올 곳이 없으면 은신 상태를 유지한다.
- 숨어서 끌어들이기: 몸을 작게 줄이는 효과를 없애고 입구 아래로 내려가 가려지게 한다. 보관된 몸의 위치와 은신처 참조도 일치시킨다.

결과와 수용 인원은 실제 접촉 후 한 번만 갱신한다. 연속 입력이 동작을 건너뛰거나 다른 대상으로 바꾸지 않는다. 수거함에 보관한 사람이 두 명이면 주인공이 추가로 들어갈 수 없다. 한 명을 붙잡고 함께 들어갈 때는 두 명분의 공간을 확인한다. 가득 찬 곳에서 넣기를 눌러도 운반 대상을 바닥에 버리지 않는다.

짧게 누르면 기절, 같은 입력을 길게 유지하면 처치하는 기준을 유지한다. 접촉 전에 입력을 놓으면 기절로 마무리한다. 다른 버튼의 입력은 길게 누르기에 합산하지 않는다. 길게 누르기 진행도는 처음 누른 버튼에 표시한다. 숨는 모습을 본 적은 뚜껑을 닫았다고 목격 사실을 잊지 않는다.

기존 조작 위치를 유지하고, `들어가 숨기`·`기절자 넣기`·`시체 넣기`·동작 중 상태로 의미를 구분한다. 새로운 안내 박스나 옵션은 추가하지 않는다.

검증:

- `t_hide_flow.py`: 6개 의뢰의 수거함·맨홀을 네 방향에서 진입·퇴장 209회씩 PC·모바일에서 검사. 반복 입력, 입구 열림, 막힌 착지·퇴장, 결과의 지연 적용, 가득 찬 곳에서 운반 유지, 보관 좌표, 목격 유지, 붙잡고 들어가기 3가지 입력 조건, 숨어서 끌어들이기 4조건을 검사했다. 실제 키보드와 터치로 숨기·방향 퇴장·운반 대상 넣기도 통과했다.
- `t_combat_policy.py`: 짧게 기절·같은 버튼을 길게 처치, 입력 해제·다른 버튼·앱 전환, 실제 모바일 터치와 두 PC 키 배치의 입력·진행 표시 통과. 기존 컨테이너 검사는 새 동작이 완료될 시간을 준 뒤 결과를 확인한다.
- `t_interaction_flow.py`: 다른 사물 조작·반복 입력 잠금·대상 유효성·환풍구 15곳 왕복 통과.
- `t_target_body.py`: 기절한 표적의 운반·보관·보관 후 처치 가능 상태 통과. 보관이 접촉 전에 적용되지 않는지도 확인한다.

닫힌 시설은 80×96 크기의 그림 두 장을 공유한다. 뚜껑·몸·앞판을 나누는 그리기는 동작 중인 시설에 적용한다. 100프레임 반복 그리기에서 추가 캔버스 할당은 없다. 캐릭터 모델과 동작 에셋은 그대로 사용한다.

화면은 Chromium의 PC·모바일 화면 크기로 확인했다. 영상은 고정 간격으로 진행한 동작 기록이다.
