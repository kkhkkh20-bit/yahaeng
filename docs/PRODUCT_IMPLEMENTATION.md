# v94 · VIP 한 판과 공통 조작 개선

적용일: 2026-10-31 (한국 시간). [기획안](PRODUCT_IMPROVEMENT_PLAN.md) · [실제 변경 화면](product-improvement/index.html).

## 반영한 동작

- 유효한 변장으로 이동·달릴 때 중앙 수상함 안내와 AI 판정을 맞췄다. 범행·신원 확인·알려진 복장의 경고는 유지한다.
- 메뉴에서 추적할 의뢰 목표를 선택한다. 이동만으로 다른 목표로 바뀌지 않으며 완료 시 다음 미완료 목표를 추천한다. 기회 추적은 명시적으로 선택한 동안 우선한다.
- 수금원·클럽 실장을 구별한다. 중복된 건물명 괄호를 줄이고 빌라는 실제 간판명을 사용한다.
- 최소/끔 안내에서는 표적을 직접 봐야 정확한 위치를 얻는다. 시야 상실 뒤 마지막 목격점을 15초 유지하고 활동 구역으로 돌아간다. 미니맵·전술 지도·목표·일과표가 같은 정보를 사용한다. 전체 안내는 정확한 위치 지원을 유지한다.
- 현재 위치, 층, 옥상 높이, 벽, 은닉 상태를 확인해 목격을 기록한다. 옥상에서 실제로 내려다볼 수 있는 외부 표적도 확인할 수 있다. 관측 정보와 선택 목표는 체크포인트에 저장한다.
- 다른 층의 목표는 실제 연결 경로의 입구를 가리킨다. 경로에 잠긴 문이 있으면 먼저 해당 문을 안내한다. 상단 거리도 연결 입구까지의 거리로 구별한다. 월드 목표 문구는 미니맵·중앙 상태·조작 버튼과의 겹침을 피한다.
- 기존 대상 버튼은 이름 목록을 연다. 목록은 선택만 하고 실행은 기존 행동 버튼으로 한다. PC Tab 순환과 목록 안 키보드 선택을 지원한다. 이동·전투·메뉴 전환 시 목록을 닫는다.
- 고른 대상이 사라지면 다른 물체를 자동 실행하지 않는다. 남은 후보가 하나여도 다시 선택할 수 있다. 조작 불가 시 거리·벽·층 관련 이유를 짧게 제공한다.
- 단서·복장·소품·사용 완료·카드·중요 문 개방·보안실 정리를 안전 저장 계기로 추가했다. 반복 착의나 문 여닫기는 새 진척으로 세지 않는다. 경보·신원 확인·동작 중에는 저장을 보류한다.
- 저장 성공은 짧게 표시하고, 기기 저장 실패를 성공으로 알리지 않는다. 저장 공간이 부족해도 현재 실행의 메모리 체크포인트는 유지한다. 복원 시 약한 객체 식별자에 의존하는 행동 선택은 초기화한다.

## VIP의 세 경로

| 경로 | 변화 |
|---|---|
| 직원 잠입 | 술병 준비와 실제 음용을 분리했다. 바에서 실제로 2초 마신 뒤 화장실 우회를 한 번 시작한다. 경보·붙잡기·이동으로 음용이 끊기면 효과를 미리 적용하지 않는다. 준비와 진행을 저장·복원한다. |
| 옥상 사고 | 기존 낙하 범위에 표적·다른 사람 위험 안내와 간판 조작 브래킷을 보강했다. 실제로 볼 수 있는 사람만 안내에 반영한다. 수동 발동은 길게 누르기를 유지한다. |
| 금고·뒷문 | 파란 카드 획득 안내와 문에 VIP룸 뒷문 용도를 연결했다. 문 옆 카드 리더·키패드를 표시한다. 카드로 문을 여는 것과 복장 권한은 별개다. |

실장의 일과는 VIP룸→바→흡연으로 정리했다. 표적 정차 지점 가까이에 군중이 처음 서거나 배회 목적지를 잡지 않도록 했다. 선두가 자기 호위를 피해 역방향으로 우회하지 않는다. 군중 우회가 정체되면 원래 목적지로 재탐색하고, 도착점 12px 이내에서 정상 정차를 인정한다. 벽 판정·몸 간격 보정·실제 이동은 유지한다.

호위가 화장실 밖에서 기다렸다가 다시 따르는 동작은 기존 기능을 재사용했다. v93 저장에서 이미 만들어진 화장실 우회를 새 음용으로 중복 시작하지 않는다. 이전 기회 단계도 이어진다.

## 공간·결과

VIP 사무동·클럽, 대청소 사무동·클럽·기존 빌라, 배신 감금동·경비실에 현재 시점의 높이 단서를 적용했다. 상층 벽 단면·바닥 두께·옥상 난간과 기존 실제 옥탑 입구를 사용한다. 전체 카메라나 맵 좌표를 교체하지 않았다. 술병·컵·간판 브래킷·출입 장치를 기존 렌더러로 보강했으며 새 외부 에셋 팩은 추가하지 않았다.

VIP 결과에 접근 방식을 표시한다. CCTV 삭제는 현재 남은 기록을 지우되 이번 임무에서 녹화된 이력은 별도 보존한다. ‘남은 CCTV 기록 없음’은 등급 항목, ‘신원이 한 번도 녹화되지 않기’는 별도 도전이다. 기존에도 삭제 시 현재 녹화 수를 초기화하던 동작이 있었으므로, 이번에는 이력과 도전을 구분하는 데 집중했다. 삭제로 목격·신고·전체 경보는 취소되지 않는다. 구버전 저장의 확인할 수 없는 과거 이력을 0회라고 간주하지 않는다.

## 검증과 한계

- 관련 회귀 31종을 검사했다. 구형 일과표 검사는 미목격 위치 비공개 규칙으로, 기회 설정 검사는 현재 설정 화면 진입 경로로 갱신했다. 세력 전투 검사는 병렬 1회 실패 후 단독 재실행에서 통과했다. 해당 검사는 실시간·무작위 상황에 민감하다.
- 신규 `t_product_plan.py`: PC/터치에서 정상 변장, 목표 고정, 관측·마지막 목격·활동 구역, 준비 저장과 경보 중 보류, 음용 중단·복원·구버전, 입구 연결, 저장 실패, 녹화 삭제와 등급·도전 분리, 실제 행동 목록 선택과 대상 소실을 확인한다.
- 신규 `t_vip_routes.py`: 세 경로 × PC/터치 × 2회 = 12개 장면. NPC를 정지시키지 않고 실제 일과·음용·화장실 이동·호위 분리·길게 처치·간판 사고·잠긴 뒷문 개방을 확인한다. 시작 위치와 장비는 장면 재현을 위한 조건이다. 임무 전체를 사람이 걸어서 완주한 12회라는 뜻은 아니다.
- `t_mission_flow.py`: 6개 의뢰 × PC/모바일 × 배치 3종 = 36개 전체 이동·목표·탈출 경로. 이 검사는 진행 판정을 분리하기 위해 NPC를 정지시킨다.
- 전체 지도 도달 검사에서 문제·페이지 오류 0건. 무작위 조작 6판에서 게임 오류·판정 검사 문제 0건. 무작위 조작 중 외부 통계 전송은 `nostats`로 비활성화한다.
- 390px 비교 캡처와 PC/모바일 화면 확인. 테스트는 Chromium 터치 에뮬레이션이며 실제 iPhone Safari·Android Chrome 확인을 대체하지 않는다.
- 신규 플레이어 5인의 이해·재도전 평가, 실제 기기 성능, 첫 공략 시간 측정은 아직 수행하지 않았다. 10~15분은 검증할 설계 가설이다.

## 관련 코드

`44_mission_plan.js`: 관측 정보·목표 고정·연결 입구·실제 음용·접근 방식.

`81_action_picker.js`: 행동 이름 목록과 선택·실행 분리. `83_plan_graphics.js`: 출입 장치·준비된 술병·컵·간판 위험과 지도 관측 표식.

`50_opps_checkpoint.js`: 준비 사건의 고유 기록·안전 저장·복원. 나머지 변경은 기존 판정·HUD·렌더·의뢰 데이터에 연결했다.
