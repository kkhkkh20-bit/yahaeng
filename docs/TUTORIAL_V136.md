# v136 — 2D 복귀와 시야·소리 학습

첫 연습은 상호작용보다 지각 규칙을 먼저 가르친다. 기존 첫 연습은 공개/금지 구역·경고·엿듣기·변장부터 요구했고, 기본 조작 연습에는 지도·엄폐·추가 제압까지 섞여 있었다.

## 학습 순서

1. 첫 연습 `tB`: 이동 → 실제 달리는 발소리 → 웅크려 조용히 이동 → 시야 바깥에서 멈춰 부채꼴 관찰 → 시야 안의 풀숲에서 은신 → 숨어서 휘파람 → 적이 소리 난 곳을 살피는 동안 이탈 → 탈출.
2. 다음 연습 `t0`: 등 뒤 접근 → 붙잡기 → 짧게 기절 → 변장 → 운반 → 수거함 은닉 → 탈출.
3. 의뢰 01. 신분·고급 기술 연습은 목록의 선택 연습으로 유지한다.

긴 대화창 대신 기존 목표 칸에 현재 할 행동 하나와 원리 한 줄을 넣었다. PC에는 실제 키, 모바일에는 버튼 이름을 쓴다. 모바일 휘파람은 본편과 같은 도구 버튼이며, 첫 연습에서는 바로 휘파람으로 준비한다. 필요 없는 공격 버튼은 첫 연습에서 숨긴다. 연습 문장은 좁은 화면에서도 자르지 않는다. 두 번째 연습의 잘못된 운반 선택은 내려놓기와 옷 선택 안내로 회복할 수 있다.

실제 시야 안에 놓인 풀숲에서 웅크림 은신을 검사했다. 같은 위치는 은신을 빼면 웅크려도 감지되고, 은신 중에는 감지되지 않는다. 휘파람 성공은 입력 횟수로 통과시키지 않고 실제 적이 소리를 들었는지 확인한다. 첫 연습의 시각 발각은 전투로 이어지기 전에 안전 체크포인트부터 다시 시작한다.

## 시야와 소리 표현

- 서기/웅크리기 두 도형의 교차 페이드 대신 경계 거리를 보간한다. 다섯 전환 상태 모두 적당 채움 1회·윤곽 1회다.
- 손전등 조명 판정은 유지하되 별도 부채꼴을 겹쳐 그리지 않는다. 손의 작은 전구와 같은 시야 영역으로 표현한다.
- 계속 떠 있던 발소리 예상 타원을 제거한다. 발소리는 실제 발걸음에서만 짧은 점선 물결로 나타나고, 겹치는 이전 발걸음 물결은 생략한다. 소리와 시야는 모양과 시간으로 구분한다.
- 기존 탐지 거리·밝기·벽 차단·청력·전투 수치는 유지한다. 난이도 조정의 첫 단계는 원리를 익히는 학습 경로다.

## 검수

- `tests/tutorial/first_session.py`: PC 키보드 / 모바일 실제 CDP 조이스틱·터치 버튼으로 두 연습 → 의뢰 01. AI와 보유 도구, 플레이어 위치·진행을 지급하거나 바꾸지 않는다. 게임 시간만 고정 간격으로 진행한다. 목표 설명 영역 잘림도 검사한다. 결과 `pc.json`, `touch.json`.
- `tests/tutorial/perception_visual.py`: 위치를 놓는 부품 검사. 단일 시야, 서기→웅크리기 범위, 지속 발소리 타원 제거, 실제 시각 탐지→안전 체크포인트 복귀. 결과 `perception-controlled.json`.
- `tests/tutorial/verify_deployment.py`: 분할 배포본의 HTML·버전·스크립트 해시, 실제 브라우저 프레임의 PC/터치 시작·이동·웅크리기·메뉴·연습 재진입, 3D 모듈/모델 요청 없음. 로컬 `local-packaged.json`, 공개 주소 결과는 배포 뒤 별도 기록.
- 기존 선택 신분 연습의 완주/조기 탈출 방지/구버전 체크포인트 복구, 본편 시야·상태·대인 행동·입력과 접촉 피드백 회귀 검사도 통과했다.

화면은 `docs/tutorial-v136/`에 있다. 자동 플레이는 신규 사용자 사용성 실험을 대신하지 않으며 실제 휴대폰 성능 측정은 아니다.
