# 사물 접촉과 몸·복장 상태의 연속성 (v190)

옷을 가져간 기절자의 탈의 상태를 원래 NPC에도 보관한다. 동료가 깨우거나 다시 쓰러져도 옷이 복원되지 않으며, 이전 체크포인트의 탈의된 몸도 깨어날 때 상태를 이월한다. 탈의한 NPC의 옷은 다시 얻을 수 없다.

문은 기존 손잡이 전용 동작을 유지한다. 스위치·줍기 등 공용 손동작은 필요할 때 최대 34px까지 짧게 걸어 접근한 뒤 기존 접촉 프레임에 효과를 낸다. 벽면까지의 거리로 멈추는 위치를 정하고, 작은 이동 단계마다 충돌을 검사한다. 발소리·걸음 시계는 일반 이동과 같은 함수를 사용한다. 대상 이탈·피격·층 변경·외부 위치 이동은 작업을 취소한다. 옷 갈아입기와 몸을 멘 상태에서는 자동 접근하지 않는다.

사람을 먼 거리로 던지는 행동을 제거하고, 오래된 예약 입력도 운반 중인 몸을 잃지 않고 거부한다. 들어 올리기는 0.7초, 내려놓기는 0.6초로 조정하고 빠른 숨기기는 실제 들어 올리기가 끝난 뒤 이어진다. 기절자는 내려놓기 안내에서도 기절자로 표시한다.

일반 경비와 허용 복장의 정상 보행 규칙은 유지한다. 눈썰미 NPC의 신원 확인도 걷는 동안 새로 쌓이지 않는다. 이미 시작한 확인은 걷기 입력 한 번에 즉시 지워지는 대신 천천히 줄어든다. 시야를 벗어나거나 얼굴을 돌리면 확인이 초기화된다.

검증은 GitHub Actions의 Chromium에서 실행한다. 실제 소스 함수의 상태 전이 20개 그룹, 핵심 브라우저 회귀 85개 스크립트, PC·모바일 실제 입력으로 첫 두 연습 완료, PC 실제 입력으로 VIP 의뢰 완료를 구분해 확인한다. 통제된 물리 상호작용 장면은 PC·모바일에서 옷 갈아입기→기상→재기절, 운반·내려놓기, 물건 접근을 검증한다.

원래 연습/VIP 맵의 실제 입력 재생은 일반 requestAnimationFrame, 활성 AI·CCTV, 무작위 시드 고정 없이 수행한다. 플레이어·적·보유품·임무 진행을 강제로 변경하지 않는다. 알려진 맵을 사용하는 개발자 자동 재생이므로 초보자 사용성 연구나 실물 휴대전화 검증으로 해석하지 않는다. 화면과 상태 기록은 `docs/physical-v190/`에 보관한다.

회귀 85개·PC/모바일 첫 두 연습의 통과 기록: https://github.com/kkhkkh20-bit/yahaeng/actions/runs/41968366628

VIP의 실제 입력 완주 기록: https://github.com/kkhkkh20-bit/yahaeng/actions/runs/41970267779 — 체력 3, 플레이어 발각 0, CCTV 촬영 0. 시신 발견에 따른 경보 2회가 있어 무경보 공략은 아니다. 표적·장부·남동쪽 숙소의 암호표·동쪽 탈출을 모두 완료하고, 기술 UI에서 의뢰 전 2P와 완료 후 4P를 정상 사용했다.

첫 실행의 VIP 자동 경로는 순찰과 150px 이상 떨어질 때만 진입하려다 짧은 실내 순찰에서 멈췄다. 게임 코드는 변경하지 않고, 적이 멀어지거나 등을 돌리는 실제 틈에 문으로 접근하게 재생 경로를 수정했다. 이미 통과한 검사 결과는 게임/빌드 파일의 동일성을 git diff로 확인한 경우에만 재사용했다.

격리 장면의 캡처 보정: https://github.com/kkhkkh20-bit/yahaeng/actions/runs/41971044335 — 플레이어 함수만 진행시키는 격리 시계는 전역 시작 페이드를 진행시키지 않으므로 장면 초기화 시 페이드를 해제한다. 실제 게임의 조명·페이드 코드는 바꾸지 않는다.

배포 후에는 Workers와 Pages의 version.json·HTML·스크립트·글꼴 해시가 테스트한 public 패키지와 같은지 확인하고 각 공개 주소에서 PC·모바일 입력, 이동·웅크리기, 목표 패널 일시정지/재개, 연습 선택을 검증한다. 이 배포 검증은 `.github/workflows/verify-deployment.yml`에서 자동 실행하며 실제 성공 여부는 해당 실행 결과로 판단한다.
