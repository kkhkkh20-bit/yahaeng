# 현재 시점의 높이 단서 시험 · v85

대청소 맵 남서쪽 3층 빌라(`heightCueBuildings: [4]`) 한 채에 적용했다. [기존/보강 후 화면](height-cues/index.html).

## 변경

- 실내의 막힌 벽 칸 안에 잘린 윗면과 앞면을 그린다. 원래 창문·비밀 통로·문·계단의 그림과 바닥 위치는 유지한다.
- 실내 바닥 아래에 얇은 단면과 접촉 그림자를 더한다. 아래층 창문 등 새 조작 대상으로 오해할 장식은 만들지 않는다.
- 옥상은 기존 난간 위치에 윗면·안쪽 그림자·정면 두께만 보강한다.
- 기존 시점, 캐릭터 발 위치, 이동·충돌·사물 선택·계단·옥탑문 좌표, HUD와 모바일 버튼 위치는 유지한다.

## 비용

벽 단면은 기존 `floorCanvas()`를 만들 때 함께 그리며 기존 캐시를 재사용한다. 바닥 단면과 난간은 작은 Canvas 2D 도형으로 그린다. 3D 모델, 이미지 에셋, 별도 비트맵 캐시를 추가하지 않는다.

- 새 게임 에셋: 0개. 추가 Canvas 캐시: 0개.
- 게임 HTML 증가: 3,888바이트. 압축 실행 파일 증가: 1,315바이트.
- 비교 스크린샷은 별도 검토 페이지에서만 읽으며 게임 HTML에 포함하지 않는다.

동일한 1244×721 Chromium 환경에서 장면별로 캐시를 예열한 뒤 16프레임씩 세 번 측정한 그리기 시간의 중앙값이다. 관측값의 작은 음수 차이를 성능 향상으로 해석하지 않는다. 휴대폰 실기 측정값은 아니다.

| 장면 | 기존 | 보강 후 |
| --- | --- | --- |
| 거리 | 10.81ms | 9.97ms |
| 2층 실내 | 11.08ms | 11.65ms |
| 옥상 | 7.76ms | 7.23ms |

## 검증

- `t_height_cues.py`: 시험 건물이 한 채인지, 다른 건물의 그림이 같은지, 이동 가능한 타일 38개의 중앙과 창문 7개의 픽셀이 유지되는지, 층별 계단·옥탑문 선택 좌표가 유지되는지 검사했다. 추가 Canvas 할당이 없고 반복해서 같은 캐시를 쓰는지 확인한다.
- 바닥·사다리·계단·문 데이터가 그리기 전후에 동일하며 Canvas의 알파·변환·합성 상태를 복원한다.
- 기존 `t_world_alignment`, `t_stair_geometry`, `t_combat_policy`, `t_interaction_flow`, `t_ui2` 통과.
- 이전/보강 후 스크린샷의 주인공 좌표·층·가능한 행동이 동일하다. 비교 페이지는 PC·390px 모바일·키보드 조작을 확인했다.
